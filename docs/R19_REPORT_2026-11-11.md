# R19 — 공개 리서치 API 범위 위반 수정

## 구현

이전 커밋 5e5ce46은 유지하고 범위 위반으로 지적된 신규 파일
`src/rag_research_agent/rag/research_api.py`를 제거한다. 기존 파일을 수정한 것이
아니므로 제거하면 R19 이전 상태로 돌아간다.

허용된 `research/__init__.py`에 기존 공개 파사드를 옮기고 `research/api.py`는
같은 패키지의 공개 이름을 제공한다. 공개 경로는 `rag_research_agent.research`와
`rag_research_agent.research.api`다. API_VERSION 0.1, run_research,
ResearchConfig, ResearchResult, DomainFilter, register, get_filter, SearchFn,
keyword_search, chroma_search를 제공한다. 기존 클래스·검색 함수의 동일성을 유지한다.
모델·검색·필터·그래프 구현은 기존 위치에 두고 새 대체 구현은 만들지 않았다.

구조 규칙을 재확인했다. 새 패키지 이름 제한은 없으며 modules()는 __init__.py를
검사 대상에서 제외한다. 공개 이름 집계는 이 패키지 진입점에서 수행한다.
api.py의 직접 의존성은 같은 research 패키지뿐이다. rag·guard 이름은 사용 시
지연 로딩하며 모듈 import 자체에는 필요하지 않다. 따라서 모듈 제거 시험에서
다른 패키지를 제거해도 파사드 모듈을 import할 수 있게 설계했다(실행 미검증).
LangChain·LangGraph 직접 import는 추가하지 않았고 MATURITY는 incubating이다.
KNOWN_DEBT와 기존 구조 시험은 변경하지 않았다.

기본 research 실행은 기존 ResearchRunner에 그대로 위임한다. 다른 도메인은
입력 검사 → 기존 그래프 → 한 번의 도메인 검수 → 성공 시 고지 순서다.
입력 차단 시 검색하지 않고 검수 실패 시 안전 문구를 반환한다.
문서의 독립 예제 세 개와 시험의 import 경로를 새 공개 경로로 갱신했다.

## 시험

전체 시험 시도 명령:

```powershell
python -m pytest -q -p no:cacheprovider --basetemp=.runs/r19-fix/full-tmp --junitxml=.runs/r19-fix/full-pytest.xml
```

**tests not run here: Python is not available on PATH.**

이 환경에서 시험 미실행: python 명령을 찾지 못했다. py·pytest도 PATH에 없고
.venv-python·.venv-cache에서 python.exe를 찾지 못했다.
최종 실행 0건. passed/failed/error/skipped는 미실행으로 집계 불가다.
NightCoder 게이트에서 전체 시험 판정이 필요하다.
시도 기록: `.runs/r19-fix/test-attempt.txt`.

공개 API 시험은 매개변수 포함 10건으로, 기존 9건의 검증을 유지하고 패키지와
api 모듈의 모든 공개 객체 동일성 검증 1건을 추가했다. 기존 클래스·실제 필터·
실제 ResearchRunner와 문서 예제를 사용한다. Chroma 예제는 실제 ChromaIndex와
기존 FakeEmbedder를 사용하는 **경로 시험**이며 실제 모델 품질 평가는 아니다.
선택 의존성을 차단한 하위 프로세스 import 시험도 유지한다.
기존 시험 기대값 변경·skip·삭제는 없다.

## 설계 대비 차이

기본 그래프·설정값은 바꾸지 않았다. 기본 research의 주장 단위 검수·재검색은
기존 구현을 사용하고 별도 도메인 검수를 중복 적용하지 않는다.
다른 도메인의 그래프 내부 재시도·branch별 검색 격리는 **후속 연결 필요**다.
도메인 고지는 report에만 붙고 draft는 원래 인용 문장을 유지한다.

구조 규칙의 패키지 진입점 집계를 사용하므로 rag/research_api.py 대체 경로는
필요하지 않다. 향후 분리 배포에는 기존 rag·guard·core·store 구현이 필요하다.
파사드와 도메인 계약 import는 선택 의존성 없이 가능하도록 설계했다.
ResearchConfig 등은 LangGraph를 사용하는 기존 research_graph에서 지연 제공하므로
모든 이름 import·실행의 선택 의존성 제거는 **후속 연결 필요**다.
실험 보드·기존 서비스·체크포인터·모델 인터페이스는 수정하지 않았다.
