# R28: 문서별 병렬 추출 옵션

작성: 2026-11-12 KST. NightCoder 작업, 현재 브랜치 `nc/rra-codex`.

## 구현

- `ResearchConfig.parallel_extract=False`를 추가했다. 기본 순차 extract 경로와 일괄 추출 호출은 유지한다.
- 켜면 refine 뒤 정제된 문서마다 LangGraph `Send("extract_one", ...)`를 생성한다. 기존 추출 함수와 span 검증을 재사용하고 claims/metrics/relations/log/cost 누적 리듀서로 합친다. `join_extract`만 pending을 비우고 compare를 한 번 실행한다. 문서가 없으면 join으로 직접 진행하며 gap 재검색에도 같은 경로를 적용한다.
- 기존 주입 extractor의 규칙 폴백을 유지한다. 폴백하지 않는 문서별 예외는 `EXTRACT_ONE:ERROR`만 기록하고 다른 문서 결과는 보존한다. 예외 메시지와 문서 ID는 오류 로그에 넣지 않는다. 실패 문서 입력의 추정 비용도 기록한다.
- 체크포인트가 있으면 Send 입력과 worker 출력을 기존 직렬화 경계로 통과시킨다. 여러 worker가 토큰 한도에 도달해도 단일 값 stopped 채널에 동시에 쓰지 않고 join에서 중단한다. 이미 시작된 같은 배치의 작업은 완료된다.
- 호출자 주입 추출기는 문서 단위 추출에 적합하고 동시 호출에 안전해야 한다. 문서 사이 관계를 한 번에 추론하는 배치 추출기와의 결과 동등성은 보장하지 않는다. compare는 합쳐진 전체 claims를 사용한다.

## 시험

신규 `tests/test_research_parallel_extract.py`: 10개 시험 함수, 매개변수 확장 시 14개 사례. 실제 build_research_graph/ResearchRunner 및 LangGraph를 사용하며 주입 함수는 기존 규칙 추출기를 호출한다. 오류·잘못된 span은 주입 인터페이스에서 유발한다. 모델·임베딩 품질 평가가 아닌 오프라인 경로 시험이다.

정의한 검증: 순차/병렬 sources·claims·metrics·relations 집합 동등성, 검색 병렬 옵션과 조합, 주입 문서 제외, Barrier로 실제 추출 동시 실행 확인, 문서 실패 격리, 기존 규칙 폴백, 기본 batch 호출·Runner 결과 불변, 빈 배치, gap 재검색, 체크포인트 실제 자료형 복원, 잘못된 span과 종속 레코드 제거, 여러 worker의 토큰 한도 중단.

## 설계 대비 차이

정본 `RESEARCH_GRAPH_DESIGN.ko.md`, `DOMAIN_FILTERS.ko.md`, `LANGGRAPH_GUARDRAIL.ko.md`를 확인했다. 누적 리듀서와 추출/비교 경계를 유지했다. 정본의 단일 extract를 옵션에서 문서 map 및 join으로 세분화했다. 공통 노드 오류 중단 원칙과 달리 이번 요구에 따라 병렬 추출의 개별 문서 예외는 격리한다. 기본 순차 오류 정책은 변경하지 않는다.

순서와 보고서 문자열의 완전 동일성은 병렬 옵션의 계약이 아니다. 문서별 입력 토큰 추정은 문서마다 반올림하므로 순차 일괄 추정과 차이가 날 수 있다. 토큰 한도는 기존처럼 실행 후 추정 한도이며 실제 모델 토큰 제한이 아니다.

## 미검증 및 변경 범위

실제 LangGraph 런타임·시험 14건과 전체 시험 결과, 실제 Chroma 통합, 실제 모델 추출 품질·성능·가속은 미검증이다. 실제 모델 실행 명령은 호출자 소유 로컬 모델과 masker를 `ResearchRunner(..., extractor_model=..., masker=...)`에 주입해야 하며 이 작업에는 모델 실행 CLI나 모델이 없어 재현 가능한 실제 모델 명령을 제공할 수 없다. CLI/UI 설정 노출은 후속 연결 필요.

지정된 그래프·신규 시험·보고서 세 파일만 변경했다. 초기 git status는 깨끗했다. 기존 시험·기대값·skip·KNOWN_DEBT·보호 파일·README·금지 파일은 변경하지 않았다. memvid 의존성 추가, 네트워크, 모델 실행/다운로드, 패키지 설치, push, 원격/브랜치 설정 변경은 없다. 결과 증거는 `.runs/r28/`에만 저장했다.
