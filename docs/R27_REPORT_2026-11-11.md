# R27: 작성 노드 구조화 출력 어댑터

작업일: 2026-11-12 KST. NightCoder 레인, 현재 브랜치에서만 작업.

## 구현

- `research_llm.py`: `llm_writer(model, masker)`와 엄격한 `ReportOut` /
  `SentenceOut` 스키마를 추가했다. 기존 `WriterFn` 서명을 따르며 선택적 `log`를 받는다.
- 모델 입력은 State의 의미 있는 claim 표(`id`, `text`, `kind`, `stance`)와 검수
  피드백 코드뿐이다. 중립 일반론은 설계 10절에 따라 제외한다. 질문, 계획, 원문,
  source_id/span, 별도 metrics/relations는 전달하지 않는다. JSON 입력을 마스킹하고
  DATA 구분자를 이스케이프한다. 출력 문장도 마스킹한다.
- 인용 누락·빈 목록·공백 ID는 `drop_empty`, 표에 없는 ID(유효 ID와 섞인 경우도 포함)는
  `drop_unknown`, 빈 문장은 `drop_blank`로 집계하여 해당 문장 전체를 버린다.
  정상 문장은 유지하며 중복 인용은 제거한다. 모든 문장이 버려져도 규칙 문장으로
  대체하지 않고 빈 초안을 검수에 보낸다. 내용·ID·예외 메시지는 로그에 넣지 않는다.
- 구조화 출력 바인딩·호출·스키마·마스킹 오류는 `WRITE_LLM:FALLBACK_RULE` 코드와 함께
  기존 `write_rule`로 폴백한다. 반대 근거 없음 안내는 모델이 아닌 어댑터가 붙인다.
- `ResearchConfig.writer` 기본값은 `rule`이며 `llm`은 `writer_model`과 masker가 필요하다.
  `ResearchRunner`와 그래프 빌더에 주입 인자를 추가했다. R20의 명시적 writer 플러그인이
  LLM 옵션보다 우선하며 기존 플러그인 오류 정책은 유지한다. 재작성 엣지는 기존대로
  검수 코드를 다음 작성 호출에 전달한다. 기본 설정의 작성 경로는 그대로다.

## 설계 대비 차이

`RESEARCH_GRAPH_DESIGN.ko.md` 3절의 claims/metrics/relations 표 중 이번 명세에 따라
claim 표만 전송한다. 10절의 중립 일반론 제외 원칙과 문장별 claim 인용을 따른다.
도메인 필터와 가드레일 계약은 바꾸지 않는다. LangChain/LangGraph 관련 연결은 rag 안에
유지하고 공용 데이터는 core를 사용한다. Chroma 기본값과 memvid 경로를 변경하지 않았다.

기존 shadow cost는 질문과 claim 본문으로 계산하는 추정치이며 이번 프롬프트의 JSON,
ID·종류·관점·피드백·시스템 지시 길이 및 버린 출력까지 정확하게 계측하지 않는다.
이는 실제 토큰 사용량이 아니며 정확한 비용 계측은 후속 연결 필요다.
