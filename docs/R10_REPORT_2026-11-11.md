# R10 — extract 노드 구조화 출력 어댑터

## 구현

`rag/research_llm.py`에 엄격한 Pydantic 스키마 `ClaimOut`, `MetricOut`, `RelationOut`, `ExtractionOut`과 `llm_extractor(model, masker)`를 추가했다. masker의 `mask`가 없으면 생성 시 거부한다. 문서마다 `with_structured_output(ExtractionOut)` 모델을 호출하며, 모델 입력에는 마스킹한 문서 텍스트만 DATA 블록으로 넣는다. 질문·계획·출처 ID는 보내지 않는다. 문서의 DATA 구분자와 앰퍼샌드는 이스케이프하고 시스템 지시와 분리한다. `serving_trace_guard`와 `serving_config`를 적용한다.

모델의 인용을 SourceRef 원문에서 검색해 start/end를 채운 뒤 `span_matches`로 대조한다. 마스킹 결과에서 사라진 인용도 거부한다. 인용이 없는 주장, 버린 주장에 연결된 수치·관계, 양끝이 유효하지 않은 관계를 버린다. 수치의 값과 단위도 주장에 원문 그대로 있어야 한다. 모델의 문서 내부 ID는 출처 ID로 이름 공간을 나눠 저장한다. 이미 알려진 주장 ID는 재누적하지 않는다. 버린 개수는 `EXTRACT_LLM:drop_claims=N,drop_metrics=N,drop_relations=N`으로 기록한다.

모델 바인딩·호출·검증·마스킹 오류와 중복 주장 ID는 전체 배치의 부분 결과를 폐기하고 기존 `extract_rule`로 폴백한다. 로그는 `EXTRACT_LLM:FALLBACK_RULE`뿐이며 예외 메시지·본문은 기록하지 않는다. 정상적인 빈 출력이나 지어낸 인용은 오류 폴백 대상이 아니라 검증 후 빈 결과가 된다.

`ResearchConfig.extractor="rule"` 기본값을 유지하고 `"llm"`만 옵션으로 연결했다. `build_research_graph(..., extractor_model=None, masker=None)`와 `ResearchRunner`에 주입 인자를 추가했다. llm 모드에서 모델 또는 masker 누락, 알 수 없는 모드는 생성 시 거부한다. rule 모드는 주입 모델을 사용하지 않는다. 검색·저장소 경로는 변경하지 않았으며 memvid 의존성을 추가하지 않았다.

## 시험

새 `tests/test_research_llm_extract.py`는 실제 Pydantic 스키마, core 자료형, `extract_rule`, `span_matches`, ResearchRunner와 LangGraph를 사용한다. 모델 경계만 명세에 따라 fake 모델을 주입한다. masker 기본 시험은 동결된 실제 `mask_pii`를 감싼다. 변환·오류 경계 시험은 개인정보 대신 영문 마커와 예약 마스킹 문자열을 사용한다.

정상 Pydantic/dict 출력, 지어낸 인용과 종속 항목 제거, 예외·이상 형식·바인딩 실패, 배치 중간 실패의 원자적 폴백, 모델 입력의 마스킹·DATA 경계, masker 실패 시 모델 미호출, 마스킹으로 제거된 인용 복원 거부, 정상 빈 출력, 지어낸 수치와 부분 숫자 일치 거부, 중복 ID, known ID, masker 필수, 그래프의 정상·예외·이상 형식 완료, rule 기본값 보존과 의존성 검증을 작성했다. 모두 경로 시험이며 실제 모델 품질 측정이 아니다.

전체 시험 명령을 시도했다.


## 설계 대비 차이

설계 정본 세 문서의 구조화 출력·span 검증·코드 로그·규칙 폴백 원칙을 따른다. 기존 core 계약을 유지하므로 Metric에는 직접 span 필드를 추가하지 않고 검증된 Claim의 claim_id/source_id를 통해 span을 추적한다. 관계 종류는 기존 core의 causes/contradicts/condition만 지원한다. 개체 추출, supports/supersedes, 기간·비교 기준 확장은 이번 파일 범위 밖이며 후속 연결 필요다.

기존 `extract_rule`를 폴백으로 사용하며 ontology/rule_labeler와 compose/numbers를 별도로 재연결하지 않았다. 기본 동작을 보존하고 지정 범위 밖 수정을 피하기 위함이다. SourceRef.text는 기존 계약상 마스킹된 검색 원문이며, 그래프의 검색·State 계약은 그대로다. 어댑터는 모델 입력을 다시 마스킹하지만 원문 위치는 전달받은 SourceRef를 기준으로 한다. 재마스킹으로 변한 구간의 인용은 원문과 일치하지 않으면 버린다. masker 주입 인자를 그래프와 Runner에도 추가해 필수 의존성을 명시했다.

문서마다 독립 추출하므로 모델이 문서 사이 관계를 직접 생성하지 않는다. 기존 compare 노드가 문서 간 상충 비교를 계속 담당한다. 반복 인용은 첫 원문 위치를 선택한다. 기존 shadow cost 계산은 유지하며 실제 호출 토큰·이스케이프 및 시스템 지시 비용은 미검증이다.

## 미검증 및 대표 실행 명령

전체 시험 통과, 실제 모델 출력 품질, 주입 방어 효과, canonical IntakeMasker와 실제 로컬 모델의 통합은 미검증이다. frozen masking·기존 시험·기대값·skip·KNOWN_DEBT는 변경하지 않았다.

대표 PC에서 이미 보유한 로컬 모델과 masker를 `.runs/local_extractor_factory.py`의 `model`, `masker` 변수로 준비한 뒤 실행할 수 있는 명령이다. 이 파일은 대표가 준비하는 주입 진입점이며 이번 작업에서 생성하거나 실행하지 않았다. 다운로드나 외부 API를 수행하는 factory를 사용하지 않는다.

```powershell
python -c "import runpy; from rag_research_agent.rag.research_graph import ResearchRunner, ResearchConfig, keyword_search; c=runpy.run_path('.runs/local_extractor_factory.py'); r=ResearchRunner(keyword_search({'doc-a1':'매출은 18% 증가했다.'}), ResearchConfig(extractor='llm', stance_split=False, auto_metrics=False), extractor_model=c['model'], masker=c['masker']); print(r.run('매출', ('매출',)))"
```

## 범위·보호 확인·커밋 제약

초기 git status는 깨끗했다. 변경은 지정된 소스 두 개·신규 시험·본 보고서 네 파일뿐이다. 보호 파일 18개 SHA-256은 기존 `.runs/n10/protected-after.json`의 Expected와 작업 전후 모두 동일하다. 증거는 `.runs/r10/protected-before.json`, `.runs/r10/protected-after.json`이다. `git diff --check`는 통과했다. 결과 파일은 `.runs/`에만 썼다. README, 금지 소스, data/profiles는 수정하지 않았고 push·원격·브랜치 설정 변경은 하지 않았다.

`git add`와 `git commit`을 시도했으나 `.git/index.lock: Permission denied`로 실패했다. 이 샌드박스에서 .git은 읽기 전용이고 권한 상승이 허용되지 않는다. 커밋 해시가 없으며 미커밋 변경 0건 조건을 충족하지 못했다. 작업을 삭제하지 않고 보존한다. Git 쓰기가 가능한 NightCoder 환경에서 위 네 파일을 한 커밋으로 수집해야 한다.
