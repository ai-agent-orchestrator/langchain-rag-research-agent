# N13 보고서 — 재순위화 인터페이스와 모델 없는 기준선

2026-11-10 KST. AGENTS.md를 먼저 읽고 현재 저장소·브랜치 `nc/rra-codex`에서 작업했다. NightCoder 규칙을 적용하며 push·원격·브랜치 설정 변경을 하지 않는다.

## 구현

- `retrieve/rerank.py`에 `Reranker.rerank(query: str, chunks: Sequence[Chunk]) -> list[tuple[Chunk, float]]` Protocol을 추가했다. 기존 `core.contracts.Chunk`를 사용하고 원본 객체와 중복을 보존한다.
- `IdentityReranker`는 입력 순서를 유지한다. n > 1이면 0부터 시작하는 순위 i의 점수는 `1 - i / (n - 1)`, 단일 청크는 1.0이다. 질의와 무관한 순위 기준선이다.
- `LexicalOverlapReranker`는 질의와 청크 `safe_text`에 기존 `core.lexical.lex_terms`를 적용한다. 점수는 고유 질의 단어 중 일치한 비율이며, 유효 질의 단어가 없으면 0.0이다. 제목은 평가하지 않는다. 반복 단어를 가중하지 않고, 기존 대소문자 구분·공백 토큰·문장부호·마스크·연산자 처리 규칙을 그대로 따른다. 내림차순 안정 정렬로 동점의 입력 순서를 유지한다.
- 두 점수 모두 0~1 범위이며 docstring에 **확률 보정 아님**을 명시했다. 모델·저장소·네트워크 호출은 없다.
- 같은 폴더와 동일하게 `MATURITY = "incubating"`을 선언했다. 의존성은 표준 라이브러리와 core뿐이며 KNOWN_DEBT를 늘리지 않았다. 기존 Candidate용 `retrieve/protocols.py`의 Reranker는 별도 계약이므로 보존했다.
- 기존 검색 경로·Library에는 연결하지 않았다. 향후 조립 계층에서 검색 evidence의 Chunk 목록을 전달하고 반환 점수의 사용 정책을 정하는 후속 연결 필요. Chroma 기본값을 유지하고 memvid 의존성·대체 기능을 추가하지 않았다.
