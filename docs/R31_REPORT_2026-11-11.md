# R31 도메인 무관 평가 보드

작업일: 2026-11-12 KST. NightCoder 레인, 현재 저장소·브랜치에서 작업했다.

## 구현

- `scripts/domain_board.py`: R21의 `.runs/domain_eval/<domain>/runs.jsonl`을 읽어 외부 자원 없는 HTML을 생성한다. `load_pack`·`validate_metrics`를 재사용하며 도메인별 지표 이름을 하드코딩하지 않는다. 팩 정의 순서와 safety 플래그로 열을 만든다. research는 R21의 기존 내장 팩 정의를 사용한다.
- 문서 순서는 전체 도메인의 안전 지표 → 품질 지표 → 추정 토큰 → 실행 기록이다. 안전 표에는 위반 문항 수/표본 수, 위반율, Wilson 95% 구간과 상한을 표시한다. R21의 count는 발생 횟수이므로 위반 문항 수 대신 쓰지 않는다. 원본 count를 포함한 기록은 실행 기록에서 확인한다.
- 실행 유형별 표를 분리해 합성 경로 시험과 다른 평가 결과를 같은 표에 섞지 않는다. compare/confirm은 원본 분할을 표시할 뿐 선택·재평가하지 않는다. 품질은 R21의 injection 제외 집계를 그대로 사용한다.
- R21에는 토큰 필드가 없다. 선택적 `tokens_mean`이 기록된 경우만 추정 토큰/문항으로 표시하고, 없으면 미검증으로 표시한다. 토큰·표본·지표 값을 임의 생성하지 않는다. 0건은 안전 보장이 아니라는 안내를 표시한다.
- OS 테마 자동 적용과 밝게/어둡게 선택, 휴대폰 폭에서 표를 세로 카드로 바꾸는 CSS를 제공한다. 긴 문자열은 줄바꿈한다. 모든 데이터는 텍스트와 HTML 속성 문맥에서 이스케이프하며 실행 스크립트에 삽입하지 않는다.
- CLI 출력은 실제 경로가 저장소 `.runs/` 내부인 `.html` 파일로 제한한다. 실행 기록은 수정하지 않는다. 기본 러너·기존 보드·설정은 변경하지 않았다.

사용 예:

```powershell
.\.venv\Scripts\python.exe scripts/domain_board.py
.\.venv\Scripts\python.exe scripts/domain_board.py --domain legal
```

기본 출력: `.runs/domain_eval/board.html`. `--domain`은 반복 지정 가능하다. `--packs`, `--runs-root`, `--output`으로 경로를 지정할 수 있다. 기본은 발견한 모든 도메인의 기록이다.

## 시험

신규 `tests/test_domain_board.py`는 8개 시험 함수, 매개변수 확장 기준 10개 사례를 정의한다. 실제 R21 평가기·팩 로더·보드 렌더러·CLI를 사용한다. 두 합성 도메인, 동적 열/순서, 안전 분리, injection 품질 분모 제외, 0건 Wilson 상한, 빈/누락 값, 실행 유형별 표 분리, HTML 이스케이프, 출력 경계, 기록 보존, 경로·JSON·스키마 오류, 테마 및 모바일 CSS를 다룬다. 개인정보 모양의 시험 값은 사용하지 않았다.

전체 시험 시도 명령:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

**tests not run here: repository virtualenv Python has no pytest module.**
이 환경에서 시험 미실행: `.venv/Scripts/python.exe`는 Python 3.15.2이나 `No module named pytest`로 시작하지 못했다. PATH의 `python`·`py`도 없다. 대상 시험 명령도 같은 이유로 시작하지 못했다. 패키지 설치는 하지 않았다.

전체 pytest 결과: **passed/failed/error/skipped 모두 집계 불가, 실행 사례 0개**. 수집 이전 실행기 의존성 오류이며 시험 실패·skip 수로 바꾸어 보고하지 않는다. 전체 판정은 NightCoder 게이트에 위임한다.

별도 표준 라이브러리 직접 점검은 최종 통과했다. 실제 `domain_eval.run`으로 두 임시 팩의 결과를 생성하고 `load_domains`·`render`·CLI로 HTML을 생성했다. 안전/품질 순서, 동적 열, injection 제외 표본 수, 위반 수, Wilson 상한, 악성 HTML 문자열 이스케이프, 빈 결과, 실행 유형 그룹 분리를 assertion으로 확인했다. 이는 합성 **경로 시험**이며 pytest 10개 통과나 실제 모델 품질을 의미하지 않는다. 소스·신규 시험 2개 파일 AST 구문 검사도 통과했다. 점검 HTML: `.runs/r31/board-smoke.html`.

`git diff --check` 통과. 보호 파일은 기존 `.runs/n10/protected-after.json`의 Expected SHA-256과 작업 전·후 모두 **18/18 동일**하다. 근거: `.runs/r31/protected-before.json`, `.runs/r31/protected-after.json`. 기준 manifest의 정당성 자체는 미검증이다.

## 설계 대비 차이

설계 정본의 교체 가능한 도메인 경계와 로컬 평가·보드 원칙에 따라 독립 스크립트로 추가했다. 지표 계약은 R21 팩에 위임하고 그래프·필터·저장소를 수정하지 않았다. 기존 `research_board.py`의 연구 전용 그래프/격자 UI를 복제하지 않았다. R21 실행 후 자동 보드 생성은 지정 파일 범위 밖이므로 **후속 연결 필요**다.

R21이 토큰 정보를 기록하지 않는 점은 보드에서 미검증으로 노출한다. 실제 토큰 계측은 후속 연결 필요다. 모델이 필요한 기능이 아니므로 모델 주입·실제 모델 실행 명령은 해당하지 않는다.
