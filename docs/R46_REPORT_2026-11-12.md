# R46 사람 검토 분기

## 구현

`rag/human_review.py`에 선택형 `HumanReviewRunner`를 추가했다. 실제 `ResearchRunner` 또는 `GuardrailRunner`를 실행한 뒤 검수 실패 코드가 남으면 LangGraph `interrupt()`로 질문·초안·실패 코드·근거 목록을 반환한다. 가드레일은 실제 그래프의 updates 스트림에서 안전 답변으로 대체되기 전 초안을 보존한다. 리서치는 실제 draft와 추출된 claim만 근거로 사용한다. 질문·초안·수정문·검색 자료의 마스킹은 기존 파이프라인/호출자 책임이며, 원문을 새로 수집하지 않는다.

`ReviewPolicy`는 법률·의료 기본 True, 리서치 기본 False다. 기존 runner 진입점은 변경하지 않았다. 명시적으로 래퍼를 선택했어도 정책이 꺼져 있으면 원래 실행 결과를 그대로 반환한다. 켜진 경우 체크포인터와 비어 있지 않은 thread_id가 필수다. 의료 필터는 기존 레지스트리에 없으므로 의료 정책 사용자는 실제 도메인 verifier를 주입해야 한다(후속 연결 필요).

재개는 `resume(thread_id, {"action": ...})`가 실제 `Command(resume=...)`를 전달한다. approve는 초안을 그대로 승인하고 reject는 기존 안전 답변을 낸다. edit는 `answer` 본문을 기존 DomainFilter로 재검사한다. 리서치는 저장된 계획·claim·metric으로 `verify_report(check_claim_alignment=True)`와 설정된 grounded grader까지 다시 적용한다. 평문 수정본은 원문 claim 전체가 남은 경우에만 해당 claim을 인용한 것으로 처리하는 보수적 방식이다. 실패한 수정은 갱신된 코드로 다시 interrupt하며 성공 답변으로 노출하지 않는다. 승인/수정 통과/거절 후 `end_type="human"`, `reviewer_action`을 결과와 로컬 `event()`에 기록한다. 이벤트에는 본문·질문·근거가 없다.

체크포인터는 호출자가 주입하고 소유한다. 직렬화에는 기본 dict/list와 기존 research checkpoint codec을 사용한다. 중단 이후 새 래퍼에서도 같은 saver/thread로 재개하며, 검색·생성을 반복하지 않는다. 없는 thread, 완료된 thread, 시작 시 기존 thread 재사용, 잘못된 action/빈 수정문은 거절한다.

```python
from langgraph.checkpoint.memory import InMemorySaver
from rag_research_agent.rag.human_review import HumanReviewRunner, ReviewPolicy

# runner: 호출자가 구성한 실제 ResearchRunner 또는 GuardrailRunner
review = HumanReviewRunner(runner, policy=ReviewPolicy("research", True),
                           checkpointer=InMemorySaver())
paused = await review.ainvoke({"coreStatement": masked_question}, thread_id="review-a1")
result = await review.resume("review-a1", {"action": "edit", "answer": masked_edit})
event = result.event()
```

## 시험

새 시험 12개 함수, 매개변수 확장 기준 20개 경로 시험을 작성했다. 실제 runner/StateGraph와 주입된 InMemorySaver를 사용한다. 중단 페이로드, approve/edit/reject, 직접 Command 재개, 실패한 edit의 재중단, saver 재사용, thread 격리, 잘못된 resume, 정책 기본값/override, 꺼진 정책의 원래 결과 동일성, 정상 리서치의 무중단, 리서치 필수 지표 재검사를 다룬다. 생성은 주입한 비동기 함수이며 실제 모델/임베더 평가가 아니다. 기존 시험·skip·기대값은 수정하지 않았다.

## 설계 대비 차이

허용 파일 범위 때문에 기존 그래프 노드/runner, 공통 RunEvent, HTTP·실험 보드에는 직접 연결하지 않았다. 명시적인 래퍼가 별도 그래프로 실제 실행 뒤 terminal review를 수행한다. `event()`는 공통 이벤트에 합칠 수 있는 두 필드만 제공한다. 기존 이벤트 sink로의 자동 전달은 후속 연결 필요다. METRICS_BOARD 정본의 기존 종료 유형에 대한 변경 없이 이번 요청의 `human` 확장을 래퍼 결과에 적용했다.

기존 research 계획 검토/checkpoint를 중첩한 runner는 이 래퍼에서 거절한다. 계획 검토 재개와 terminal 검토의 결합은 후속 연결 필요다. 수정문 인용은 평문 인터페이스의 한계상 보수적으로 인정하며, 의미가 같은 바꿔쓰기가 UNCITED로 다시 검토될 수 있다. 저장되는 검토 본문은 이벤트와 분리되며, 실제 배포용 saver의 접근권한·보존기간·동시 재개 제어는 호출자 영역이다.

## 미검증

작성한 시험의 실제 통과 여부, 실제 모델 품질, 실제 Chroma 검색, 영속 saver/프로세스 재시작, 동시 resume는 미검증이다. memvid 코드는 읽거나 수정하지 않았고 신규 의존도 없다. LangSmith 업로드, 네트워크 호출, 모델 실행/다운로드, 패키지 설치, 키 조회는 수행하지 않았다. 실제 모델 전용 CLI는 이 모듈에 없으므로 실행 명령을 임의로 만들지 않는다. 대표의 실제 모델 검증은 위 코드의 runner에 기존 주입 인터페이스로 모델/마스커를 구성한 뒤 별도로 수행해야 한다.

현재 브랜치를 유지하며 push·원격/브랜치 설정 변경은 하지 않는다.

커밋 차단: 지정 세 파일의 `git add -- ...` 및 `git commit -m "feat: add opt-in human review interrupt and resume"`가 모두 `.git/index.lock: Permission denied`로 실패했다. 현재 샌드박스의 `.git` 쓰기 권한이 없고 권한 상승도 허용되지 않는다. 커밋 해시는 없으며 세 파일은 untracked 상태로 보존한다. 따라서 커밋/깨끗한 작업 트리 요구는 이 환경에서 완료하지 못했다. NightCoder가 쓰기 가능한 환경에서 지정 파일을 추가하고 시험 후 커밋해야 한다.
