# E8 작은 응용

learning_applications.py는 200개 이하 소규모 입력에 세 응용을 제공한다. 결과 JSON/MD/HTML은 .runs에 저장하며 원문/프로필을 바꾸지 않는다.

중복: cosine 임계값 이상의 모든 쌍과 미리보기, 원문 SHA-256, 연결 성분을 보고한다. 각 쌍은 PENDING_HUMAN_REVIEW다. 연결 성분은 후보를 모을 뿐 그룹 전체의 동일성을 보장하지 않는다. 자동 병합/삭제 기능은 없다.

긴 프롬프트: 질의 유사도·중복 억제 기반 MMR 문장 원문 추출과 기존 Equalizer의 프로필/클래스/보호/관계 기반 감량을 같은 문자 예산으로 비교한다. 출력 길이·상태·보호 계약을 표에 기록한다. 생성 요약을 구현하거나 의미 보존 성능을 입증한 것이 아니다. MMR의 명시 보호 문장만으로 예산이 넘으면 보존하고 overflow를 보고한다. 기존 Equalizer 설정/감량 코드는 바꾸지 않았다.

주입: 기존 SemanticGuard로 보정 전 유사도 REVIEW 신호를 기록한다. canonical IntakeInputPolicy 결과는 별도 필드이며 유사도 ALLOW도 canonical BLOCK을 완화하지 않는다. 미설치면 정책 미연결로 표시한다. 이 실험을 C17의 injection 품질 연결 완료로 취급하지 않으며 검색 품질 분모에 넣지 않는다.

fake는 경로 시험, 실제 모델은 별도 열이다. 실제 모델·다운로드·LLM 생성·Kiwi 설치는 실행하지 않았다. 준비된 로컬 모델에서 대표 명령:

```powershell
.\.venv\Scripts\python.exe scripts/learning_applications.py --embedder e5 --mode duplicates --threshold .9 --out .runs/e8/e5-duplicates
.\.venv\Scripts\python.exe scripts/learning_applications.py --embedder e5 --mode compression --budget 600 --query "계약 자료와 준비 사항" --out .runs/e8/e5-compression
.\.venv\Scripts\python.exe scripts/learning_applications.py --embedder e5 --mode injection --review-threshold .8 --out .runs/e8/e5-injection
```

실제 임계값 선택에는 별도 검토/라벨 표본이 필요하다. 본 단계는 작은 검토 도구다.

공통 조건 점검으로 E4/E5 두 진입점의 CLI 출력 경로를 .runs 내부로 제한하고, 기존 개요 표에도 남아 있던 fake/실제 모델 수치 혼합을 제거했다. E8 쌍 점수와 감량 길이도 별도 열로 표시한다. 시험 함수의 임시 폴더 주입은 유지한다.

첫 전체 시험: `247 passed, 5 skipped` (28.86s). fake CLI 실행은 `.runs/e8/fake-path/`에 보고서를 생성했다. 보호 18개 SHA-256 동일, 기존 시험/데이터/프로필/frozen masking 수정 없음. 최종 출력 형식 점검 후 전체 시험 결과를 추가한다.

최종 전체 시험: `245 passed, 1 failed, 1 error, 5 skipped` (24.76s). 기존 `tests/test_index_lifecycle.py::test_versions_rollback_and_prune` 실패, `tests/test_memvid_store.py::test_versions_are_immutable`의 published fixture 오류다. 두 건 모두 `MemvidError: MV999: Tantivy error: tantivy index writer unavailable`이 `RetrievalUnavailable`로 전달됐다. 기존 시험·저장소 구현은 수정하거나 재시도하지 않았다. 로그: `.runs/e8-pytest-final.txt`.

최종 fake CLI는 정상 종료했다. 합성 주입 문장에서는 보조 REVIEW와 canonical `BLOCKED_JAILBREAK`를 서로 분리해 출력했고, 검색 품질 분모 제외가 true임을 확인했다. 실제 모델 결과는 없다. git diff 검증상 기존 시험/데이터/프로필/masking 수정 없음, 보호 18개 SHA-256 동일이다. 사용자 README 수정은 커밋에 포함하지 않는다.
