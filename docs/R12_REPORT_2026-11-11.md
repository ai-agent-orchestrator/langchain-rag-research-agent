# R12 — 문장과 인용 claim 대조 검수

## NightCoder TESTS 게이트 수정

이 절은 이전 실행의 시험·커밋 상태 기록과 구분되는 수정 실행 기록이다. 전달받은 게이트 결과는 694 passed, 2 failed, 1 skipped, 10 deselected이며 실패 상세는 제공되지 않았다.

코드 점검에서 재작성 경로 시험의 입력 설정 문제를 확인했다. `stance_split=False`, `auto_metrics=False`이고 체크리스트도 없어 계획의 필수 지표가 비어 있었다. 입력 claim은 중립 fact이므로 실제 `write_rule`이 선택하는 문장이 없고, 시험의 `draft.sentences[0]` 접근에서 실패한다. 이 문제는 MISQUOTED/OVERREACH 두 매개변수 경우에 공통이다. 게이트 traceback과의 직접 대조는 미검증이다.

명시적 `checklist=("매출",)`를 전달해 실제 계획·추출·작성 경로에서 수치와 인용이 있는 문장을 만들도록 수정했다. 계획 지표, 최초 작성 문장, claim 인용 존재에 대한 검증도 추가했다. 기존 실패 코드 탐지, rewrite 1회, 작성 2회, 최종 검수 통과 기대값은 그대로 유지했다. 검수 구현과 기본 설정은 변경하지 않았다. 새 fake 클래스나 모델은 사용하지 않는다.

이 환경에서 시험 미실행: PATH의 `python` 명령을 찾지 못했다. 기존 로컬 Python 실행기를 직접 지정한 전체 시험 및 해당 파일 시험도 `No module named pytest`로 시작하지 못했다. 패키지는 설치하지 않았다. 이번 실행의 최종 pytest 집계는 실행 0건, passed/failed/error/skipped 집계 불가이며 NightCoder 재검증이 필요하다. 두 Python 파일의 `compile` 구문 검사만 통과했다. 이를 pytest 통과 수에 포함하지 않는다.

보호 파일 18개의 SHA-256은 이전 기준과 모두 동일하다. 증거는 `.runs/r12/fix-protected-after.json`이며 `git diff --check`도 통과했다. 수정 파일은 이 보고서와 `tests/test_research_claim_verify.py` 두 개뿐이다. 기존 커밋·브랜치·원격 설정을 유지했고 push, 네트워크 호출, 모델 실행, 다운로드는 수행하지 않았다. 설계 대비 차이와 미검증 범위는 아래 본문과 같으며, 그래프 옵션의 후속 연결 필요 상태도 유지한다.

수정 커밋도 시도했으나 `git add`와 `git commit` 모두 `.git/index.lock: Permission denied`로 차단되었다. 이 환경은 `.git` 읽기만 허용하며 권한 승격도 허용하지 않는다. 새 커밋 해시는 없으며 위 두 파일이 미커밋 상태로 남는다. NightCoder의 Git 쓰기 가능한 환경에서 이 수정의 커밋과 시험이 필요하다.

## 구현

`verify_report(..., check_claim_alignment=False)` 옵션을 추가했다. 기본값과 기존 코드·반환 계약은 유지한다. 활성화하면 note가 아닌 각 ReportSentence가 실제 인용한 claim만 내용어·수치 대조 대상으로 삼는다. 원문이나 예외 메시지는 반환하지 않고 코드만 반환한다. 규칙 버전은 `CLAIM_ALIGNMENT_VERSION = "claim-alignment/1"`이며 기존 ResearchFilter의 규칙·버전은 변경하지 않았다.

`MISQUOTED`는 문장 절의 수치가 내용어 기준으로 가장 가까운 인용 claim에 없을 때 발생한다. 내용어 Jaccard 유사도로 수치를 보지 않고 후보를 고른 뒤 수치를 확인하므로, 다른 claim의 수치가 보고서 전체에 존재해도 잘못 차용할 수 없다. 동률이면 그중 하나가 절의 모든 수치를 담아야 한다. 세미콜론·줄바꿈·문장 경계로 절을 나누고 기존 수치 정규화를 사용한다.

`OVERREACH`는 문장 내용어 중 인용 claim 전체에 없는 비율이 0.5를 초과할 때 발생한다. 명시적 인과 연결 표현으로 나눈 원인·결과 내용어가 인용 claim과 직접 대응하는 정도보다 반대로 대응하는 정도가 높아도 발생한다. English because/due to는 원인이 뒤에 오는 순서로 해석한다. 두 코드는 각각 보고서당 한 번만 반환한다.

인용 claim을 그대로 추출한 문장은 새 휴리스틱을 적용하기 전에 허용한다. 기존 규칙 작성기의 결과에 새 검수로 인한 실패를 추가하지 않기 위한 처리다. 시스템 note는 제외하며 빈 보고서·잘못된 인용은 기존 EMPTY_REPORT/UNCITED 처리를 유지한다. 새 의존성·모델·저장소 코드는 없다.

두 코드는 GAP가 아닌 서술 오류이므로 기존 그래프의 재작성 조건에 해당한다. verify_report는 기존처럼 코드 튜플을 반환하며 별도 retryable 객체를 도입하지 않았다.

## 시험

신규 시험은 실제 Claim, Draft, ReportSentence, ResearchPlan, extract_rule, write_rule 및 ResearchRunner/LangGraph를 사용한다. 수치 바꿔치기, 다른 출처 수치 차용, 두 인용 claim의 수치 교환, 한국어·영어 인과 방향 반전, 내용어 과장, 인용되지 않은 claim의 내용어 차용, 인용 마커, 쉼표·소수 수치, note·없는 인용·빈 보고서, 옵션 기본값 보존과 정상 추출문을 다룬다.

그래프 경로 시험은 실제 작성 결과를 최초 한 번만 변조하고 검수 옵션을 주입한다. MISQUOTED/OVERREACH 발생 뒤 실제 rewrite → write → verify를 통해 정상 추출문으로 복구되는지 확인하도록 작성했다. 모델·임베더 대역은 없으며 합성 입력을 사용한 경로 시험이다. 실제 모델 품질 평가가 아니다. 개인정보 형태의 입력은 사용하지 않았다.

전체 시험 실행을 시도한 명령:

```powershell
python -m pytest -q -p no:cacheprovider --basetemp=.runs/r12/full-tmp
```

tests not run here: Python executable is unavailable (CommandNotFoundException).

이 환경에서 시험 미실행: PATH에 Python 실행기가 없으며 저장소의 .venv-python/.venv-cache에서도 사용 가능한 Python 실행기를 찾지 못했다. 실행 0건, passed/failed/error/skipped 집계 불가다. NightCoder 게이트에서 전체 시험 판정이 필요하다. 실행하지 않은 시험을 통과로 표시하지 않는다. 네트워크·실제 모델·LLM 호출·다운로드·패키지 설치는 수행하지 않았다.

## 설계 대비 차이

설계 8-6의 문장 ↔ 인용 claim 대조를 결정적 규칙으로 구현했다. 설계의 UNGROUNDED_SENTENCE 대신 작업 명세가 지정한 MISQUOTED/OVERREACH를 추가했다. 기본 동작 보존 요구에 따라 옵션은 꺼져 있다. 허용 파일 밖인 rag/research_graph.py의 ResearchConfig 및 verify 노드에서 옵션을 노출하는 것은 **후속 연결 필요**다. 경로 시험에서만 옵션을 주입한다.

일반적인 의미 함의 판정 대신 내용어 비율·가장 가까운 claim·명시적 인과 표현을 사용했다. 단일 절에 여러 claim의 수치를 합쳐 쓴 정상 요약도 보수적으로 MISQUOTED가 될 수 있으므로, 수치별 근거를 절로 분리한 조합과 정확한 추출문을 정상 경로로 다룬다. 이 한계 때문에 기본 경로에 자동 적용하지 않는다.

## 미검증

전체 시험 통과, 실제 문서·생성문에서 오탐/누락 수준은 미검증이다. 동의어·복잡한 부정·단위 및 수치 의미 동치·암시적 인과관계·지원하지 않는 인과 표현·어휘 유사도 동률에서의 수치 귀속은 완전하게 판정하지 않는다. 내용어 집합이 같은 모든 왜곡을 탐지한다는 보장은 없다. 여러 수치의 복잡한 대응 관계도 미검증이다. 실제 모델은 필요하지 않아 실행 명령을 추가하지 않았다.

## 범위 및 보호 확인

## 커밋 제약

지정 세 파일의 git add와 `git commit -m "feat(guard): add optional sentence claim alignment checks"`를 모두 시도했으나 `.git/index.lock: Permission denied`로 실패했다. 이 샌드박스의 .git은 읽기 전용이며 권한 상승이 허용되지 않는다. 커밋 해시는 없고 미커밋 변경 0건 조건을 충족하지 못했다. 작업을 삭제하지 않고 세 파일에 보존하며 Git 쓰기가 가능한 NightCoder 환경에서 한 커밋으로 수집해야 한다.
