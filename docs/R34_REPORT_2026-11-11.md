## 구현

`docs/KIT_EXTRACTION_PLAN.ko.md`를 작성했다. 기존 공개 파사드·주입점, 파일별 import 그래프, GuidanceReply·tracing·execution 경계를 끊는 계약 제안, 패키지 구조, 원 저장소 호환 연결, 시험·문항 이동 목록, 단계별 위험과 완료 기준을 기록했다. 확인한 현재 사실과 후속 제안을 구분했다.

R34의 구체 지시인 “코드는 수정하지 않는다”와 두 문서의 허용 범위를 적용했다. 소스·시험·기본 설정·KNOWN_DEBT는 변경하지 않았다. Chroma 연결은 원 저장소 어댑터로 남기고 memvid는 새 개발 경로에서 제외했다. 정적 import 조사 결과는 `.runs/r34/imports.json`이다.

## 시험

전체 시험 시도 명령은 NightCoder 게이트의 memvid 표식 제외 범위다.

```powershell
.\.venv\Scripts\python.exe -m pytest -q -m 'not memvid' --basetemp=.runs/r34/pytest-tmp
```

**tests not run here: repository virtualenv Python has no pytest module.**

이 환경에서 시험 미실행: `No module named pytest`로 수집 전에 종료했다(exit 1). 실행 시험 0개이며 passed/failed/error/skipped는 집계 불가다. 시험 실패·수집 오류 건수로 환산하지 않는다. 로그는 `.runs/r34/full-tests.txt`에 보관했다. 패키지를 설치하거나 대역을 넣어 우회하지 않았다. 전체 시험 판정은 NightCoder 게이트에서 필요하다.

표준 라이브러리 AST로 조사 대상 20개 파일의 내부 import를 수집했다. 문서의 현 파일·시험·문항 경로 존재와 `git diff --check`를 확인했다. 문서 전용 변경이므로 새 기능 시험은 추가하지 않았다.
