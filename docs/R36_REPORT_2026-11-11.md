# R36 — 노드 콜백 수집기

## 구현

`rag/run_trace.py`에 MATURITY=incubating 수집기를 추가했다. R35의 실제
RunEvent·NodeEvent·cost_krw 계약을 재사용하며 신규 memvid 의존성이 없다.
설계 정본 METRICS_BOARD.ko.md, RESEARCH_GRAPH_DESIGN.ko.md,
DOMAIN_FILTERS.ko.md, LANGGRAPH_GUARDRAIL.ko.md와 구조 시험을 읽었다.

- `event_from_result(result, domain, config)`는 기존 ResearchResult의 path/cost와
  stopped/verify_codes를 변환한다. config는 이벤트 메타데이터 dict다.
  반복 write의 입력·출력 추정 토큰을 호출별로 나누고 rewrite/retrieve_gap 횟수와
  최초 검수 이후 verify 재실행 횟수를 기록한다. 정상은 END, 미통과·안전 중단·계획
  검토 대기는 give_up, 노드 한도·오류·비용 한도는 cutoff로 분류한다.
- `TraceCollector`는 LangGraph 노드의 start/end 콜백을 invocation ID로 연결한다.
  중첩 체인은 중복 집계하지 않으며 병렬 호출도 개별 시간으로 기록한다.
  시계는 monotonic 초 단위 callable로 주입한다. LLM/chat 콜백이 보고하는 모델명과
  입력·출력 토큰을 수집하며 첫 토큰 콜백으로 TTFT를 기록한다.
  모델 토큰은 llm_output의 token_usage/usage 또는 메시지 usage_metadata를 사용한다.
- `JsonlSink`는 기본 `.runs/events/<domain>/events.jsonl`에 UTF-8 JSON 한 줄을
  추가한다. domain 경로 이탈과 .runs 밖 root를 거부한다. 잠금은 동일 싱크 객체를
  공유하는 스레드 범위이며 프로세스 간 기록 원자성은 미검증이다.
- `TraceResearchRunner`는 기존 ResearchRunner의 하위 클래스다. 기본 trace=False는
  수집기·시계·싱크를 생성하거나 호출하지 않는다. trace=True 또는 주입한 collector로
  켜면 기존 run/resume 흐름에 콜백을 전달하고 반환 결과를 바꾸지 않는다.

사용 예시(네트워크·모델 없이 규칙 경로 실행):

```python
from rag_research_agent.rag.research_graph import keyword_search
from rag_research_agent.rag.run_trace import TraceCollector, TraceResearchRunner

collector = TraceCollector(domain="research", config={"dataset": "local", "sha": "rev-a1"})
runner = TraceResearchRunner(
    keyword_search({"doc-a1": "매출은 증가했다."}), trace=collector,
)
result = runner.run("매출을 정리해 주세요.")
event = collector.last_event
```

## 시험

신규 tests/test_run_trace.py에 매개변수 확장 포함 **16개 시험 사례**를 작성했다.
실제 ResearchRunner·그래프·ResearchResult·RunEvent·JSONL 싱크를 사용한다.
경로·반복 토큰 분배·루프 수, 실제 그래프 종료 3종, 검토 대기·비용 한도,
JSONL 추가 기록·역직렬화, 경로 이탈 거부, trace 꺼짐의 결과 동일성과 파일 부작용 없음,
켜짐의 실제 노드 콜백, 주입 시계, 모델 토큰·역할 호출 수·원가, 중첩·병렬 콜백·TTFT를
검사한다. 모델 시험은 실제 LLMResult·Generation 자료형으로 콜백 입력을 전달하는
경로 시험이며 실제 모델 품질·성능 평가가 아니다. 기존 시험과 기대값·skip은 수정하지 않았다.

전체 시험 실행 시도 명령:

```powershell
python -m pytest -q -p no:cacheprovider --basetemp=.runs/r36/full-tmp --junitxml=.runs/r36/full-pytest.xml
```

**tests not run here: Python is not available on PATH.**

이 환경에서 시험 미실행: python 명령을 찾지 못해 시험 명령을 시작하지 못했다.
python·python3·python3.12·py·pytest 실행기를 PATH에서 찾지 못했고,
.venv-python·.venv-cache 안에서도 python 실행 파일을 찾지 못했다.
실행 0건이며 passed/failed/error/skipped는 미실행으로 집계 불가다.
NightCoder 게이트에서 신규 16개 및 전체 시험 판정이 필요하다.

## 설계 대비 차이

허용 범위에 research_graph.py와 외부 서비스 호출부가 없으므로 기존 ResearchRunner에
직접 trace 인수를 추가하지 않았다. 새 모듈의 TraceResearchRunner가 trace 옵션을
제공한다. 기존 서비스·CLI에서 해당 클래스로 교체하는 작업은 **후속 연결 필요**다.
observe/tracing.py를 수정하거나 원격 tracing을 활성화하지 않았다.

기존 cost는 shadow token이며 모델 호출 증거가 아니다. 규칙 노드는 model=null,
estimated=true, calls=0을 유지한다. 실제 모델 콜백이 있을 때 config.model_roles의
모델명→slm/flagship 명시 매핑으로 호출 수를 채운다. 한 노드에서 여러 모델을 호출하면
같은 name의 NodeEvent를 호출별로 남기고 노드 소요 시간은 첫 항목에만 기록한다.
path는 실제 그래프 경로를 별도로 보존하며 nodes는 콜백 완료 순서다.
pricing을 명시하면 R35 계산기로 환산하며 미등록 모델 단가는 실패한다.
원가·TTFT·grade를 얻지 못하면 0/estimated로 남기므로 측정된 무료·무지연으로
해석하면 안 된다. 기본 run도 보수적으로 estimated=true다.

원문·질문·보고서·예외 메시지·자유 텍스트 log는 저장하지 않는다. 기존 log에는
문서 수와 코드만 있고 확실한 grade 분모·마스킹된 reason/span 계약이 없으므로
임의로 추론하지 않는다. grade는 호출자 주입이며 guard는 빈 배열이다.
grade/guard 상세 어댑터는 **후속 연결 필요**다. injection을 검색 품질 분모로 집계하지 않는다.
예외로 runner가 결과를 반환하지 못한 실행은 JSONL 이벤트를 기록하지 않는다.
수집기 하나는 동시에 실행 중인 호출 하나에만 사용한다.
resume의 result.path는 현재 호출, cost는 체크포인트 누적일 수 있다. 실시간 collector는
현재 호출 콜백만 기록하며 resume을 포함한 전체 세션 통합은 후속 연결 필요다.

## 미검증·보호 확인

신규·전체 시험 실행 통과, 설치된 LangGraph 버전의 콜백 호환성, 체크포인트 resume,
실제 모델 토큰·원가·성능, 서비스·보드 종단 연결은 **미검증**이다.
실제 모델 실행 명령은 제공하지 않는다. 이 기능의 검증에는 모델 실행이 필요 없으며
현재 프로젝트에는 완성된 실제 모델 작성기 실행 명령도 없다.
패키지 설치·모델 다운로드·실제 모델·LLM 호출·네트워크 접근을 수행하지 않았다.
새 import는 rag 안에서 core/기존 rag/표준 라이브러리/기존 LangChain만 사용한다.
KNOWN_DEBT·Chroma 기본값·기존 memvid 시험은 변경하지 않았다.

보호 파일은 `.runs/n10/protected-after.json`의 Expected를 기준으로 전후 **18/18 SHA-256 동일**이다.
결과는 `.runs/r36/protected-before.json`, `.runs/r36/protected-after.json`에 기록했다.
기준 manifest 생성 정당성은 미검증이다. 금지 파일과 README는 변경하지 않았다.
결과 파일은 .runs/r36 안에만 썼다. `git diff --check`는 통과했다.
push·원격·브랜치 설정 변경은 하지 않았다.
