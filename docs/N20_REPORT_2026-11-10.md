# N20 보고서 — 문장 분리 경계 시험

2026-11-10 KST. AGENTS.md를 먼저 읽고 현재 저장소·브랜치 `nc/rra-codex`에서 NightCoder 규칙을 적용했다.

## 구현

`tests/test_sentences_edges.py`에 매개변수 전개 기준 25건을 추가했다. 기존 문장 시험과 같이 합성 문자열을 실제 `SentenceChunker`에 직접 전달한다. 대체 구현·mock·임베더·저장소는 필요하지 않다.

- 경계 16건: 마침표 없음, 앞뒤 공백, LF/CRLF/CR 줄바꿈, 소수점, 약어, 번호 목록, 직선·곡선 따옴표, 한국어 인용 조사, 괄호·중첩 괄호, 연속 구두점.
- 빈 문자열·공백·줄바꿈만 있는 입력 6건: 빈 Segment 목록 반환.
- 정확한 오프셋 3건: 반복 문장, 이모지·한글, 혼합 줄바꿈, 탭과 내부 연속 공백. 숫자로 명시한 시작·끝 위치와 원문 부분 문자열을 대조한다. 경계 16건에서도 원문 슬라이스, 순서·범위, ID와 source를 확인한다.

생산 코드·기존 시험·기대값·skip·KNOWN_DEBT는 변경하지 않았다. 신규 생산 모듈은 없다. Chroma 개발 기본값을 유지하며 memvid 의존성을 추가하지 않았다. 네트워크·모델 다운로드·실제 모델·LLM 호출·패키지 설치·push·원격/브랜치 설정 변경은 수행하지 않았다.

## 관찰된 동작

아래는 소스 정적 확인에 근거한 현재 동작이다. 런타임 관찰은 미검증이며 시험 기대값에 이 동작을 명시했다.

- 번호 목록은 문장 중간 마침표와 관계없이 줄 전체가 한 Segment다.
- 등록된 약어 뒤 마침표는 문장 경계로 쓰이지 않는다. `Items etc. Next item.`도 한 Segment다.
- 따옴표 내부의 중간 마침표는 유지하고, 닫는 따옴표 뒤에서 분리할 수 있다. 한국어 `라고` 인용절은 같은 문장에 남는다.
- 괄호 내부 마침표는 분리하지 않는다. 줄바꿈은 종결 마침표 없이도 경계가 된다.
- 앞뒤 공백은 반환 범위에서 제외하지만 원문을 수정하지 않는다. 내부 공백과 구두점은 원문 슬라이스 그대로 남는다.

명백한 결함으로 판정해 보고서에만 남긴 항목은 없다. xfail이나 skip은 추가하지 않았다.

## 시험 / 확인

파일 작성 후 전체 시험 명령을 시도했다.

```powershell
python -m pytest -q -p no:cacheprovider --basetemp=.runs/n20/full-tmp --junitxml=.runs/n20/full-pytest.xml
```

**tests not run here: Python is not available on PATH.**

이 환경에서 시험 미실행: `CommandNotFoundException`으로 명령을 시작하지 못했다. `python`, `py`, `pytest`를 PATH에서 찾지 못했다. 실행 0건이며 passed/failed/error/skipped는 모두 집계 불가(미실행)다. 신규 25건은 작성 건수이며 통과 수치가 아니다. JUnit은 생성되지 않았다. 최종 시험 판정은 NightCoder 게이트가 필요하다.

보호 기준은 기존 `.runs/n10/protected-after.json`의 Expected SHA-256이다. 보호 파일 18/18은 기준·작업 전·후 모두 동일하다. 증거는 `.runs/n20/protected-before.json`, `.runs/n20/protected-after.json`에 보관했다. 초기 git status는 깨끗했으며 지정 신규 두 파일만 추가했다. `git diff --check`를 확인했다.

## 입증하지 못한 것 / 미검증

Python 부재로 신규 시험과 전체 시험의 실행 결과는 미검증이다. 모든 자연어 문장 경계에 대한 정확성을 입증하지 않았다. 검색 품질·실제 임베더·모델 평가는 수행하지 않았다.
