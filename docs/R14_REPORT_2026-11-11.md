# R14 — 리서치 그래프 가드레일 어댑터

## 구현

`rag/research_guardrail.py`에 명시적으로 생성할 때만 동작하는 `ResearchGuardrailAdapter`를 추가했다. 기존 기본 설정과 서버 연결은 바꾸지 않는다. 실제 `ResearchRunner.run`을 작업 스레드에서 실행하고 `(GuidanceReply, evidence_texts)`로 반환한다. 검색과 모델은 기존 주입 인터페이스를 그대로 사용한다. 저장소를 새로 선택하지 않으며 memvid 의존성을 추가하지 않았다. Chroma 검색 어댑터를 주입한 ResearchRunner도 같은 계약으로 받는다.

사용 예:

```python
adapter = ResearchGuardrailAdapter(research_runner, tokens_per_unit=1000)
runner = GuardrailRunner(adapter, domain=get_filter("research"), cost=adapter.cost)
result = await runner.ainvoke({"coreStatement": masked_question, "checklist": masked_metrics})
# 같은 설정을 연결하는 편의 함수: adapter.guardrail(limits=GuardrailLimits(...))
```

입력 질문·체크리스트·검색 자료는 호출자가 먼저 마스킹해야 한다. 기본 파이프라인에 연결하는 작업은 후속 연결 필요다. 체크포인터/사람 검토가 켜진 ResearchRunner는 생성 시 거부한다. 기존 세션 재개 계약을 임의로 바꾸지 않았다.

`tokens_to_cost`는 추정 토큰 / tokens_per_unit으로 환산한다. 기본은 1000토큰당 1.0 단위이며 양수·유한 환산율을 검증한다. 비용은 reply의 내부 필드에 넣어 동시 요청 사이의 마지막 결과 공유를 피했다. 기존 외부 직렬화에는 추가되지 않는다. 토큰 장부를 받지 못한 실패 호출은 기존 가드레일 기본 추정 0.1 단위를 사용한다. 실제 과금·실제 토큰 측정은 아니다. 규칙 작성기를 모델 호출로 세지 않는다.

검수 실패 시 초안 대신 기존 `VERIFY_FAILED_ANSWER`, `REQUEST_MORE`, `reason_code="VERIFY_FAILED"`를 반환한다. 내부 실패 코드는 `research_verify_codes`로만 남고 외부 답변 직렬화에는 포함되지 않는다. 중단·빈 초안·interrupt 결과도 OK로 승격하지 않는다. 근거는 refine 이후 채택된 claim의 source에 한정하고, 인용 ID는 보고서가 인용한 claim의 source ID로 변환한다. 차단된 주입 자료를 근거로 되돌려 넣지 않는다.

## 시험

신규 pytest 사례는 매개변수 확장 기준 19개다. 실제 ResearchRunner·GuardrailRunner·규칙 검색을 사용한다. 정상 응답/근거/비용/경로/domain_log, 내부 검수 실패, COST_LIMIT, screen 차단 시 검색 미호출, smalltalk, 주입 자료 제외, 근거 없음, 반대 근거 부족 중단, 환산율·토큰 오류, 동시 요청, 네이티브 서브그래프 비교를 정의했다. 임베더·실제 모델을 실행하지 않았으며 품질 평가는 아니다.

전체 시험 실행 시도:

```powershell
python -m pytest -q -p no:cacheprovider --basetemp=.runs/r14/full-tmp
```

tests not run here: Python executable is unavailable (CommandNotFoundException).

이 환경에서 시험 미실행: PATH의 python/py 및 저장소 가상환경에서 Python 실행기를 찾지 못했다. 전체 시험 명령이 시작되지 않았다. 실행 0건, passed/failed/error/skipped 집계 불가. 신규 19개 사례도 실행 통과는 미검증이며 NightCoder 게이트 판정이 필요하다. memvid 시험은 실행·수정·재시험·skip하지 않았다.

보호 파일 18개는 `.runs/n10/protected-after.json`의 Expected와 SHA-256을 대조해 18/18 동일했다. 증거는 `.runs/r14/protected-after.json`이다. `git diff --check` 및 신규 파일 줄 끝 공백 검사를 수행했다. 기존 시험/기대값/skip/KNOWN_DEBT, 금지 파일, data/profiles는 변경하지 않았다. 초기 작업 트리는 깨끗했다.

## 설계 대비 차이와 서브그래프 비교

설계 정본 세 문서의 classify → screen → rag → verify → finish 구조를 재사용한다. 정상 경로의 domain_log는 SCREEN:PASS, VERIFY:PASS다. 비용 초과는 verify 전 kill로 가고 reply가 제거된다. 외부 비용 관문은 내부 리서치 한 번이 끝난 뒤 총 추정 비용을 확인한다. 내부 개별 노드의 선제 중단은 기존 ResearchConfig 예산에 맡긴다. 가드레일 max_loops는 내부 개별 노드 횟수가 아니라 전체 RAG 호출 횟수다.

내부 claim 단위 검수 실패를 기존 외부 텍스트 필터에 다시 맡기면 GAP 같은 내부 코드를 놓칠 수 있다. 허용 파일 범위에서 안전하게 연결하기 위해 기존 안전 답변을 어댑터에서 즉시 반환했다. 이 경로는 classify → screen → rag → finish이며 외부 verify 노드·재생성은 실행되지 않는다. 따라서 GuardrailResult.verify_codes는 비어 있고 domain_log는 SCREEN:PASS만 남는다. 내부 원인은 reply.research_verify_codes로 확인한다. 외부 VERIFY:FAIL 로그에 내부 코드를 합치는 기능은 가드레일 계약 확장이 필요하므로 후속 연결 필요다. 검수 미통과 부분 보고서를 노출하는 설계와 달리 이 어댑터는 요청된 안전 답변을 우선한다.

네이티브 서브그래프 시험은 `StateGraph(ResearchState)`의 노드로 실제 `ResearchRunner.graph`를 직접 넣고 START/END로 연결한다. 보고서·검수 코드·누적 추정 토큰이 ResearchRunner 실행과 같은지 비교한다. 실행기 부재로 비교 실행은 미검증이다. 기존 GuardrailState는 request/reply, ResearchState는 question/draft를 쓰므로 기존 가드레일의 RAG 위치에 바로 대입할 수 없다. 운영 연결은 상태 변환을 담당하는 호출형 어댑터를 선택했고, 기존 가드레일·리서치 그래프를 수정하지 않았다.

## 미검증과 인계

실제 모델 품질, 실제 Chroma 결합 실행, checkpoint/resume 연결, 서버 연결, 전체 pytest 통과와 서브그래프 실행 결과는 미검증이다. 모델·네트워크·다운로드·패키지 설치·LangSmith 업로드는 수행하지 않았다. 실제 모델 실행을 위한 새로운 CLI는 만들지 않았다. 대표가 이미 로컬에 보유한 모델·마스커를 주입한 ResearchRunner를 위 사용 예에 전달해 실행해야 한다. 실행 가능한 모델 CLI 명령은 이 변경 범위에 없음.

변경 파일은 지정된 소스·신규 시험·본 보고서 세 파일이다. 현재 브랜치 `nc/rra-codex`를 유지했고 push/원격 변경은 하지 않았다. `git add`와 `git commit -m "feat: adapt research graph to guardrail RAG node"` 모두 `fatal: Unable to create 'C:/work/rra-codex/.git/index.lock': Permission denied`로 실패했다. `.git` 읽기 전용 샌드박스에서 권한 상승은 불가능하다. 커밋 해시는 없으며 미커밋 변경 0건 조건은 충족하지 못했다. 작업을 삭제하지 않고 세 파일을 보존했다. Git 쓰기가 가능한 NightCoder 환경에서 지정된 세 파일을 단일 커밋으로 수집해야 한다.
