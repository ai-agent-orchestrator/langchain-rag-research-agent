# R3 — E2 재검색 비용을 가드레일 예산에 반영

## 무엇을 고쳤나

- `retry_graph.py`: 반환 상태의 `retrieval_calls`에 실제 `Library.search()` 호출 수를 기록한다. 최초 검색을 포함하고, 한 재시도에서 여러 하위 질문을 검색하면 각각 센다. 호출마다 0으로 초기화하며 성공·재시도 소진·변형 쿼리 소진 경로 모두에 남는다. 기존 재시도 상한과 Equalizer 동작은 유지한다.
- `guidance.py`: `GuidanceReply` 마지막 필드에 `retrieval_calls=1`을 추가했다. 기존 위치 인자와 `to_dict()`의 정상·차단 응답 형식은 유지한다.
- `guardrail_graph.py`: `default_cost`는 생성 호출당 1.0에 검색 호출당 0.1을 합산한다. 예외 응답인 `None`은 기존 0.1을 유지한다. 검색 3회는 0.3, 생성 1회까지 있으면 1.3이며, 단일 검색·생성 1회는 기존과 같은 1.1이다. 정수 호출 수를 10으로 나누어 검색 3회의 비용이 한도 0.3과 같을 때 부동소수점 곱셈 오차로 kill되지 않게 했다.

## 시험

신규 `tests/test_retry_budget.py`에 9개 경로 시험을 추가했다. 가짜 그래프나 저장소 대신 실제 `Library`와 Chroma, `build_graph`, `GuidanceReply`, `GuardrailRunner`를 사용한다. 임베딩만 기존 `FakeEmbedder`이며 합성 문서를 쓴다. 실제 모델 품질 평가가 아니다.

- 총 검색 3회와 요청별 카운터 초기화, 한 라운드의 하위 질문 검색 2회 집계.
- 첫 검색 성공(Equalizer 경유), 재시도 비활성화, 변형 쿼리 소진 시 기존 비용 유지.
- 실제 E2 상태를 응답 카운터로 전달하여 가드레일 비용 0.3 확인, 한도 0.3에서는 finish, 한도 0.2 초과 시 `COST_LIMIT`과 reply 제거.
- 생성 비용 합산, 기존 기본 비용 및 정상·차단 `to_dict()` 형식 유지.

```powershell

JUnit은 생성되지 않았다. 신규 9개와 기존 전체 시험의 실행 판정은 NightCoder 게이트가 필요하다.

## 고치지 않은 것과 이유 / 미검증

- E2는 상태 dict, 기존 `GuidancePipeline`은 별도의 단일 검색 경로다. E2를 사용하는 호출자는 응답을 만들 때 `retrieval_calls=state["retrieval_calls"]`를 전달해야 한다. 회귀 시험은 실제 E2 실행 결과를 이 방식으로 가드레일에 연결한다. 기존 서비스의 E2 선택·어댑터 배선은 이번 요청에 없으므로 **후속 연결 필요**다.
- `max_loops`는 기존대로 외부 RAG 노드 실행 횟수다. 내부 E2는 기존 최대 2회 재시도를 유지하고 검색 비용을 반환 후 정산한다. 내부 검색 도중의 선제 중단·외부 루프 수와의 통합은 구현하지 않았다. 이번 명세의 변경 대상은 검색 횟수 노출과 `default_cost` 반영이다.
- 예외로 E2가 반환하지 못한 경우 세부 검색 횟수는 전달되지 않으며 기존 `cost(None)=0.1`을 따른다. 부분 실행 비용 전파는 미구현이다.
- 런타임·전체 시험은 Python 부재로 **미검증**이다. 네트워크, 실제 모델 실행·다운로드, LLM 호출, 패키지 설치는 수행하지 않았다. memvid·동결 masking·data·profiles·README 및 저장소 밖 파일은 수정하지 않았다. push·원격·브랜치 설정 변경은 하지 않았다.
