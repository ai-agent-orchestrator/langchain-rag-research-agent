# E7 키워드·벡터 결합 비교

eval_retrieval_v2.py에 `--retrieval lex|vector|rrf|weighted`, `--alpha`, `--rrf-k`를 추가했다. 별도 compare_retrieval_fusion.py가 키워드/벡터 단독과 RRF k, 가중합 α 격자를 같은 compare 문항으로 비교한다. 문항 유형별 Recall@k(기본 3), MRR, 오수용, 오거절을 표에 출력한다. injection은 검색 품질 분모에서 제외한다. confirm은 방식 선택 격자에 사용하지 않는다.

후보는 전체 청크로 동일하게 잡는다. RRF는 순위 기반, 가중합은 α*(cos+1)/2+(1−α)*lex/max_lex다. lex가 비면 해당 항은 0이다. 벡터는 L2 정규화 cosine, 키워드는 비음수 term-match count를 가정한다. 이 정규화는 확률 보정이 아니며 서로 다른 방식의 원시 점수/임계값은 비교할 수 없다. 각 방식은 compare 점수에서 별도로 gate를 보정한다. α=0은 키워드만, α=1은 벡터만 반영한다. fake는 경로 시험 열이며 의미 검색 성능으로 해석하지 않는다.

실제 모델은 실행하지 않았다. 대표 명령:

```powershell
.\.venv\Scripts\python.exe scripts/compare_retrieval_fusion.py --set data/golden_retrieval/terms_v2.json --embedder e5 --alphas 0 .25 .5 .75 1 --rrf-ks 10 60 100 --chunk-size 256 --overlap 32 --out .runs/e7/e5
# compare에서 고른 한 설정만 confirm에 적용
.\.venv\Scripts\python.exe scripts/eval_retrieval_v2.py --set data/golden_retrieval/terms_v2.json --embedder e5 --split confirm --retrieval weighted --alpha .5 --chunk-size 256 --overlap 32 --out .runs/e7/confirm-selected
```

Chroma 미설치로 실제 서재 CLI 실행은 E5에서 차단되어 재실행/설치하지 않았다. 새 시험은 주입한 인덱스로 서로 다른 순위, α 양 끝, RRF k 변화, 유형별 보고서, confirm 분리를 확인한다.

전체 시험: `243 passed, 5 skipped` (27.69s). 실제 모델 결과는 없다. 출력 표의 기존 bootstrap 구간은 검색 지표 요약용이며, 판정 경계의 소표본 오수용/오거절 추론에는 E6 Wilson 보고서를 사용해야 한다.
