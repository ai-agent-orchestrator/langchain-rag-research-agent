# R22 — 법률 합성 평가 팩

## 구현

- `evals/domains/legal/cases.json`: 형사 3·민사 3·가사 2, 총 8개 합성 사례.
  각 사례는 질문, 가상 조문 원문 형태의 근거, 날짜가 있는 사건 기록,
  필수 조문 2개, 시간순 사건 정답, 금지 인용(없는 조문·폐지 조문), 정답 문장을 담는다.
  사례마다 폐지 표시 문서 1개를 포함했다. 조문 번호는 모두 제900조 이상이다.
  실제 사건·실명·판례번호를 사용하지 않았으며 개인정보 모양 값도 필요하지 않아 넣지 않았다.
  문서 ID는 `doc-a1` 같은 영문 혼합 식별자다.
- `evals/domains/legal/metrics.json`: R21이 읽는 선언형 지표 4개.
  필수 조문 포함률만 품질 지표이며, 없는 조문 인용 수·폐지 조문 인용 수·시간 순서
  오류 수는 안전 지표로 분리한다. 비율은 R21의 표본 수·Wilson 95% 구간을 따른다.
- `tests/test_legal_eval_pack.py`: R21 `load_pack`, `validate_metrics`, `evaluate`, `run`과
  실제 R18 `LegalFilter.check_input/verify`를 호출한다. 대체 필터나 모델을 만들지 않았다.
  테스트의 실행기 주입 함수는 실제 `Issue.count`만큼 진단 코드를 목록에 넣어
  R21의 `count` 입력으로 변환한다. 정답의 금지 목록을 탐지 규칙으로 사용하지 않는다.
  제공 출력에 저장된 빈 안전 목록도 실제 필터 판정과 일치하는지 검증한다.

팩의 `output`은 정답 형식 확인용 제공 출력이다. 다음 명령은 제공 출력을 평가할 뿐,
새 답변 생성이나 실제 법률 필터 실행을 의미하지 않는다.

```powershell
python scripts/domain_eval.py --domain legal
```

새 답변을 평가하려면 R21의 `evaluator(case)` 인터페이스로 답변과 실제 필터 판정 목록을
제공해야 한다. 시험의 `verified_output`이 이 연결을 검증한다. 안전 목록 필드는
`unsupported_statutes`, `repealed_statutes`, `timeline_errors`이며 진단 코드 목록이다.
없는 조문·폐지 조문은 R18의 고유 조문 개수, 시간 오류는 `TIMELINE_MIXED` 판정 개수다.
시간 오류 수를 모든 사건 쌍의 역전 개수로 해석해서는 안 된다.
R21의 `errors`는 위반 문항 수이고 `count`는 해당 개수의 합이다.

## 설계 대비 차이

설계 정본 `RESEARCH_GRAPH_DESIGN.ko.md`, `DOMAIN_FILTERS.ko.md`,
`LANGGRAPH_GUARDRAIL.ko.md`의 교체형 도메인 경계를 따라 JSON 팩으로 추가했다.
R18/R21이 모두 있어 형식 시험 외에 실제 클래스 연결 시험도 정의했다.
새 src 모듈이나 모듈 간 import를 추가하지 않았고 MATURITY·KNOWN_DEBT·기본 설정을 바꾸지 않았다.
memvid를 사용하지 않는다. 저장소나 임베더가 필요 없는 작업이며 Chroma 기본값을 유지한다.

허용 파일 범위에 생산용 법률 실행기 어댑터는 없어 R21 기본 CLI는 제공 출력만 평가한다.
실제 필터 변환은 시험에서 실행기 주입 인터페이스를 통해 검증한다.
생산용 법률 실행기 자동 연결과 실험 보드 연결은 **후속 연결 필요**다.
시간순 사건 로그 리듀서·검색 경로 격리·검증 조문 강제 주입도 이번 범위 밖이다.
설계의 의미 단위 법률 검증 대신 R18의 어휘·날짜 순서 규칙을 그대로 사용했다.

모든 문항은 compare다. 설정 선택이나 confirm 실행은 하지 않았다.
confirm 일회성 관리 및 독립 검증 문항은 후속 연결 필요다.

## 미검증

Python 시험 통과, 실제 모델 출력, 실제 Chroma 검색, 실제 법률 문서 정확도는 미검증이다.
실제 모델 실행·다운로드·LLM 호출·패키지 설치·네트워크 접근은 하지 않았다.
모델 실행기는 이번 범위에 없으므로 실제 모델 실행 명령은 제공할 수 없다.
위 명령들은 오프라인 경로 시험용이다. 제공 정답의 결과를 모델 품질로 보고하지 않았다.

R21 필수 조문 검사는 부분 문자열 포함 검사다. R18은 법령명·항·호·시행일이나 사건과 날짜의
의미 대응을 확인하지 않는다. 날짜 누락·단일 날짜·알 수 없는 날짜는 시간 오류로 잡지 못한다.
폐지 근거의 상태는 같은 절의 조문에만 적용되고, 폐지 조문을 부정·설명하는 인용도 잡을 수 있다.
이 팩의 날짜 근거는 시간순으로 배열했다. 의미 평가·표현 변형·실제 법률 적합성은 미검증이며
안전 오류 0건이더라도 안전을 보장하지 않는다.

## 커밋 제한

커밋 해시: 없음. 현재 브랜치 `nc/rra-codex`에서 `git add`와 `git commit`을
시도했으나 `.git/index.lock` 생성이 `Permission denied`로 거부되었다.
샌드박스의 `.git` 읽기 전용 제한으로 단일 커밋 및 미커밋 변경 없는 종료 요구를
이행하지 못했다. 결과물을 삭제하거나 권한 제한을 우회하지 않고 지정된 네 파일로 보존한다.
NightCoder가 쓰기 가능한 환경에서 다음 명령으로 단일 커밋을 수집해야 한다.

```powershell
git add -- evals/domains/legal/cases.json evals/domains/legal/metrics.json tests/test_legal_eval_pack.py docs/R22_REPORT_2026-11-11.md
git commit -m "feat: add synthetic legal evaluation pack (R22)"
```

push, 원격 변경, 브랜치 변경은 하지 않았다.
