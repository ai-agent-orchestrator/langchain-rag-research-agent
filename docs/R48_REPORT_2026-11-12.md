# R48 검색 적중률 평가기

## 구현

- `rag/eval_retrieval.py`: ID 목록만 받는 순수 함수 `score_retrieval`과 `aggregate_retrieval`. 기본 hit@1/3/5, recall@1/3/5, 전체 입력 순위의 reciprocal rank 및 집계 MRR을 제공한다. 호출자가 다른 양의 정수 k를 지정할 수 있다.
- 정답 ID는 집합으로 계산한다. 검색 결과의 중복은 순위 자리를 차지하지만 recall 분자를 늘리지 않는다. k보다 결과가 적어도 분모는 정답 ID 수다. 정답이 없거나 빈 목록이면 `None`으로 건너뛴다. 검색 결과가 빈 목록이면 점수는 0이다.
- hit 집계는 문항 단위 성공 수 `ok`, 표본 수 `n`, `rate`, Wilson 95% 구간이다. recall 집계는 문항/정답 ID 쌍을 분모로 하는 micro recall이며 같은 필드를 제공한다. 같은 문항의 정답들은 상관될 수 있으므로 이 구간은 문항 간 변동의 신뢰구간으로 해석하지 않는다. MRR은 이항 비율이 아니므로 문항 수와 평균만 제공한다.
- `scripts/domain_eval.py --retrieval`: 기존 JSON/JSONL 필드를 유지하고 최상위와 해당 문항에 `retrieval`만 추가한다. 옵션을 끄면 기존 출력과 평가 방식이 유지된다. 일반 팩은 문항의 `gold_sources`와 출력의 `retrieved_ids`를 사용한다. 정답이 있는 문항의 검색 순위가 누락되면 오류로 처리하며, injection과 정답 없는 문항은 검색 품질 분모에서 제외한다.
- 리서치 어댑터는 실제 기존 `keyword_search`와 `ResearchRunner`를 사용한다. 옵션을 켠 라벨 문항에 한해 최초 질문의 top-5 검색 ID 순위를 별도로 보존한다. 그래프의 누적 출처 목록을 검색 순위로 간주하지 않는다. 따라서 이 어댑터의 MRR 관측 범위는 최초 top-5다. 독립 점수 함수는 전달받은 전체 순위를 사용한다.
- 리서치 라벨은 `evals/research/gold_sources.json`의 `{문항 ID: [근거 ID, ...]}` 형식으로 읽는다. 파일이 없으면 건너뛴다. 알 수 없는 문항 ID와 해당 문항 문서에 없는 근거 ID는 거절한다. 옵션을 끄면 별도 파일을 읽지 않는다.

## 미검증

실제 모델·임베딩·Chroma 검색, LLM 판정, LangSmith 업로드, 네트워크 통신, confirm 설정 선택은 실행하지 않았다. 실제 모델 평가 명령은 현재 어댑터가 모델/Chroma 실행을 지원하지 않아 제공할 수 없다. 후속 연결 후 대표가 별도로 실행해야 한다. 현재 오프라인 경로 실행 명령은 다음과 같으며 실제 모델 평가 결과로 해석하지 않는다.

```powershell
.\.venv\Scripts\python.exe scripts/domain_eval.py --domain research --retrieval
```

커밋 시도는 샌드박스 권한 때문에 실패했다. 지정 4개 파일의 `git add`와 `git commit` 모두 `Unable to create 'C:/work/rra-codex/.git/index.lock': Permission denied`로 차단됐다. 이 환경은 `.git` 읽기만 허용하며 권한 승격도 금지한다. 따라서 이번 작업의 커밋 해시는 없고 4개 변경을 보존한 미커밋 상태다. NightCoder의 커밋 수집 단계에서 위 파일을 단일 커밋으로 기록해야 한다. 커밋 및 깨끗한 작업 트리 요구는 이 권한 제한 때문에 충족하지 못했다.
