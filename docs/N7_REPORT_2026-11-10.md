# N7 실행 설정 로더

2026-11-10 KST · 작성: Claude (브랜치 `claude/n6-n7-n11`) · NightCoder 명세 `rra-n7-runtime-settings`

## 구현
구조 규칙상 `core/`는 `os`·`json`·`math`를 import할 수 없어 두 파일로 나눴다.
- `core/settings.py`: frozen `RuntimeSettings`와 검증, 계층 병합(`settings_from_layers`), 환경변수 계층(`env_layer`). 순수 모듈.
- `rag/settings_loader.py`: 기본값 < UTF-8 JSON 파일 < `RRA_*` 환경변수 순으로 읽는 `load_settings()`, 기존 생성자용 인자 변환
  `relevance_rule()`, `worker_kwargs()`, `pipeline_kwargs()`. `.env`를 읽지 않고 비밀값 필드가 없다.

## 필드와 기본값의 출처
| 필드 | 기본값 | 출처 |
| --- | --- | --- |
| retrieval_timeout_s, generation_timeout_s | 30.0 | `GuidancePipeline(retrieval_timeout=30.0, generation_timeout=30.0)` |
| k | 3 | `GuidancePipeline(k=3)` |
| worker_slots, queue_limit, admission_timeout_s | 1, 4, 1.0 | `BoundedWorker(concurrent=1, waiters=4, admission_timeout=1.0)` |
| tau_abs, tau_gap | **없음(필수)** | `RelevanceRule` docstring: 공용 기본값 없음, compare split 보정값만 |
| rule_version, index_version | **없음(필수)** | `GuidancePipeline`이 명시 버전을 요구 |
| retrieval_mode | **없음(필수)** | `RelevanceRule.mode` (lex / vector) |

명세의 `request_timeout_s` 하나 대신, 실제 코드에 맞춰 검색·생성 timeout을 따로 두고 `k`와 `admission_timeout_s`를 더했다.
tau가 빠지거나 범위를 벗어나면 오류 메시지에 "모델·검색 모드·인덱스 버전별 보정값이어야 한다"는 안내가 붙는다.

## 시험
`tests/test_runtime_settings.py` 22개: 기본값이 기존 코드와 같음, 우선순위, 환경변수 형 변환, 알 수 없는 키 거절(파일·환경변수),
tau 누락 시 보정 안내, 필드별 범위 오류 9종, 잘못된 형 4종(불리언을 숫자로 받지 않음), 파일 오류, frozen,
실제 `RelevanceRule`·`BoundedWorker` 생성자에 넘겨지는지, 한글 값 왕복.

## 연결(하지 않음, 제안)
서비스 시작 시 `load_settings()` → `GuidancePipeline(library, relevance_rule(s), worker=BoundedWorker(**worker_kwargs(s)), model=..., enabled=..., **pipeline_kwargs(s))`.
