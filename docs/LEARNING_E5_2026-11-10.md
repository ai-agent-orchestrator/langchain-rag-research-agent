# E5 청크 크기 실험

compare_embedders.py와 eval_retrieval_v2.py에 `--chunk-size` (토큰), `--overlap` (토큰)을 추가했다. 지정하지 않으면 기존 문단 청커를 유지한다. 지정하면 원문 부분문자열을 그대로 보존하는 token-window-v1을 사용한다. 각 실행은 고유 서재 경로를 사용하며 기존 서재를 재사용하지 않는다. 겹침은 실제 count_tokens로 계산한다.

v2는 모든 relevant quote 중 하나라도 어떤 청크에도 온전히 포함되지 않은 문항 ID/수를 보고한다. quote 자체가 청크 예산보다 긴 경우도 포함한다. v1은 quote가 없으므로 0이며 quote 검증이 가능하다는 뜻은 아니다. 토큰 한도 초과 청크 ID/수를 인코딩 전에 보고하고, 초과가 있으면 평가하지 않는다. fake의 512 한도는 경로 시험을 위한 모의 한도다. R-20의 모델 실제 tokenizer와 인코딩 검사는 유지한다.

실제 모델은 실행하지 않았다. 대표 명령(같은 골든셋):

```powershell
foreach ($size in @(128,256,512)) {
  foreach ($overlap in @(0,32)) {
    .\.venv\Scripts\python.exe scripts/eval_retrieval_v2.py --set data/golden_retrieval/terms_v2.json --embedder e5 --split compare --chunk-size $size --overlap $overlap --out ".runs/e5/e5-$size-$overlap"
    .\.venv\Scripts\python.exe scripts/compare_embedders.py --models e5 bge-m3 --chunk-size $size --overlap $overlap --out ".runs/e5/compare-$size-$overlap"
  }
}
```

결과는 .runs에만 저장한다. fake 경로 시험과 실제 모델 열은 E4 형식을 유지한다.

전체 시험: `239 passed, 5 skipped` (26.99s). 추가 fake CLI 연결 실행은 `RetrievalUnavailable: chromadb is not installed: pip install -e .[chroma]`로 서재 생성 전에 중단됐다. 설치하거나 기존 시험을 바꾸지 않았다. 로그: `.runs/e5-smoke.txt`. 따라서 Chroma를 포함한 새 옵션의 실제 서재 통합 동작은 이번 환경에서 검증하지 못했다. 새 시험은 원문 quote 경계 손실, overlap으로 복원, 한도 초과 집계를 검증한다. 실제 모델 결과는 없다.
