# R41 — 포인터 파일 방식 Chroma 버전 관리

## 구현

`store/chroma_pointer.py`에 명시적으로 생성해 사용하는 `ChromaPointer`를 추가했다.
기존 store 공개 인터페이스·설정·기본 동작은 변경하지 않는다.
실제 Chroma 클라이언트와 `ChromaIndex`를 사용하고 memvid는 import하지 않는다.

- `publish`: `versions/v<N>/`를 새로 예약하고 Chroma를 생성·검증한다.
  마스킹 완료 Chunk 메타데이터를 manifest에 기록하고 닫은 뒤 포인터를 교체한다.
  실패한 빌드 폴더는 보존하며 기존 활성 포인터를 유지한다.
- `current.json`: 같은 디렉터리의 고유 임시 파일에 version/previous를 기록하고
  flush·fsync 후 `os.replace`한다. Windows의 짧은 파일 공유 잠금은 최대
  20회 교체 시도(간격 0.01초)로 처리한다. 최종 실패 시 기존 포인터가 남는다.
- `open_active`: 한 번 읽은 포인터로 실제 ChromaIndex를 열고 검증한다.
  반환된 핸들은 호출자가 닫으며, 이후 포인터 교체로 바뀌지 않는다.
- `activate`·`rollback`: 대상 manifest·컬렉션을 검증한 후 포인터만 교체한다.
  같은 버전 재활성화는 previous를 바꾸지 않는다.
- `prune`: 별도 명시적 관리 호출이다. 활성·직전 버전을 남기고 오래된 폴더만
  삭제한다. PermissionError는 원문 예외 없이 `CHROMA_PRUNE_LOCKED` 경고와
  kept_locked 목록으로 남기고 다음 폴더를 계속 처리한다.
- `.writer.lock`의 배타 생성으로 프로세스·인스턴스 간 쓰기를 차단한다.
  동시 쓰기는 `CHROMA_WRITER_BUSY`로 즉시 실패한다.
  `.allocated/v<N>`의 영구 빈 예약 파일로 prune 이후에도 버전 ID를 재사용하지 않는다.

정상 발행·활성화·롤백은 버전 폴더를 삭제하거나 옮기지 않는다.
독자와 발행자는 함께 실행할 수 있다. prune은 retired 버전 독자가 모두 끝난 뒤
실행하는 관리 작업이다. 독자 lease나 사용 중 버전의 자동 정리는 구현하지 않았다.
비정상 종료 후 잠금 파일은 자동 해제하지 않으며 관리자가 상태를 확인해야 한다.

## 시험

신규 시험은 매개변수 확장을 포함해 17개 사례다. 작은 고정 벡터를 주입해 실제
Chroma 클래스·저장 파일·검색 경로를 검증한다. fake 저장소나 모델은 사용하지 않는다.
모델 품질 평가가 아닌 **경로 시험**이다. 새 버전 생성·재열기·기존 독자 유지,
원자 교체 직전 완성 상태, 교체 실패 시 원본 유지·임시 파일 정리,
롤백·누락/불완전/변조 대상 거부, 삭제 잠금 경고와 다음 정리 진행,
동시 읽기·포인터 전환, 쓰기 배제, 잘못된 버전 경로, 정리 후 ID 재사용 방지를 다룬다.
monkeypatch는 교체·삭제 오류 주입과 폴더 이동 금지 검증에 사용한다.

전체 시험 명령(NightCoder의 memvid 표식 제외 정책):

```powershell
python -m pytest -q -m "not memvid" -p no:cacheprovider --basetemp=.runs/r41/pytest-temp
```

**이 환경에서 시험 미실행: 사용 가능한 Python 3.15 실행기에 pytest가 없음.**
tests not run here: No module named pytest in the available Python interpreter.
passed/failed/error/skipped는 모두 미집계다. 수집·실행이 시작되지 않았으며
실행 판정은 NightCoder 게이트가 수행해야 한다. `.runs/r41/fix-full-tests.txt`에 이유를 기록했다.
기존 가상환경 실행기는 설치되지 않은 Python312 경로를 참조해 시작할 수 없었다.
수정 전 전달받은 게이트 결과는 **1145 passed / 2 failed / 0 error / 1 skipped /
10 deselected / 220 subtests passed**다. 실패별 traceback은 제공되지 않았다.
기존 시험·기대값·skip은 변경하지 않았다. `git diff --check`도 수행했다.
수정한 Python 두 파일의 AST 구문 분석은 통과했다. 이 검사는 시험 실행을 대신하지 않는다.

## 게이트 재시도 수정

코드 검토에서 기존 `publish_chroma`가 쓰기 클라이언트와 반환 인덱스 클라이언트를
각각 열지만 호출자가 닫을 수 있는 것은 반환 인덱스뿐임을 확인했다.
쓰기 클라이언트의 소유권이 남으면 Windows에서 retired HNSW 파일 삭제가 막힐 수 있다.
두 prune 시험 실패와의 관련성은 추론이며, 실패 로그와 재실행이 없어 **미검증**이다.

허용 범위 밖인 기존 Chroma 어댑터를 수정하지 않고 `_write_version`에서 실제
클라이언트를 직접 소유하고 `finally: client.close()`로 성공·실패 모두 해제한다.
새 폴더에서만 컬렉션을 만들므로 기존 컬렉션 삭제는 하지 않는다.
입력 검증·고정 벡터·64개 배치·쓰기 재시도는 기존 방식과 동일하게 유지한다.
쓰기 클라이언트를 닫고 manifest를 저장한 다음 실제 `ChromaIndex`로 재열기·검증하고
닫은 후 포인터를 교체한다. `_open`의 Chunk 재구성은 클라이언트 생성 전에 일어나므로
변조 Chunk 검증 실패 자체가 클라이언트 누수를 만드는 것은 아니다.

추가 회귀 시험 2개는 실제 클라이언트를 열고 실제 close 호출까지 추적한다.
정상 쓰기와 Collection.add 오류 주입 모두 쓰기 클라이언트가 닫히는지 확인하고,
실패 시 기존 포인터·실패 버전 예약 보존 및 쓰기 잠금 해제를 확인한다.
저장소·Chroma 클라이언트를 가짜 구현으로 대체하지 않는다.

## 설계 대비 차이

METRICS_BOARD.ko.md를 먼저 읽고 RESEARCH_GRAPH_DESIGN.ko.md,
DOMAIN_FILTERS.ko.md, LANGGRAPH_GUARDRAIL.ko.md를 확인했다.
이 모듈은 저장소 경계 안에서 core 계약과 같은 store 모듈만 사용하며 MATURITY는
incubating이다. KNOWN_DEBT 추가나 LangChain/LangGraph 의존성은 없다.
계측 보드 이벤트는 생성하지 않는다. version/previous는 디스크 포인터 형식이며
run/node 이벤트 필드의 대체 이름이 아니다. 보드 이벤트 연결은 **후속 연결 필요**다.
prune 호출용 CLI와 기존 서비스에 대한 선택 설정 노출도 허용 파일 범위 밖이므로
**후속 연결 필요**다. 현재는 별도 Python 관리 메서드로 호출한다.
이 작업의 명시적 요청에 따라 Chroma 버전 발행·롤백을 구현했다.
manifest는 Chunk 재구성용이며 HNSW 전체 파일 해시 manifest 기능은 **Chroma 경로에 없음**이다.

## 미검증 및 보호 확인

신규 시험 실행 통과, 실제 Windows HNSW 공유 잠금 상황, 강제 전원 차단 내구성,
다중 프로세스 부하, 장기 운영 성능은 **미검증**이다.
폴더 불변은 이 관리 API의 계약이며 반환된 ChromaIndex의 내부 객체를 직접 수정하는
외부 코드를 막는 파일 시스템 읽기 전용 보장은 아니다.
실제 모델 실행이 필요한 기능이 아니므로 모델 실행 명령은 없다.
네트워크·모델 다운로드·LLM 호출·패키지 설치는 수행하지 않았다.

보호 파일은 `.runs/n10/protected-after.json`의 Expected를 기준으로 작업 전후
**18/18 SHA-256 동일**이다. 증거는 `.runs/r41/protected-before.json`과
`.runs/r41/fix-protected-after.json`이다. 기준 manifest의 정당성은 미검증이다.
초기 작업 트리는 깨끗했다. 금지 파일·README·기존 시험은 변경하지 않았다.
개인정보 모양의 시험 값은 추가하지 않았다.
