# R41 — 포인터 파일 방식 Chroma 버전 관리

## 구현

2026-11-12 NightCoder 작업. 기존 선택형 ChromaPointer 구현을 유지하고 인덱스 생성 실패 시 클라이언트 정리를 보완했다. 기존 공개 인터페이스와 기본값은 바꾸지 않았다.

- publish: 새 versions/v<N>/에 실제 Chroma 컬렉션과 Chunk manifest를 생성하고 검증한 후 활성화한다. 실패 폴더를 보존하고 예약 파일로 버전 ID 재사용을 막는다.
- current.json: 같은 디렉터리의 임시 파일을 flush·fsync한 뒤 os.replace한다. PermissionError는 최대 20회 시도하며 실패하면 원본 포인터를 유지한다.
- activate·rollback: 대상을 검증하고 포인터만 교체한다. 버전 폴더를 이동하거나 삭제하지 않는다. 기존 독자는 처음 연 버전을 계속 사용한다.
- prune: 별도 명시적 관리 메서드다. 활성·직전 버전을 보존하고 삭제 중 PermissionError는 CHROMA_PRUNE_LOCKED 경고만 남기고 다음 폴더를 처리한다.
- .writer.lock은 쓰기를 배제하고 프로세스 공용 RLock은 R41 클라이언트의 생성·종료를 직렬화한다.
- 이번 수정: _PointerIndex의 상위 생성자가 클라이언트를 얻은 뒤 컬렉션 열기에 실패하면 같은 잠금 안에서 close한다. 정리 자체가 실패해도 원래 생성 오류를 유지하며 원문 없이 CHROMA_OPEN_CLEANUP_FAILED 경고를 남긴다.

## 시험

기존 시험 본문·기대값·skip을 유지하고 실제 Chroma 클라이언트를 사용하는 회귀 시험 2개를 추가했다. 컬렉션 열기 실패 시 실제 close 호출, 정리 오류 발생 시 원래 오류 유지, 포인터 보존, 이후 재열기·벡터 검색을 확인하도록 작성했다. fake 저장소·클라이언트·모델을 추가하지 않았다.

R41 시험 정의는 매개변수 확장 포함 **21개 사례**다. 기존 새 버전 생성·원자적 포인터 교체·롤백·잠긴 폴더 정리·동시 읽기 시험을 포함한다. 고정 벡터를 주입한 **경로 시험**이며 실제 모델 품질 평가는 아니다.

## 설계 대비 차이

AGENTS.md와 METRICS_BOARD.ko.md를 먼저 읽고 RESEARCH_GRAPH_DESIGN.ko.md, DOMAIN_FILTERS.ko.md, LANGGRAPH_GUARDRAIL.ko.md 및 test_structure 규칙을 확인했다. MATURITY는 incubating이며 core 계약과 같은 store 모듈만 사용한다. KNOWN_DEBT·memvid import·LangChain/LangGraph 의존성을 추가하지 않았다.

계측 이벤트는 생성하지 않는다. version/previous는 디스크 포인터 필드이고 경고는 고정 코드다. 보드 이벤트·CLI·서비스 설정 연결은 **후속 연결 필요**다. 명시적 요청에 따라 Chroma 버전 발행·롤백을 제공한다. HNSW 전체 파일 해시 manifest 기능은 **Chroma 경로에 없음**이다.

## 미검증 및 보호 확인

추가 시험의 실행 통과, 실제 Windows HNSW 잠금, 전원 차단 내구성, 다중 프로세스 부하·장기 성능은 **미검증**이다. prune은 retired 버전 독자가 모두 끝난 뒤 호출해야 한다. 독자 lease·자동 정리·충돌 후 잠금 자동 회수는 없다. 폴더 불변은 관리 API 계약이며 외부 직접 수정을 막지는 않는다. 모델이 필요하지 않아 실제 모델 실행 명령은 없다.

.runs/n10/protected-after.json의 Expected 기준 **18/18 SHA-256 동일**을 확인했다. 결과: .runs/r41/current-protected-after.json. 기준 manifest의 정당성은 미검증이다. 초기 작업 트리는 깨끗했으며 변경 파일은 허용된 모듈·시험·이 보고서뿐이다. 금지 파일·README를 수정하지 않았다. 네트워크·모델 다운로드·LLM 호출·패키지 설치·push·원격/브랜치 설정 변경을 하지 않았다.
