# R41 — 포인터 파일 방식 Chroma 버전 관리

## 구현

`store/chroma_pointer.py`의 선택형 `ChromaPointer`는 실제 Chroma 클라이언트와
`ChromaIndex`를 사용한다. 기존 store 공개 인터페이스·설정·기본 동작은 유지한다.

- `publish`: 새 `versions/v<N>/`에서 컬렉션·Chunk manifest를 생성하고 검증한다.
  쓰기 클라이언트는 성공·실패 모두 finally에서 닫는다. 실패 폴더는 보존한다.
- `current.json`: 같은 디렉터리의 고유 임시 파일에 version/previous를 기록하고
  flush·fsync 후 `os.replace`한다. PermissionError는 최대 20회 시도한다.
  교체 실패 시 원본 포인터를 유지하고 임시 파일을 정리한다.
- `open_active`: 포인터 한 번의 스냅샷으로 검증된 인덱스를 반환한다.
  호출자가 close하며 포인터 전환 후에도 원래 버전을 사용한다.
- `activate`·`rollback`: 대상을 검증한 뒤 포인터만 교체한다.
- `prune`: 별도 명시적 관리 작업이다. 활성·직전 버전을 보존한다.
  PermissionError는 원문 없이 `CHROMA_PRUNE_LOCKED` 경고와 kept_locked로 기록하고
  다음 폴더를 계속 처리한다. 정상 발행·롤백에서 버전 폴더를 삭제·이동하지 않는다.
- `.writer.lock`은 프로세스 간 쓰기 배제를 담당한다. `.allocated/v<N>`의
  영구 예약 파일은 정리 이후에도 버전 ID 재사용을 막는다.

## 이번 게이트 재시도 수정

기존 커밋 `4d444ba`, `b57ad2a`를 보존했다. 전달받은 최신 게이트 결과는
**1148 passed / 1 failed / 0 error / 1 skipped / 10 deselected /
220 subtests passed**다. 실패 시험 이름·traceback이 없어 실패 원인은 미확정이다.

로컬에 캐시된 Chroma 1.5.9의 `SharedSystemClient.__init__`,
`_create_system_if_not_exists`, `_release_system`을 검토했다. refcount 증감 잠금은
있지만 공유 시스템 생성·시작 및 마지막 소유자의 시스템 제거·종료까지 함께
보호하지 않는다. 동시 독자의 생성끼리, 마지막 close와 새로운 생성이 겹칠 수 있다.
이 경쟁이 위 게이트 실패의 원인인지는 **미검증**이다.

R41 모듈에 프로세스 공용 RLock을 추가했다. 반환 인덱스는 실제 ChromaIndex를
상속한 내부 `_PointerIndex`로, 생성과 close를 같은 잠금으로 보호한다.
발행용 실제 클라이언트의 생성·close도 같은 잠금을 사용한다.
인스턴스가 달라도 적용되며 검색·포인터 읽기 자체는 이 잠금을 잡지 않는다.
SDK 내부 캐시·refcount를 직접 수정하거나 강제 종료하지 않는다.
이 잠금은 R41을 통해 생성한 클라이언트에만 적용된다.

## 시험

기존 시험의 기대값·skip·본문은 유지했다. 실제 클라이언트 생성 또는 close를
Event로 잠시 멈춘 상태에서 다른 ChromaPointer 인스턴스가 생성에 진입하지 못하는지
확인하는 회귀 시험 2개를 추가했다. 대기 해제 후 실제 클라이언트 생성·close 및
벡터 검색을 수행한다. fake 저장소·클라이언트·모델을 만들지 않았다.
기존 시험 17개와 추가 2개로 R41 시험은 매개변수 확장 포함 **19개 사례**다.
작은 고정 벡터를 주입한 **경로 시험**이며 모델 품질 평가는 아니다.

전체 시험 시도 명령(NightCoder의 memvid 표식 제외 정책):

```powershell
& C:/Users/Codelab/AppData/Roaming/uv/python/cpython-3.15.2-windows-x86_64-none/python.exe -m pytest -q -m "not memvid" -p no:cacheprovider --basetemp=.runs/r41/retry-tests
```

**이 환경에서 시험 미실행: 사용 가능한 Python 실행기에 pytest가 없음.**
tests not run here: No module named pytest in the available Python interpreter.
수집·실행이 시작되지 않아 이번 수정 후 passed/failed/error/skipped는 미집계다.
출력은 `.runs/r41/retry-full-tests.txt`에 기록했다. 패키지 설치는 하지 않았다.
수정한 Python 두 파일의 AST 구문 분석과 `git diff --check`는 통과했다.
이 검사는 실제 시험을 대신하지 않으며 시험 판정은 NightCoder 게이트가 해야 한다.

METRICS_BOARD.ko.md를 먼저 읽고 RESEARCH_GRAPH_DESIGN.ko.md,
DOMAIN_FILTERS.ko.md, LANGGRAPH_GUARDRAIL.ko.md와 test_structure 규칙을 확인했다.

계측 이벤트는 생성하지 않는다. version/previous는 디스크 포인터 형식이다.
보드 이벤트·CLI·기존 서비스 선택 설정 연결은 **후속 연결 필요**다.
명시적 요청에 따라 Chroma 버전 발행·롤백을 구현했다. HNSW 전체 파일 해시
manifest 기능은 **Chroma 경로에 없음**이다.

## 미검증 및 보호 확인

수정 후 시험 통과, 실제 Windows HNSW 공유 잠금 상황, 전원 차단 내구성,
다중 프로세스 부하·장기 성능은 **미검증**이다. prune은 retired 버전 독자가 모두
끝난 뒤 호출해야 한다. 독자 lease·자동 정리·충돌 후 잠금 자동 회수는 없다.
폴더 불변은 관리 API 계약이며 외부 직접 수정을 파일 시스템에서 막지는 않는다.
실제 모델이 필요하지 않아 모델 실행 명령은 없다.
네트워크·모델 다운로드·LLM 호출·패키지 설치·push·원격/브랜치 설정 변경은 하지 않았다.

`.runs/n10/protected-after.json`의 Expected 기준으로 보호 파일은
**18/18 SHA-256 동일**이다. 이번 확인 결과는
`.runs/r41/retry-protected-after.json`이다. 기준 manifest의 정당성은 미검증이다.
초기 작업 트리는 깨끗했다. 변경은 허용된 모듈·시험 파일·이 보고서뿐이다.
금지 파일·README·개인정보 모양 시험 값을 추가하거나 수정하지 않았다.
