# R25: 루프 정책 옵션

## 구현

`ResearchConfig`에 다음 선택 옵션을 추가했다. 기본 설정의 기존 규칙·경로·비용 기록을 유지한다.

| 옵션 | 기본값 | 동작 |
| --- | --- | --- |
| `rewrite_codes` | `None` | 기존처럼 모든 비-GAP 코드로 재작성한다. `frozenset`을 지정하면 해당 코드만 재작성의 계기가 되고, 빈 집합이면 재작성하지 않는다. 피드백은 전체 검수 코드를 유지한다. GAP 코드는 이 집합으로 재작성에 우회시키지 않는다. |
| `gap_first` | `True` | 검수에서 재검색과 재작성 둘 다 가능하면 재검색을 우선한다. `False`면 재작성을 우선하며, 우선 경로의 반복 한도·선택 코드 조건이 맞지 않으면 다른 경로로 간다. |
| `per_node_token_cap` | `None` | 양의 정수를 지정하면 각 노드의 **한 번 실행**에서 기록한 입력·출력 추정 토큰의 합이 상한 이상일 때 다음 노드를 실행하지 않는다. 전 노드에 같은 상한을 적용한다. 비용은 잘라내지 않고 실제 추정치를 남긴다. |
| `stop_if_no_progress` | `False` | 직전 검수와 이번 검수에 공통인 코드가 하나라도 있으면 두 번째 검수 직후 중단한다. 코드 순서나 전체 집합의 일치 여부와 무관하며 GAP도 포함한다. 통과는 중단으로 취급하지 않는다. |

중단 사유는 `PER_NODE_TOKEN_CAP` 또는 `NO_PROGRESS`로 State와 코드 로그에 남기고,
`ResearchRunner` 결과 보고서에도 중단 안내를 붙인다. 체크포인트 복원에서도 같은 정책을 적용한다.
새 import·패키지·memvid 의존성이나 모듈 간 의존성은 추가하지 않았다. MATURITY와 KNOWN_DEBT는 유지한다.

## 시험

신규 `tests/test_research_loop_policy.py`는 실제 `ResearchRunner`, 컴파일한 `StateGraph`,
규칙 검색·추출·작성 및 실제 `InMemorySaver`를 사용한다. 검수 분기는 기존 주입 인터페이스로
코드만 순서대로 반환하며 fake 그래프·저장소·클래스를 만들지 않는다. 모두 오프라인 경로 시험이다.

- 기본값의 단일 경로·인용 보고서·노드별 비용을 고정 기대값과 비교하고 명시적 기본값과 전체 결과를 비교한다.
- 기존 비-GAP 코드와 사용자 코드의 기본 재작성 한도, 선택 집합·빈 집합에 따른 루프 수와 비용 감소를 확인한다.
- GAP/서술 문제 동시 발생의 경로 우선순위, 대체 경로, 재검색·재작성 횟수와 비용 차이를 확인한다.
- 노드 상한의 경계값, plan/extract/write 중단, 입력·출력 합산, 비용 보존, 충분한 상한의 결과 동일성,
  잘못된 상한 거부를 확인한다. 순차/병렬 설정과 체크포인트 설정을 포함한다.
- 같은 코드의 두 번째 검수에서 중단, 일부 코드만 재등장, 코드 변경·통과 시 계속,
  GAP 반복 중단, 비용 감소와 Runner의 중단 안내를 확인한다.

검수 GAP 경로는 정상 실행에서 앞선 coverage가 재검색 한도를 소진하면 사용할 수 없다.
두 검수 경로가 동시에 가능한 상태의 시험은 실제 그래프로 체크포인트를 생성한 뒤,
공개 `update_state(..., as_node="write")`로 한 지표의 재검색 여유를 다시 열고 재개한다.
기존 coverage 정책은 변경하지 않았다. 이 시험은 일반 실행에서 두 경로가 반드시 활성화된다는 주장이 아니다.

시도한 전체 시험 명령:

```powershell
python -m pytest -q -m "not memvid"
```

**tests not run here: Python is not available in this sandbox.**
이 환경에서 시험 미실행: `python`·`py`를 찾을 수 없고,
`uv --cache-dir .venv-cache python find --no-managed-python --no-python-downloads`도
Python 실행기가 없음을 확인했다. 설치·다운로드는 하지 않았다.
전체 시험 실행 **0건**, passed/failed/error/skipped 집계 **불가(미실행)**이다.
시험 결과는 `.runs/r25/full-pytest.log`, 실행기 탐색 결과는 `.runs/r25/python-find.log`에 기록했다.
추가한 시험의 실행 통과와 전체 회귀 판정은 NightCoder 게이트에서 확인해야 한다.
기존 시험·기대값·skip 및 memvid 시험은 변경하거나 재시험하지 않았다.

## 설계 대비 차이

정본 `RESEARCH_GRAPH_DESIGN.ko.md` 4·10절, `DOMAIN_FILTERS.ko.md`,
`LANGGRAPH_GUARDRAIL.ko.md`를 확인했다. 그래프 조립 경계 안에서 정책을 선택하며
기존 도메인 계약과 기본 저장소 Chroma 방침을 유지한다.

노드 상한은 기존 비용 계측과 같은 글자수 기반 **실행 후 추정 예산**이다.
노드 호출 자체를 취소하거나 모델의 `max_tokens`를 제한하지 않으므로 해당 호출의 추정치가
상한을 넘을 수 있다. 입력과 출력 합계를 검사하며 초과 비용을 숨기지 않는다.
노드마다 서로 다른 상한을 지정하는 매핑이나 노드별 누적 예산은 이번 옵션에 포함하지 않는다.
총예산 `max_shadow_tokens`와 지표별·재작성 반복 한도는 기존 판정을 유지한다.
실험 보드·그리드에서 새 설정을 선택하거나 직렬화하는 연결은 허용 파일 범위 밖이므로 **후속 연결 필요**다.

## 최종 확인 및 커밋 제약

작업 후 보호 파일도 **18/18 SHA-256 동일**이다. 근거는
`.runs/r25/protected-after.json`이다. `git diff --check` 및 지정 세 파일의
후행 공백 점검을 통과했다. Python 구문 검사와 시험 실행 통과를 뜻하지 않는다.

다음 커밋 명령을 시도했으나 둘 다 `.git/index.lock: Permission denied`로 실패했다.

```powershell
git add -- src/rag_research_agent/rag/research_graph.py tests/test_research_loop_policy.py docs/R25_REPORT_2026-11-11.md
git commit -m "feat: add optional research loop cost policies"
```

환경 권한은 `.git` 읽기만 허용하고 권한 상승을 금지한다. 커밋 해시는 없으며,
지정된 세 파일이 미커밋 상태로 남는다. 작업을 삭제하지 않았다.
NightCoder에서 이 세 파일의 커밋 수집과 전체 시험 실행이 필요하다.
