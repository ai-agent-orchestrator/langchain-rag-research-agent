# N17 보고서 — 인코딩·경로 이식성 점검

2026-11-10 KST. AGENTS.md를 먼저 읽고 NightCoder 규칙을 적용했다. 현재 저장소·브랜치 `nc/rra-codex`에서만 작업했다.

## 구현 / 문서

`docs/ENCODING_PATH_AUDIT_2026-11-10.md`에 파일:행별 인코딩 판정, Windows 절대 경로·역슬래시 분류, 경로 기준점, 교체·삭제·임시 DB 정리 위험과 권장 조치, 상위 10개 표를 작성했다. 변경 대상은 지정 문서 두 개뿐이다. 소스·기존 시험·기대값·skip·KNOWN_DEBT는 변경하지 않았다. 새 모듈·의존성·가짜 구현은 없다.

점검 범위는 `src/`, `scripts/`의 Python 파일 112개다. `rg`로 파일 목록과 입출력/경로 후보를 추출하고 여러 줄 호출 및 관련 소스 문맥을 읽었다. encoding 미지정 텍스트 파일 입출력은 발견하지 못했다. 미지정처럼 보이는 바이너리 open, HTTP open, Library.open을 구분해 목록화했다. `json.dump`는 0개이고 `json.dumps`의 문자열 출력은 외부 파일 쓰기 인코딩으로 판정했다. models.json 읽기·쓰기는 UTF-8을 명시한다. 이번 PowerShell에서 AGENTS.md의 기본 읽기와 UTF-8 명시 읽기의 표시 차이를 관찰했으나 models.json 손상 여부를 입증한 것은 아니다.

개발 기본값은 Chroma로 유지했다. 기존 memvid 코드는 감사 목록을 위한 읽기만 했으며 실행·수정하지 않았다. 금지된 소스 두 파일, data·profiles·frozen masking·README를 수정하지 않았다. data/profiles는 내용 열람 없이 보호 해시 계산만 했다. 외부 저장소·네트워크·모델 다운로드·실제 모델·LLM·LangSmith·패키지 설치·push·원격/브랜치 설정 변경은 없었다. 권장 수정은 전부 **후속 연결 필요**이며 적용하지 않았다.

## 시험 / 확인

전체 시험 시작 명령:

```powershell
python -m pytest -q -p no:cacheprovider --basetemp=.runs/n17/full-tmp --junitxml=.runs/n17/full-pytest.xml
```

**tests not run here: Python is not available on PATH.**

이 환경에서 시험 미실행: `python` 명령을 찾지 못해 CommandNotFoundException으로 시작하지 못했다. `Get-Command python,py,pytest`도 실행 명령을 찾지 못했다. 실행 0건이며 passed/failed/error/skipped는 집계 불가(미실행)다. JUnit은 생성되지 않았다. 최종 시험 판정은 NightCoder 게이트가 해야 한다.

보호 기준 `.runs/n10/protected-after.json`의 Expected SHA-256과 작업 전 해시가 **18/18 동일**하다. 증거는 `.runs/n17/protected-before.json`이다. 작업 후 대조와 Git 공백 검사는 아래 마무리 항목에 기록한다. 감사 검색 결과 등 실행 산출물은 `.runs/n17/`에만 썼다. 초기 git status는 깨끗했다.

## 입증하지 못한 것 / 미검증

- Python 부재로 전체 시험 실행 및 동적/AST 분석은 미검증이다. 검색과 소스 문맥 판독의 범위를 넘는 동적 호출·서드파티 SDK 내부 입출력은 미검증이다.
- 다른 PC·WSL/Linux에서 한글 경로·설치 형태·대소문자·긴 경로·실제 DB 핸들 잠금·동시 writer·디스크 오류를 재현하지 않았다. 위험 목록은 정적 추론이며 발생률을 측정하지 않았다.
- 배경의 models.json 원본 바이트 및 PowerShell 버전별 리다이렉션은 미검증이다. 인코딩 누락 미발견은 이식성 보장이 아니다.
- data/profiles 내부의 저장된 경로, 외부 기준 manifest의 생성 정당성은 미검증이다. 기존 18개 기준에 대한 현재 파일의 해시 일치만 확인한다.

## 마무리 / 커밋 차단

작업 후에도 보호 파일은 기준·작업 전·후 **18/18 SHA-256 동일**하다. 후속 증거는 `.runs/n17/protected-after.json`이다. `git diff --check`는 통과했고 신규 문서의 줄 끝 공백도 별도로 확인했다. 최종 변경 대상은 지정 문서 두 개이며 기존 추적 파일 변경은 없다.
