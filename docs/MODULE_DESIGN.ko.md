# 모듈 설계안 — 검증된 RAG·보안 부품을 재사용 가능한 백엔드 모듈로

2026-11-06 · **제안(초안). 대표 확정 전. 이 문서의 코드 구조는 아직 존재하지 않습니다.**

이 저장소(③)를 "①에서 검증한 부품을 옮겨 두는 곳"에서 한 단계 넓혀, **법률 검색과 리서치가 그대로 가져다 쓰는 Python 백엔드 모듈**로 만든다. 동시에 LangChain·LangGraph·LangSmith·임베딩·유사도 검색·보안 실험을 마음껏 할 수 있도록 **안정판(stable)과 실험판(lab)을 한 저장소 안에서 분리**한다.

## 1. 원칙

1. **세 단계로 나눈다.** `stable`은 ①(또는 ③ 평가)에서 실모델·증거가 남은 것, `incubating`은 ①에서 옮겨 왔지만 ① 증거를 기다리는 것, `lab`은 ③에서만 하는 실험이다. 각 모듈은 자기 단계를 `MATURITY` 상수로 밝힌다.
2. **실험은 마음껏, 대신 격리.** 하이브리드 검색, 의미 기반 주입 탐지, 질의 재작성, 리랭킹, LangSmith 실험은 `memvid_guardrail.lab`에서 한다. stable·incubating 코드는 lab을 import하지 않으며, 시험이 이를 확인한다.
3. **프레임워크는 선택 사항.** 핵심 계약(core)은 표준 라이브러리만 쓴다. memvid·E5·LangChain·LangGraph·LangSmith·NeMo·FastAPI는 extras로 설치한다.
4. **유사도는 후보를 찾고, 확정은 게이트가 한다.** 검색·필터·라우팅은 후보를 내고, 정책·시험·사람이 결정한다.
5. **데이터는 PC 밖으로 나가지 않는 것이 기본값.** 텔레메트리 OFF, 외부 임베딩 OFF, 원격 tracing OFF가 기본이며, 켤 때는 코드에서 명시한다.
6. **복사하지 않는다.** 검증된 부품은 ③으로 옮긴 뒤 ①과 리서치가 ③을 의존성으로 쓴다. 같은 코드를 두 곳에서 고치지 않는다.

## 2. 패키지 구조 (제안)

```text
src/memvid_guardrail/
  core/        # 계약: Chunk, Evidence, RetrievalResult, Decision, 오류 코드  (의존성 없음)
  guard/       # 입력·출력 정책, 마스킹, 요청 문맥 바인딩, 세션 위험, 실행 슬롯·예산
  embed/       # E5·Ollama·가짜 임베더, 문서/질의 규약, revision 고정 확인
  store/       # memvid 어댑터(묶음 적재·전수 검증·포인터 전환·텔레메트리 OFF), NumPy 평면 저장소
  retrieve/    # 키워드·벡터 검색, 관련성 게이트, 중복 병합, 다양성(MMR), 새로움 확인
  rag/         # LangChain 체인, LangGraph 그래프, 구조화 응답·출처 검증·서버 조립
  observe/     # tracing 차단·허용 목록, 평가 하네스(Hit@k, 혼동표, 지연)
  adapters/    # FastAPI 라우터 팩토리, CLI (선택)
  lab/         # 실험: hybrid(RRF), semantic_guard, query_rewrite, rerank, langsmith_experiments ...
tests/         # stable 시험 + lab 시험(별도 마커)
docs/evidence/ # 단계별 증거(합성 자료만)
```

설치 예: `pip install memvid-guardrail[memvid,e5]`, `[langchain]`, `[langsmith]`, `[nemo]`, `[fastapi]`.

## 5-1. 핵심 기능 A — 긴 프롬프트 브리프 (보안 + 요약 + 검색 키워드 강화)

**목표.** DB에 저장된 40쪽 이상의 긴 프롬프트(작업 지시·결정 기록·회의록)를 다음 작업에 맞는 짧은 브리프로 줄인다. 요약 품질을 올리는 수단은 요약 모델을 바꾸는 것보다 **요약에 들어갈 재료를 잘 고르는 것**이다. 같은 부품을 리서치 멀티 에이전트 오케스트레이터와 Legal Intake가 함께 쓴다.

```text
긴 프롬프트 → 구간 분할 → 보안 처리(개인정보 마스킹, 주입 문장 제외·보고, 폐기 표시 구간 강등)
 → 핵심어 강화: 한국어 조사 제거 → BM25 + 문서 핵심어(TF-IDF) → 질의 확장(상위 구간의 핵심어 추가)
 → 순위: 키워드 · 벡터 · 혼합(RRF) + 반드시 남길 구간(제약·결정·숫자) 가점
 → MMR로 글자 예산 안에서 다양하게 선택 → 원래 순서로 이어 붙인 추출 브리프
 → (선택) LLM 요약 + 원문에 없는 숫자·날짜·ID가 생기면 거절
```

| 구현 | 위치 |
| --- | --- |
| 조사 제거 토큰화, BM25, 핵심어, 질의 확장 | `lab/briefing/keywords.py` |
| 보안 처리·순위·예산 선택 | `lab/briefing/pipeline.py` |
| 원문 검사 요약(아무 LangChain 채팅 모델) | `lab/briefing/summarize.py` |
| 40쪽 이상 합성 프롬프트(정답 결정·제약, 폐기안, 주입 4개, 가짜 연락처)와 채점 | `lab/briefing/synthetic.py` |
| 실험 실행 | `scripts/run_brief_experiment.py` → `docs/evidence/brief/` |

**첫 실험(합성 41.6쪽, 예산 6,000자, 과제 6개, 가짜 임베더라 의미 검색 결과 아님).**

| 방식 | 평균 정답 회수율 | 주입 누출 | 개인정보 누출 | 폐기안 포함 |
| --- | --- | --- | --- | --- |
| 앞부분 자르기 | 0.0 | 0 | 0 | 0 |
| 키워드(BM25) | 0.467 | 0 | 0 | 2 |
| 벡터(가짜) | 0.445 | 0 | 0 | 0 |
| 혼합(RRF + 질의 확장 + 필수 가점) | 0.943 | 0 | 0 | 0 |

**승격 조건.** 실제 임베딩(E5 등)으로 같은 실험을 다시 돌려 혼합이 단독 방식보다 낫고, 실제 저장 프롬프트의 마스킹본 표본 10개에서 사람이 "작업에 필요한 내용이 빠지지 않았다"고 확인할 것.

## 5-2. 핵심 기능 B — 골든셋으로 임베딩 모델 고르기

**목표.** 임베딩 모델은 한국어 의미 파악과 검색 정확도가 모델마다 다르므로, 감으로 고르지 않고 **질문과 정답 조문(문서)을 짝지은 평가 목록(골든셋)**으로 직접 재서 고른다.

```json
{"question": "평일 오후 4시에 매장에서 식사할 수 있어?", "source": "제1조", "type": "paraphrase"}
```

| 지표 | 뜻 |
| --- | --- |
| 1위 정답 | 가장 유사하다고 고른 1위 문서가 정답과 같은 질문 수 (`n/총수`) |
| 3위 안 정답 | 상위 3개 안에 정답이 있는 질문 수 |
| MRR | 정답 순위의 역수 평균. 1위·3위 사이의 차이를 보완 |
| 유형별 | 의역·법률 용어 등 질문 유형별로 따로 |
| 지연 | 문서 인코딩 시간, 질문 1개 인코딩 중앙값 |
| 갈린 질문 | 모델마다 결과가 다른 질문을 하나씩 보여 줌 |

- 구현: `lab/golden.py`, 실행 `scripts/compare_embedders.py --models fake,e5@<revision>`. 네트워크를 차단하고 로컬 캐시 모델만 씁니다.
- 같은 비교기가 Legal Intake 평가 자료(`--legal-intake`)와 법률 조문 골든셋(`--golden --corpus`)을 둘 다 읽습니다.
- 표본이 작으므로 결과는 백분율보다 개수로 적고, 모델 선택은 갈린 질문을 사람이 읽고 확정합니다.
- 첫 결과(가짜 임베더, 기준선): 예시 골든셋 1위 5/8·3위 안 7/8, Legal Intake 자료 1위 14/20·3위 안 17/20.

**승격 조건.** E5와 비교 후보 하나 이상을 같은 골든셋으로 비교한 보고서가 `docs/evidence/golden/`에 남을 것.

실제 의뢰인 자료·소송 자료, 유료 API 기본 사용, 원격 tracing 기본 사용, 검증 없는 stable 승격, 같은 부품을 두 저장소에서 따로 고치는 것.
