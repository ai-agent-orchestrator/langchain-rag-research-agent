# R39 목표선과 초과 경고

## 구현

AGENTS.md와 METRICS_BOARD.ko.md를 먼저 읽고 RESEARCH_GRAPH_DESIGN,
DOMAIN_FILTERS, LANGGRAPH_GUARDRAIL 및 tests/test_structure.py 규칙을 확인했다.
변경 범위는 지정된 네 파일뿐이다. 신규 모듈은 MATURITY=incubating이며
표준 라이브러리, core.RunEvent, 기존 rag.guard_audit만 사용한다.
KNOWN_DEBT, 기존 시험, 기본 그래프와 설정은 변경하지 않았다.

- `load_targets(path="evals/metric_targets.json")`가 UTF-8 JSON을 읽는다.
  파일 없음은 빈 설정이며 경고·로그·파일 생성이 없다. 잘못된 JSON과
  유효하지 않은 범위, 권한 오류는 숨기지 않는다. 기본 경로는 작업 디렉터리 기준이다.
- `check_targets(events, targets, *, injection_run_ids=())`는 실제 RunEvent 또는
  전체 이벤트 매핑, 로드된 목표 사전 또는 파일 경로를 받는다.
  매핑은 실제 RunEvent 생성자로 검증하며 중복 run_id를 거부한다.
  입력을 변경하지 않고 초과·미달 항목 목록을 반환한다. 파일·도메인·지표·개별
  min/max가 없으면 그 검사를 하지 않는다. 경계값과 같은 관측값은 허용한다.
- 이벤트 정본의 `cost_krw`, `total_ms`, `grade.relevance_drop_rate`, `guard`를
  그대로 사용한다. 설정은 도메인별 같은 키 아래 min/max 객체를 두며
  grade는 중첩 객체다. guard 값은 배열의 모든 반려 발생 횟수다.
  임계값은 JSON에서만 읽고 코드에 기본 임계값을 두지 않았다.
- 각 실행을 개별 검사한다. 평균으로 개별 초과를 숨기지 않는다.
  반환 항목은 run_id/domain/estimated/metric/value/bound/limit이다.
  guard의 reason/span 및 질문·답변 원문은 복사하지 않는다.
- 탈락률 경고는 기존 실제 aggregate_guard_audit로 표본 문서 수와
  count/total/rate/Wilson 95% 구간을 추가한다. 비율과 문서 수가 불일치하면
  거부한다. 분모가 없는 실행은 검사하지 않으며 injection 실행 ID도 탈락률
  검사에서 제외한다. 원가·시간·guard 검사는 injection에도 유지한다.
  추정/비추정 실행은 합산하지 않고 각 항목에 estimated를 유지한다.

목표 JSON에는 research/legal/medical/life 네 도메인을 넣었다.
리서치 원가 1.5원·시간 6000ms는 설계 예시이며 나머지 도메인 값과 탈락률
범위는 **운영 검증 전 초기 설정**이다. 각 도메인의 guard 상한은 0이다.
이는 관측된 반려 신호에 대한 보수적 경고이며 안전 위반 0건의 보장이 아니다.
함수 호출로만 활성화되며 import 시 파일 IO·모델 실행·기존 경로 변경은 없다.

사용 예:

```python
from rag_research_agent.rag.metric_targets import check_targets, load_targets

targets = load_targets("evals/metric_targets.json")
warnings = check_targets(events, targets, injection_run_ids=["run-inj"])
```

## 시험

신규 시험은 매개변수 확장 포함 **35개 사례 정의**이며 실행 통과 수가 아니다.
실제 RunEvent·JSON 로더·기존 감사 집계·새 목표 검사 함수를 통과하는 합성
경로 시험이다. 모델·임베더 대역은 만들지 않았고 개인정보 형태의 값도 없다.

원가·시간의 미만/경계/초과, 탈락률 하한/상한 양쪽 경계와 Wilson 구간,
guard 0/중복 발생, 도메인별 목표·미설정 도메인, 지표·범위·파일 부재,
빈 입력, 파일/이벤트 JSON 왕복과 입력 불변성, 배포 JSON 네 도메인,
injection·빈 문서 분모, estimated 식별, 잘못된 목표·JSON·이벤트·중복 ID와
문서 수 불일치 거부를 검사하도록 작성했다.

전체 시험 명령(NightCoder의 memvid 표식 시험 제외 정책):

```powershell
python -m pytest -q -m "not memvid" -p no:cacheprovider --basetemp=.runs/r39/pytest-temp
```

**이 환경에서 시험 미실행: Python 실행기를 찾을 수 없음.**
tests not run here: Python executable is unavailable in this sandbox.
passed/failed/error/skipped: 모두 미집계(시험 수집·실행을 시작하지 못함).
명령 탐색에서도 `python`, `py` 실행기를 찾지 못했다.
실패 원인 기록은 `.runs/r39/full-tests.txt`다. NightCoder 게이트 판정이 필요하다.

## 설계 대비 차이·후속 연결 필요

정본에 안전 위반을 별도로 확정하는 이벤트 필드가 없으므로 새 필드를
임의로 추가하지 않고 `guard`의 반려 발생 수를 보수적 경고 신호로 사용한다.
방어 관문이 차단한 시도와 실제 최종 출력 위반을 구분하지 못한다.
안전 위반의 확정 판정과 의미 검증은 **미검증·후속 연결 필요**다.

보드 평균선 대신 실행별 목표 검사 API를 제공한다. 보드 HTML에 목표선을
그리거나 경고를 표시하는 scripts/metrics_board.py 수정은 허용 범위 밖이므로
**후속 연결 필요**다. injection 표시는 정본에 없어 기존 감사 집계처럼 run_id
sidecar로 받는다. 토큰 가격 재계산은 하지 않고 생산자의 cost_krw를 사용한다.

## 미검증·보호 확인·커밋

시험 통과, 운영 목표 적절성, 실제 이벤트 생산자의 시간·가격·grade 정합성,
실제 모델 품질과 안전 위반, 보드·서비스 종단 연결은 미검증이다.
모델이 필요한 기능이 아니므로 실제 모델 실행 명령은 없다.
네트워크·LLM 호출·모델 다운로드·패키지 설치는 수행하지 않았다.

**18/18 SHA-256 동일**을 확인했다. 증거는 `.runs/r39/protected-before.json`,
`.runs/r39/protected-after.json`이다. 기준 manifest 자체의 정당성은 미검증이다.

tracing.py, memvid_store.py와 기존 시험은 수정하지 않았다.
결과 기록은 `.runs/r39/` 안에만 썼다. push·원격·브랜치 설정 변경은 없다.

현재 `nc/rra-codex`에서 git add 및 commit을 시도했으나

권한 상승 불가로 **커밋 해시 없음·미커밋 변경 0건 조건 미달성**이다.
