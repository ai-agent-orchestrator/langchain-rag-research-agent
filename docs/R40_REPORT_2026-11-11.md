# R40 합성 이벤트 생성기와 Fast/Deep 통계

## 구현

AGENTS.md와 METRICS_BOARD.ko.md를 먼저 확인하고 RESEARCH_GRAPH_DESIGN,
DOMAIN_FILTERS, LANGGRAPH_GUARDRAIL 설계 및 test_structure 규칙을 확인했다.
허용된 scripts/make_demo_events.py, tests/test_demo_events.py, 본 보고서만 추가했다.
기존 기본 설정, 기존 시험·기대값·skip, KNOWN_DEBT는 변경하지 않았다.

- generate_events(seed=42, per_domain=25): 로컬 random.Random을 사용해 research,
  legal, medical, life 각각 25건을 만든다. 전역 난수 상태를 건드리지 않는다.
  동일 시드·건수·코드에서 이벤트 순서와 JSONL 바이트가 재현되도록 구성했다.
  시드와 도메인·순번으로 영문자만 포함하는 결정적 demo ID를 만든다.
- 실제 core.RunEvent, NodeEvent, cost_krw를 사용한다. 별도 이벤트 대역이나
  모델·임베더 대역은 없다. 검색·그래프·모델 실행 기록이 아닌 **합성 경로 시험 데이터**다.
  스크립트는 표준 라이브러리와 core만 import하며 MATURITY=incubating이다.
- Fast는 반복 없는 retrieve/grade 경로, Deep은 rewrite/gap/verify 반복 경로를
  합성한다. END/give_up/cutoff, grade, guard 코드·가짜 reason, nodes를 채운다.
  토큰·호출 수·전체 시간은 노드별 합계, 원가는 입력/출력별 가상 단가 합계다.
  demo-slm과 demo-flagship은 호출 가능한 모델이 아닌 가상 계측 이름이다.
  단가는 각각 입력/출력 백만 토큰당 100/200원, 1000/2000원의 데모 상수다.
  이벤트·노드 모두 estimated=true이며 TTFT도 가상 값이다.
- write_events는 `.runs/events/` 아래 배치 디렉터리에만 events.jsonl과
  summary.json을 쓴다. 경로를 resolve한 뒤 검사하며 events 루트 자체와 외부는 거부한다.
  같은 배치를 다시 쓰면 이 두 파일을 교체한다. 삭제·누적 추가는 하지 않는다.
- summarize_events(iterable)는 estimated/non_estimated 코호트를 분리하고,
  각각 전체 및 도메인별 n, Fast/Deep count/n/ratio/Wilson 95% 구간,
  mean_cost_krw, mean_loops(rewrite/gap/verify), mean_total_loops를 반환한다.
  총 루프 평균은 세 종류 합계의 실행당 평균이다. 빈 분모의 평균·비율·구간은
  null(미검증)이며 관측 0건을 보장으로 해석하지 않는다.
  라우팅 통계만 계산하고 검색 품질 분모나 품질 점수는 만들지 않는다.

## R38 보드 사용법

저장소 루트에서 다음 명령을 순서대로 실행한다. 결과는 전부 .runs 안에 생성된다.

```powershell
python scripts/make_demo_events.py --seed 42 --per-domain 25 --output .runs/events/r40-demo
python scripts/metrics_board.py --events .runs/events --output .runs/r40/metrics-board.html
```

R38은 배치 하위 events.jsonl만 읽으므로 summary.json을 이벤트로 읽지 않는다.
4개 도메인 탭의 추정 계측 코호트에서 기존 4패널과 Fast/Deep 비율을 확인하고,
도메인별 평균 비용·루프와 구간의 숫자 원본은 `.runs/events/r40-demo/summary.json`에서 본다.
기본 출력 옵션을 생략하면 시드에서 만든 영문 라벨의 demo 배치를 사용한다.
동일 시드의 데이터는 같은 배치로 재생성해야 한다. 같은 데이터를 다른 배치에도
복사하면 run_id가 겹쳐 기존 R38 로더가 거부한다. 기존 운영 데이터와 분리하려면:

```powershell
python scripts/make_demo_events.py --seed 42 --output .runs/events/r40-only/demo
python scripts/metrics_board.py --events .runs/events/r40-only --output .runs/r40/demo-only.html
```

Python 사용 시 `generate_events`, `write_events`, `summarize_events`를
scripts.make_demo_events에서 import할 수 있다. 보드 자체는 수정하지 않았다.

## 시험

신규 시험은 매개변수 확장 포함 **13개 사례 정의**다. 실행 통과 수가 아니다.
시드별 직렬화 재현성과 전역 난수 보존, 도메인 4종과 ID 유일성,
R35 from_json 왕복, 경로·루프·노드별 호출/토큰/시간·가격 합계,
잘못된 인자, 손으로 계산한 통계와 Wilson 구간, 빈 입력·추정 코호트 분리,
JSONL 재작성 바이트와 R38 load_events/render, CLI·출력 경로 제한을 검사한다.
실제 클래스와 실제 보드 경로를 사용하며 네트워크 접근은 없다.
시험 결과 파일은 `.runs/events/` 아래 임시 디렉터리에서 생성하고 정리한다.
개인정보 모양의 이름·연락처·식별번호는 시험·예시 데이터에 넣지 않았다.

전체 시험 명령(NightCoder memvid 표식 제외 정책):

```powershell
python -m pytest -q -m "not memvid" -p no:cacheprovider --basetemp=.runs/r40/pytest-temp
```

**이 환경에서 시험 미실행: Python 실행기를 찾을 수 없음.**
tests not run here: Python executable is unavailable in this sandbox.
passed/failed/error/skipped는 모두 미집계(수집·실행 시작 불가)다.
실패한 시험 사례나 memvid 시험 결과는 발생하지 않았으며 수정·재시험·skip 추가도 없다.
이유는 `.runs/r40/full-tests.txt`에 기록했다. 실행 판정은 NightCoder 게이트가 해야 한다.

## 설계 대비 차이

정본과 R35 필드 이름을 그대로 사용하고 nodes를 run 내부에 넣는다.
R35의 추가 estimated 필드도 포함한다. run_id는 UUID 대신 개인정보 모양을 피한
결정적 demo 영문 ID이며 sha는 실제 코드 해시가 아닌 demo-unversioned 표시다.
원가는 pricing.json과 같은 모델별 입력/출력 단가 계약으로 계산하되 명시적인
가상 단가 상수를 사용한다. 실측·현행 시장 가격·도메인별 품질 주장이 아니다.
실제 라우터 결정, 도메인 필터, Chroma 검색은 실행하지 않는다.
이 기능은 명시적 스크립트 호출에서만 켜지고 기존 그래프 기본 동작은 유지된다.
실시간 이벤트 수집, Spring Boot/FastAPI 콜백, 요약 JSON을 보드 UI에 직접 표시하는
기능은 범위 밖이므로 **후속 연결 필요**다. 가드 코드와 경로의 관계도 합성 예시다.

## 미검증·보호 확인·커밋

생성 CLI·신규 시험의 실제 실행 통과, 보드 브라우저 표시, 실제 모델의 품질·비용·
레이턴시·라우팅 비율은 **미검증**이다. 모델 실행이 필요한 기능이 아니므로 실제
모델 실행 명령은 없다. 모델 다운로드·LLM 호출·패키지 설치·네트워크 접근은 하지 않았다.
Chroma 기본값은 유지하며 memvid import나 대체 기능은 추가하지 않았다.

보호 파일은 `.runs/n10/protected-after.json`의 Expected를 기준으로 작업 전후
**18/18 SHA-256 동일**이다. 증거는 `.runs/r40/protected-before.json`,
`.runs/r40/protected-after.json`이다. 기준 manifest의 정당성은 미검증이다.
초기 작업 트리는 깨끗했다. 금지 파일·README·기존 시험은 변경하지 않았다.
git diff --check와 새 파일의 줄 끝 공백 정적 확인을 수행했다.

현재 브랜치에서 git add가 `.git/index.lock: Permission denied`로 실패했다.
커밋도 같은 Git 쓰기 권한 차단으로 실패했다. **커밋 해시 없음.**
권한 상승이 허용되지 않아 세 파일을 보존하며, 미커밋 변경 0건 조건은 달성하지
못했다. Git 쓰기가 가능한 NightCoder 환경에서 시험 후 단일 커밋 수집이 필요하다.
의도한 메시지: `feat: add deterministic demo events and routing summary (R40)`.
push·원격·브랜치 설정 변경은 수행하지 않았다.
