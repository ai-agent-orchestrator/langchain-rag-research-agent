# R40 합성 이벤트 생성기와 Fast/Deep 통계

## 구현

2026-11-12 점검. AGENTS.md, METRICS_BOARD.ko.md, RESEARCH_GRAPH_DESIGN.ko.md,
DOMAIN_FILTERS.ko.md, LANGGRAPH_GUARDRAIL.ko.md와 test_structure 규칙을 확인했다.
기존 R40 구현이 현재 브랜치에 이미 있어 이를 보완했다. 변경 범위는 지정된
scripts/make_demo_events.py, tests/test_demo_events.py, 본 보고서 세 파일이다.

- `generate_events(seed=42, per_domain=25)`는 로컬 random.Random으로 research,
  legal, medical, life 각각 같은 건수의 실제 RunEvent를 만든다. 같은 시드·건수·코드에서
  직렬화가 재현되며 전역 난수 상태는 유지된다. ID는 영문자 데모 라벨이다.
- 실제 core.RunEvent, NodeEvent, cost_krw를 사용한다. 표준 라이브러리와 core만
  import한다. 모델·임베더 대역이나 실제 모델 호출 없이 합성 계측을 생성한다.
- Fast는 반복 없는 경로이고 Deep은 rewrite/gap/verify 반복을 합성한다.
  END는 generate 후 선택적으로 verify/write를 수행한다. 이번 보완으로
  생성 이전에 중단하는 give_up/cutoff에는 verify/write가 붙지 않으며 verify 횟수도 0이다.
- TTFT는 첫 생성 노드 이전 시간과 그 노드 시간의 절반을 합한 가상 값이다.
  뒤의 verify/write 시간을 포함하던 계산을 수정했다. 생성 없는 실행은 스키마의
  숫자 필드를 유지하려고 total_ms를 대체값으로 쓴다. 실제 첫 토큰 관측값이 아니다.
- 토큰·호출 수·전체 시간은 노드별 합계다. 가상 모델 이름 demo-slm/demo-flagship의
  입력/출력 백만 토큰당 100/200원, 1000/2000원 상수를 cost_krw에 전달한다.
  모든 데모 이벤트와 노드는 estimated=true이다. 가격은 시장 가격이 아니다.
- `write_events(events, directory)`는 resolve한 `.runs/events/` 하위 배치에
  events.jsonl과 summary.json을 쓴다. 루트 자체와 외부 경로는 거부한다.
- `summarize_events(iterable)`는 estimated/non_estimated를 분리한다. 각 코호트의
  전체 및 도메인별 n, Fast/Deep count/n/ratio/Wilson 95% 구간, mean_cost_krw,
  mean_loops(rewrite/gap/verify), mean_total_loops를 반환한다. 빈 분모는 null(미검증)이다.
  관측 0건은 보장이 아니며 검색 품질 지표는 계산하지 않는다.

## R38 보드 사용법

저장소 루트에서 다음 명령을 순서대로 실행한다. 다른 배치와 중복 run_id가 생기지
않도록 전용 이벤트 디렉터리를 사용한다. 결과는 모두 .runs 아래에 쓴다.

```powershell
python scripts/make_demo_events.py --seed 42 --per-domain 25 --output .runs/events/r40-only/demo
python scripts/metrics_board.py --events .runs/events/r40-only --output .runs/r40/demo-only.html
```

R38은 배치 하위 events.jsonl만 읽는다. 4개 도메인 탭에서 추정 계측 코호트의
4패널과 Fast/Deep 비율을 확인한다. 도메인별 평균 비용·루프의 숫자 원본은
`.runs/events/r40-only/demo/summary.json`이다. 동일 시드 데이터는 같은 배치로
재생성한다. 다른 배치로 복사하면 R38의 중복 run_id 검사에 걸린다.
Python에서는 scripts.make_demo_events의 generate_events/write_events/summarize_events를 쓴다.

## 설계 대비 차이

정본 및 R35 필드 이름과 R35 estimated 필드를 사용한다. run_id는 UUID 대신 결정적
영문 데모 라벨이고 sha는 demo-unversioned다. pricing.json 대신 같은 입력/출력 단가
계약의 가상 상수를 쓴다. 이벤트 경로·가드 사유도 합성 예시로 실제 라우터·필터 실행이 아니다.
이번 중단/TTFT 보완은 합성 데이터의 내부 일관성을 위한 변경이다.
기존 그래프 설정·기본 동작, Chroma 기본값, KNOWN_DEBT는 유지한다.
실시간 수집, Spring Boot/FastAPI 콜백, 요약 JSON의 보드 UI 표시는 **후속 연결 필요**다.
