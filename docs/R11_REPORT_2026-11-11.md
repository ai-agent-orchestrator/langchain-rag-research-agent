# R11 — plan 노드 구조화 출력 어댑터

## 구현

`research_llm.py`에 엄격한 Pydantic `PlanOut`을 추가했다. 필수 필드는 `required_metrics`, `issues`, `perspectives`이며, 관점은 base/pro/con만 허용한다. 추가 필드·잘못된 자료형·공백 지표 및 쟁점을 거부한다. 빈 목록은 유효한 계획이다.

`llm_planner(model, masker)`는 기존 `plan_rule` 호출 계약에 선택적 코드 로그를 더한다. 질문을 마스킹하고 DATA 경계를 이스케이프해 모델에 전달한다. 체크리스트는 모델에 보내지 않고 마스킹 후 먼저 병합하며, 모델 지표는 중복을 제거해 뒤에 추가한다. 체크리스트 중복의 기존 처리 방식은 유지한다. `use_checklist`와 `auto_metrics`를 모두 존중한다. 모델의 지표·쟁점도 저장 전에 마스킹한다. 바인딩·호출은 실제 `serving_trace_guard`와 `serving_config`를 사용한다.

마스킹·모델 바인딩·호출·출력 검증 중 오류가 발생하면 부분 계획을 폐기하고 원래 인자로 기존 `plan_rule`을 호출한다. 성공/실패 로그는 `PLAN_LLM:OK` 또는 `PLAN_LLM:FALLBACK_RULE`이며 질문·예외 메시지·모델 출력은 로그에 넣지 않는다. masker가 없으면 어댑터 생성을 거부한다.

`ResearchConfig.planner: Literal["rule", "llm"] = "rule"`과 그래프/Runner의 `planner_model` 주입 인자를 추가했다. 알 수 없는 모드, llm 모드의 모델·masker 누락을 생성 시 거부한다. 기본 rule 경로는 그대로이며 주입한 모델을 호출하지 않는다. 추출 모델과 계획 모델은 별도로 주입한다. 검색·저장소 구현은 변경하지 않았고 memvid 의존성도 추가하지 않았다.

## 시험

신규 `tests/test_research_llm_plan.py`는 실제 PlanOut, ResearchPlan, plan_rule, ResearchRunner, LangGraph 및 동결된 `mask_pii`를 사용한다. 모델 경계만 fake 모델을 주입한다. 개인정보 경계 시험은 영문 마커와 예약된 `[MASKED_EMAIL]`을 사용한다.

작성한 시험은 Pydantic/dict 출력, 체크리스트 우선순위·중복, 두 설정 플래그 조합, 바인딩 오류·모델 예외·이상 출력·공백 항목 폴백, 마스킹 오류 시 모델 미호출, DATA 경계 이스케이프, 유효한 빈 목록, masker 필수, 실제 그래프 검수 완료, 기본 rule 보존, 모델이 계획한 지표의 실제 gap 검색 연결, 계획/추출 모델 동시 주입과 설정 오류를 다룬다. 모두 경로 시험이며 실제 모델 품질 평가는 아니다.

## 설계 대비 차이

설계 정본 세 문서의 선택적 구조화 출력·마스킹·규칙 폴백 및 설계 9절 체크리스트 우선 병합을 따른다. 지정 범위 밖 `core/research.py`의 ResearchPlan에 쟁점 필드가 없어, rag 내부의 동결 dataclass 하위 자료형 `_LLMResearchPlan`에 `issues`를 보존한다. 기존 ResearchResult.plan과 State가 이 객체를 그대로 전달한다. 공통 core 계약으로의 쟁점 필드 통합은 후속 연결 필요다.

모델이 제안한 관점·쟁점은 계획에 보존하지만 검색 분기를 바꾸지 않는다. 기존 `stance_split`에 따른 base/pro/con/limits 검색과 지표 기반 coverage/gap 동작을 유지한다. 쟁점별 coverage 및 모델 관점에 따른 분기 변경은 후속 연결 필요다. 기본 동작과 기존 편향 방지 경로를 보존하기 위함이다.

기존 그래프의 question/checklist는 이미 마스킹된 입력이라는 설계 계약을 유지한다. 어댑터의 재마스킹은 모델 경계에 적용하며, 마스킹 오류 시 규칙 폴백은 기존 인자로 수행한다. 그래프 전체 입력 마스킹 계약을 새로 구현하지 않았다. 기존 shadow cost 계산도 유지하므로 실제 모델 토큰·시스템 지시·출력 비용은 미검증이다.

## 미검증 및 대표 실행 명령

전체 시험 통과, 실제 로컬 모델의 계획 품질·구조화 출력 지원, 주입 방어 효과, 실제 masker 통합은 미검증이다. 대표 PC에서 이미 보유한 로컬 모델과 masker를 `.runs/local_planner_factory.py`의 `model`, `masker`로 준비한 뒤 실행할 명령이다. 해당 factory는 대표가 준비하는 주입 진입점이며 이번 작업에서 만들거나 실행하지 않았다. 외부 API·다운로드를 수행하는 factory를 사용하지 않는다.

```powershell
python -c "import runpy; from rag_research_agent.rag.research_graph import ResearchRunner, ResearchConfig, keyword_search; c=runpy.run_path('.runs/local_planner_factory.py'); r=ResearchRunner(keyword_search({'doc-a1':'매출은 18% 증가했다.'}), ResearchConfig(planner='llm', stance_split=False), planner_model=c['model'], masker=c['masker']); print(r.run('매출 분석', ('매출',)))"
```

## 범위 및 보호 확인

초기 git status는 깨끗했다. 변경 대상은 지정된 소스 두 개·신규 시험·본 보고서 네 파일이다. 기존 시험·기대값·skip·KNOWN_DEBT·금지 파일·README·data/profiles는 변경하지 않았다. 보호 파일 18개 SHA-256이 기존 `.runs/n10/protected-after.json`의 Expected와 모두 일치한다. 비교 증거는 `.runs/r11/protected-after.json`이다. `git diff --check`를 통과했다. 실행 산출물은 `.runs/`에만 기록하며 push·원격·브랜치 설정 변경은 하지 않는다.

## 커밋 제약

지정한 네 파일에 대한 `git add`와 `git commit -m "feat(rag): add optional structured research planner"`를 모두 시도했으나 `.git/index.lock: Permission denied`로 실패했다. 이 샌드박스의 `.git`은 읽기 전용이며 권한 상승이 허용되지 않는다. 커밋 해시는 없고 미커밋 변경 0건 조건을 충족하지 못했다. 작업은 삭제하지 않고 네 파일에 보존했다. Git 쓰기가 가능한 NightCoder 환경에서 한 커밋으로 수집해야 한다.
