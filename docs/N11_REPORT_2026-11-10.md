# N11 파이프라인 결과 → HTTP 응답 매핑

2026-11-10 KST · 작성: Claude (브랜치 `claude/n6-n7-n11`) · NightCoder 명세 `rra-n11-http-mapping`

## 구현
`rag/http_mapping.py`: 웹 프레임워크를 import하지 않는 순수 함수. `validate_request`, `map_reply`, `map_exception`, `map_outcome`.
매핑 표는 코드 상수(`REPLY_STATUS`, `ERRORS`)이며 docs/LANGGRAPH_GUARDRAIL.ko.md에 그대로 실었다.

근거와 선택:
- 설계 문서(MODULE_DESIGN.ko.md 2-3)가 정한 것: `RETRIEVAL_UNAVAILABLE` 503, "정책 차단과 기술 오류를 섞지 않는다".
- 기존 계약 유지: 답변·근거 없음·정책 차단은 모두 `GuidanceReply.to_dict()` 본문 그대로 200. 차단을 오류 코드로 바꾸지 않았다.
- 새로 정한 것(검토 필요): 슬롯 부족 503 + Retry-After 5, 추론 시간 초과 504, 백본 미설정·RAG 꺼짐 503, 모델 초안 거절 502,
  가드레일 한도 중단 503 `GUARDRAIL_STOPPED`(원인이 일시 장애면 그 코드로 보고), 잘못된 요청 400, 그 외 500.
- 400은 파이프라인 실행 전 `validate_request`로만 낸다. 파이프라인 안의 `ValueError`는 서버 오류(500)로 본다.
- 오류 본문은 `{"error": 코드}`뿐이다. 예외 메시지·질의·스택이 들어가지 않는 것을 개인정보가 든 예외로 시험했다.
