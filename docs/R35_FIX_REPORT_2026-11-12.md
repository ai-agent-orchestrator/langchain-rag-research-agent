## 결론·원인 분류

과거 R35 보고의 실패는 **시험 격리** 문제다. 프로덕션 회귀나 실행 순서 의존,
동일 조건에서 결과가 바뀌는 flaky로 분류하지 않는다.
실패 시험은 R38에서 추가된
`tests/test_metrics_board.py::test_cli_refuses_output_outside_runs`다.
pytest의 tmp_path가 저장소 .runs 밖이라는 숨은 전제와, R35 실행 명령의
`--basetemp=.runs/...`가 충돌했다. CLI는 .runs 안 출력을 정상 허용했지만
시험은 이를 .runs 밖이라고 간주해 SystemExit를 기대했다.
R36~R38 재검증에서는 pytest 기본 임시 경로를 사용했으므로 통과했다.
프로덕션 수정으로 해소된 것이 아니었다.

## 수정·회귀 방지

변경 코드는 tests/test_metrics_board.py의 관련 시험만이다.
거부 시험은 monkeypatch로 CLI의 ROOT를 임시 fixture 아래 별도 project로 격리한다.
검사 출력 경로는 그 project 밖이므로 실제 pytest 임시 경로가 어디든 같은 거부
조건이 유지된다. monkeypatch는 시험 종료 시 ROOT를 복구한다.
`pytest.raises(SystemExit)` 기대값은 그대로 유지한다.

새 시험 `test_cli_rejection_when_pytest_temp_is_inside_runs` 1개는
원래 프로젝트 .runs/pytest-temp/case-a 아래에 fixture가 놓이는 과거 재현 조건을
고정하고 격리된 거부 시험을 실행한다. 출력 파일이 생성되지 않은 것도 검사한다.
새 회귀 조건은 .runs 내부 basetemp로 직접 실행한 전체/전용 시험에서도 검증했다.
프로덕션 코드, R35 전용 시험 67개, skip/xfail, memvid 표식과 제외 범위는 변경하지 않았다.
