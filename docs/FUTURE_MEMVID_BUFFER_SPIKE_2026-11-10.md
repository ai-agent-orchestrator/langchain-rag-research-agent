# 보류 과제: memvid 안정화 버퍼 spike (11월 말, 본 개발 시작 전)

날짜: 2026-11-10 KST · 상태: **보류. 대표가 지시하기 전에는 시작하지 않는다.**
관련: docs/DECISION_STORE_CHROMA_2026-11-10.md, docs/X0_MEMVID_DIAGNOSIS_2026-11-10.md

## 목적
memvid 쓰기의 간헐 실패(MV999, os error 5)를 버퍼 계층으로 완화할 수 있는지 시험한다.
버퍼는 원인을 고치는 것이 아니라 증상을 가릴 수 있으므로, 결과는 "안정화 가능 /
불가 / 환경 조치 필요" 중 하나로 정리하고 원인을 단정하지 않는다.

## 후보 (싼 순)
1. 새 핸들·새 파일 재시도: 실패 시 writer를 닫고 새 파일에 처음부터 다시 쓴다.
   (현 retry는 같은 writer에 재호출한다.)
2. 임시 위치에 쓰고 검증 후 최종 위치로 이동. 이동 전에 핸들이 닫혔는지 확인한다.
   (열린 핸들 파일의 os.replace가 같은 접근 거부를 낸 대조 결과가 있다.)
3. 쓰기 전용 프로세스 격리와 실패 시 재기동.
4. 저널 버퍼(SQLite 또는 파일)에 먼저 기록 후 memvid에 배치 반영.
5. 모든 방식에 쓰기 후 읽기·해시 검증.

## 시험 설계 (결과를 보기 전에 고정)
- 현재 방식과 각 후보를 같은 조건에서 최소 30회씩 실행한다.
- 성공률, Wilson 95% 구간, 실패 시점, 소요 시간을 기록한다. 구간이 겹치면 "차이 불확실".
- 조건: 저장 위치(저장소 .runs / 사용자 Temp), 보안 프로그램 제외 전후(대표 선택).
- 합격선은 시작 전에 대표와 정한다.
- 본 개발 코드와 섞지 않는 별도 spike로 둔다.

## 선행 조건
- X0 진단 확장(trials 확대, 조건 대조)이 먼저 끝나 비교 기준이 있어야 한다.
- 이 spike의 결과와 무관하게 개발 기본값은 Chroma다.
