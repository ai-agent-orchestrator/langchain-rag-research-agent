# N12 보고서 — 답변 인용 표시 포매터

2026-11-10 KST. AGENTS.md를 먼저 읽고 현재 저장소·브랜치 `nc/rra-codex`에서 작업했다. Chroma 개발 기본값을 따르며 memvid 의존성을 추가하지 않았다.

## 구현

- `rag/citations.py`에 `format_citations(answer, citation_ids, evidence, *, document_hashes, format="markdown") -> str`을 추가했다. 기존 `GuidanceDraft`/`GuidanceReply`의 chunk ID 인용 목록과 `GuidanceEvidence` 형태(`answer.EvidenceLike`)를 그대로 사용한다. 새 DTO·가짜 클래스는 만들지 않았다.
- 본문을 보존하고 본문 끝에 `[1] [2]`를 붙인다. 문장별 인용 위치는 추론하지 않는다. 인용 목록에서 처음 등장한 순서로 번호를 부여하며 같은 document ID의 청크·중복 인용은 하나로 합친다. 제목은 첫 인용의 값을 사용한다. 인용하지 않은 검색 결과는 참고자료에 넣지 않고 알 수 없는 chunk ID는 거절한다.
- 참고자료에 마스킹된 제목, 문서 ID, SHA-256 앞 8자리를 표시한다. Markdown은 제목·ID의 제어 문자를 escape하고 목록 항목으로 출력한다. 일반 텍스트는 heading 문법·escape 없이 출력한다. 참고자료 필드의 줄바꿈은 공백으로 바꾼다. 인용이 없으면 본문을 그대로 반환한다.
- 기존 DTO에는 문서 hash가 없다. 호출자가 신뢰할 수 있는 문서 ID별 SHA-256 매핑을 별도 전달해야 하며, 인용 문서에 hash가 없거나 64자리 hex가 아니면 거절한다. `source_version`이나 청크 `content_hash`를 문서 hash로 대체하지 않는다. 포매터는 파일·원문·검색 저장소를 읽지 않으며 본문·제목은 호출 전 마스킹·검사가 완료되어야 한다.
- `MATURITY = "incubating"`을 선언하고 `rag/`에 배치했다. 기존 answer 조립 코드, 구조 시험, KNOWN_DEBT, 기존 시험 기대값은 수정하지 않았다.

신규 시험은 매개변수 전개 기준 13건이다. 실제 `GuidanceEvidence` DTO와 실제 포매터를 사용하여 두 형식의 정확한 출력, 인용 순서, 같은 문서 병합, 미인용 문서 제외, 인용 없는 본문 보존, 존재하지 않는 ID 거절, hash 누락·형식 오류, Markdown 메타데이터 escape, 미지원 형식, 충돌 chunk ID 거절을 검사한다. 네트워크·모델·LLM 호출을 추가하지 않았다.

## 입증하지 못한 것 / 미검증 및 후속 연결

- 실행 환경의 Python 부재로 신규 동작 및 전체 시험 통과는 미검증이다. 구조 규칙은 선언·배치를 소스로 확인했으며 구조 시험 실행은 미검증이다.
- 문서 SHA-256의 진위 및 마스킹 완료 여부는 호출자 계약이다. 포매터에서 원문 재검증하지 않는다. 기존 DTO·Chroma 검색 경로에 문서 전체 hash 제공 계약은 없으므로 후속 연결 필요다.
- 연결 후보는 `GuidancePipeline.ainvoke`에서 draft 인용 검증 후 `GuidanceReply` 반환 전의 표시 단계다. 현재 `assemble_answer`는 이미 참고자료를 넣으므로 그대로 포매터를 덧붙이면 참고자료가 중복된다. 후속 작업에서 표시용 본문과 검증된 인용·마스킹 evidence 및 신뢰할 수 있는 문서 hash를 전달하고, 최종 표시 결과에도 출력 정책·길이 제한을 적용해야 한다. 이번에는 기존 조립 코드를 수정하지 않았다.
- 실제 모델·검색 품질 평가 및 종단 간 UI 연결은 미검증이다. 본 작업은 순수 표시 기능이므로 실제 모델 실행 명령은 추가하지 않았다.
