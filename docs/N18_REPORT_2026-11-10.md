# N18 보고서 — 스크립트 명령 참조

2026-11-10 KST. AGENTS.md를 먼저 읽고 NightCoder 규칙을 적용했다. 현재 저장소·브랜치 `nc/rra-codex`에서만 작업했다.

## 구현

`docs/CLI_REFERENCE.md`에 `scripts/*.py` **21개 전부**를 정리했다. argparse 진입점은 20개이며 `render_rules_catalog.py`는 sys.argv 위치 인수 방식이다. `filter_board.py`, `golden_edge_eval.py`는 각각 위임 대상 `rag/board.py`, `rag/score.py`의 실제 argparse 정의까지 읽었다. 스크립트를 실행하거나 import하거나 `--help`로 조사하지 않았다.

각 스크립트의 목적, 모든 명시적 인수·옵션의 이름/기본값/설명, 공통 도움말, 출력 파일·임시 저장소, 실제 모델 필요 여부와 PowerShell 가상환경 Python 예시를 적었다. E4 → E6 → E5 → E7 → E8 순서와 직접 파일 의존/수동 설정 전달/독립 입력을 별도 표와 명령으로 구분했다. 기본 개발 경로는 Chroma다. memvid 전용 두 진단은 보존된 CLI를 기록하되 개발 실행 대상에서 제외했다.

소스와 기존 문서의 차이·보충은 참조 문서 마지막 표에 기록했다. E4~E8 및 MODELS의 옵션 이름 불일치는 발견하지 못했으며 다음 의미 차이를 명시했다.

- E5의 “같은 골든셋” 설명과 달리 compare_embedders 기본 입력은 v1 두 세트, v2 예시 입력은 별도 v2 세트다.
- E4/E5 compare_embedders는 split 제한 없이 confirm 요약도 생성한다. 선택된 한 설정만 confirm 계산하도록 강제하는 옵션은 없다(후속 연결 필요).
- E6의 calibration 입력에는 전체 split 행이 있지만 v2 `--split compare` 출력에는 confirm 행이 없다.
- E7 예시 alpha 격자 0/.25/.5/.75/1과 소스 기본값 .25/.5/.75를 구분했다. confirm 명령은 E6 gate를 읽지 않고 자체 compare 절대 경계를 보정한다.
- E8 mode별 예시와 기본 all을 구분했다. E8은 앞 단계의 보고서나 지시문·청크 옵션을 입력받지 않는다.
- MODELS 명령의 Python 표기를 요청된 가상환경 실행 파일로 통일했다. revision 문자열은 argparse에서 40자리로 제한하는 것이 아니라 조회 결과 SHA를 검증한다.

추가로 probe_memvid 소스 docstring의 docs/evidence 출력 예시는 현재 결과물 규칙에 맞게 .runs 예시로 적었다. 시스템 임시 디렉터리를 쓰는 기존 진단/lex/stress의 위치 제한은 코드 변경 없이 후속 연결 필요로 기록했다. Chroma에 없는 memvid 버전 발행·롤백·해시 manifest는 “Chroma 경로에 없음”으로 기록했다.

지정 문서 두 개만 작성했다. 코드·시험·기대값·skip·KNOWN_DEBT·README·data/profiles·frozen masking 및 금지 파일은 수정하지 않았다. 새 모듈·의존성·가짜 구현은 없다. 네트워크·모델 다운로드·실제 모델·LLM·LangSmith·패키지 설치·push·원격/브랜치 설정 변경은 수행하지 않았다.

## 시험

전체 시험 시작 명령:

```powershell
python -m pytest -q -p no:cacheprovider --basetemp=.runs/n18/full-tmp --junitxml=.runs/n18/full-pytest.xml
```

**tests not run here: Python is not available on PATH and .venv/Scripts/python.exe does not exist.**

이 환경에서 시험 미실행: python 명령이 CommandNotFoundException으로 시작되지 않았다. Get-Command python,py,pytest는 명령을 찾지 못했고 가상환경 Python 경로도 없다. 최종 시험 실행 **0건**; passed/failed/error/skipped는 집계 불가(미실행)다. JUnit은 생성되지 않았다. 설치하거나 시험을 변경하지 않았다. 전체 시험 판정은 NightCoder 게이트가 한다.

보호 파일 기준은 기존 `.runs/n10/protected-after.json`의 Expected SHA-256이다. 작업 전 18/18이 기준과 동일했다. 증거는 `.runs/n18/protected-before.json`이다. 정적 문서 점검과 작업 후 해시는 아래 마무리에 기록한다.

## 입증하지 못한 것 / 미검증

CLI 예시의 런타임 성공, 모델/패키지/캐시 가용성, 실제 모델 품질은 미검증이다. 실제 모델 명령은 대표용 참조만 남겼다. 기존 학습 문서의 시험 수를 이번 시험 수로 재사용하지 않았다. 보호 기준 manifest 자체의 생성 정당성은 미검증이며 기존 기준에 대한 파일 해시 일치만 확인한다. 엄격한 단일 confirm 실행 강제 및 E6 gate의 후속 평가 import는 현행 CLI가 제공하지 않아 후속 연결 필요다.

## 마무리 확인

PowerShell로 소스의 add_argument 문자열과 각 스크립트 문서 절을 정적 대조했다. 21/21개 절이 존재하고 명시적 인수·옵션 130개 항목의 이름 누락은 0개다. 이 점검은 옵션 이름 포함 여부 확인이며 실행 시험이나 기본값 의미 자동 검증은 아니다. 기본값·출력 위치·실제 호출 관계는 소스 문맥을 읽어 대조했다. 링크 대상 존재 여부도 확인했다. 근거는 `.runs/n18/cli-coverage.json`, `.runs/n18/link-check.json`이다.
