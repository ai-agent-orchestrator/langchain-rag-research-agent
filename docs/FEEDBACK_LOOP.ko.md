# 골든룰 피드백 루프 사용법 (v0)

골든룰과 골든셋을 **데이터 파일로만 고치면서** 결과를 보고 다시 돌리는 방법이다. 코드는 고치지 않는다.
규칙 내용은 [GOLDEN_RULES.ko.md](GOLDEN_RULES.ko.md). 점수기는 규칙 기반 v0이며 보정되지 않았다.

## 파일 두 개

| 파일 | 무엇 | 누가 고치나 |
| --- | --- | --- |
| `data/golden_rules/research_v1.json` | 규칙: 인과·상관·트렌드·수치·누가언제·클리셰·가중치 규칙, 분야 묶음, 가중치 | 결과를 보고 표현·가중치 조정 |
| `data/golden_sets/<이름>.json` | 시험지: 초안(`draft`), 꼭 남길 문장(`must_keep`), 버릴 문장(`cliche`) | 대표가 초안에서 문장을 골라 **그대로 복사** |

공개 저장소에 올리는 골든셋은 **합성 자료만**이다. 실제 자료로 만든 골든셋은 `.runs/`처럼 커밋하지 않는 곳에 두거나 비공개로 관리한다.

## 규칙 구성 (현재)

공통 150개(인과 35, 상관 25, 트렌드 20, 수치 20, 누가·언제 10, 클리셰 20, 가중치 20) + 분야 묶음 50개(`macro`, `geopolitics`, `tech`, `defense`, `legal` 각 10~12). 전체 목록은 [GOLDEN_RULES_CATALOG.ko.md](GOLDEN_RULES_CATALOG.ko.md)(JSON에서 자동 생성).

- **클리셰 정책:** 클리셰 표현이 있어도 같은 문장에 수치·인과·기둥·묶음 신호가 있으면 감점하지 않고 "검토"로만 표시한다. 맥락은 말투만으로 정해지지 않는다.
- **법률:** `--packs legal`로 인과 35개 위에 법률 표지 10개(L1~L10)를 얹는다. 문장 보존용 표지일 뿐 법리 판단은 하지 않는다.

## 집중 키워드 (최대 5개)

```bash
# 직접 입력: key player, 시점, 무엇이든. 숫자로 상대 가중치
python scripts/golden_edge_eval.py --set data/golden_sets/macro_synthetic_v1.json --packs macro --focus 금리:2 가계부채 2025년
# 자동 빈도: N번 이상 나온 의미 있는 단어로 남은 자리를 채움 (직접 입력이 우선)
python scripts/golden_edge_eval.py --set data/golden_sets/legal_synthetic_v1.json --packs legal --focus 을 --auto-focus 2
```

보고서에 **집중 브리프**가 추가된다: 키워드가 든 문장만 원문 그대로 강조해 보여 주고, 항상 보호 문장은 단서로 남기고, 나머지는 **생략하되 번호를 남긴다**. 키워드는 단어 단위로 맞춘다(한 글자 이름 "을"은 "을은·을에게"에 맞고 "반환을"에는 안 맞음). 집중 키워드에 안 걸린 중요한 문장(예: 금액 문장)도 생략될 수 있으니 생략 번호를 확인한다.

## 한 바퀴

```bash
python scripts/golden_edge_eval.py --set data/golden_sets/macro_synthetic_v1.json --packs macro
```

1. **보기:** 보고서의 지표와 순위표를 본다.
   - `keep_recall_at_k`: 꼭 남길 문장이 상위권(보존 개수만큼)에 든 비율. 1.0이 목표.
   - `cliche_in_bottom`: 버릴 문장이 하위권에 깔린 비율. 1.0이 목표.
   - `✗놓침`: 남길 문장인데 상위권 밖. `▲과대`: 목록에 없는데 상위권 안.
   - 각 문장의 **이유** 칸이 어떤 규칙에 걸렸는지 보여 준다(예: `인과8,23`, `pack:macro`, `수치3`).
2. **고치기 (한 번에 하나만):**
   - 놓친 문장이 있으면 그 문장의 표현을 규칙 파일의 `cues`에 추가한다.
   - 과대평가된 문장이 있으면 잘못 걸린 표현을 빼거나, 그 문장이 사실 남길 문장이면 골든셋에 추가한다.
   - 가중치(`weights`)는 표현을 다 고친 뒤에 조정한다.
3. **다시 돌리기:** 보고서 아래 "지난 실행과 비교"에 바뀐 것(rules / golden set / packs)과 지표 변화(좋아짐·같음·나빠짐)가 나온다. 두 가지 이상을 한 번에 바꾸면 경고가 뜬다.

실행 기록은 `.runs/edge_eval_history.jsonl`(커밋하지 않음)에 쌓이고, 최근 보고서는 `.runs/last_report.md`다. 규칙 파일을 고칠 때마다 `rule_version`(파일 해시)이 바뀌므로 어떤 버전의 결과인지 항상 구분된다.

## 실제 첫 루프 기록 (합성 예시)

- 1회차: `keep_recall_at_k` 0.857, 평균 순위 4.71. "명목 임금은 늘었지만 ... 실질 임금은 감소했다"를 놓침(상충 결과 신호 "늘었지만"이 규칙에 없었음). "금리는 3.0%에서 3.5%로 0.5%p 올랐다"가 과대평가.
- 수정: 인과 14번(상충 결과) `cues`에 "늘었지만", "줄었지만" 추가.
- 2회차: 평균 순위 4.71 → 4.57(좋아짐), recall은 같음.

합성 예시 12문장의 결과일 뿐이며 품질을 증명하지 않는다.

## 한계 (v0)

- 신호 표현 일치만 본다. 숨은 원인·결과(인과 8~11, 15~18, 25~27, 29)는 표현 없이 쓰이면 못 잡는다. 모델 검토는 아직 없다.
- 희소성과 분류 우선순위 점수는 0이다(배경 코퍼스·분류기 없음).
- 문장 쌍 보호(원인·결과를 함께 남기기)는 아직 점수에만 반영하지 않았고, Token Diet 구현 때 넣는다.
- 문장 분할은 마침표 기준의 단순 분할이다.
