# R18 — 법률 도메인 필터 뼈대

## 구현

`guard/legal_filter.py`에 순수 Python `LegalFilter`와 버전 `legal-filter/1`,
`MATURITY = "incubating"`을 추가했다. 기존 DomainFilter 계약의 실제 InputDecision·Issue·Verdict를 사용한다.
공백 입력 차단, 형사/가사/민사/기타 키워드 분기, 근거 없는 조문·폐지 조문·날짜 순서 검사와
`법률 자문이 아닙니다` 고지를 구현했다. 등록은 모듈 import 시 register와 공유 BUILTINS에 반영한다.
기존 GuardrailRunner의 명시적 domain 옵션으로 선택하며 기본 동작은 변경하지 않았다.

수정 파일은 다음 네 개뿐이다.

- `src/rag_research_agent/guard/legal_filter.py` (신규)
- `tests/test_legal_filter.py` (신규)
- `docs/DOMAIN_FILTERS.ko.md`
- `docs/R18_REPORT_2026-11-11.md` (본 보고서)

## 시험

합성 사례만으로 공통 등록 계약을 research·legal에 적용했다. 키워드 분기와 혼합 우선순위,
공백 차단, 조문 정확 일치·중복 개수, 폐지/삭제/구법의 앞뒤 표기·절별 격리,
날짜 형식 정규화·역순·부분 인용·반복·잘못된 날짜, 다중 오류, 빈 근거·빈 답변과 고지를 검사한다.
실제 GuardrailRunner·LegalFilter·ResearchFilter·GuidanceReply를 사용하여 같은 그래프의 필터 교체,
재시도 후 통과, 예산 소진 시 안전 종료, screen 차단, domain 미설정 기본 경로도 검사한다.
주입하는 비동기 RAG 함수는 고정 합성 답변과 근거를 반환한다. 대체 그래프·대체 필터·모델을 만들지 않았다.

전체 시험 명령(기존 시험·기대값·skip 변경 없음):

```powershell
python -m pytest -q -p no:cacheprovider --basetemp=.runs/r18/full-tmp --junitxml=.runs/r18/full-pytest.xml
```

이 환경에서 시험 미실행: python 명령을 찾지 못하여 전체 시험을 시작할 수 없었다.
python·py·pytest가 PATH에 없고 저장소 .venv-python·.venv-cache에서도 python.exe를 찾지 못했다.
실행 0건이며 passed/failed/error/skipped는 미실행으로 집계 불가다. 신규 시험도 통과로 주장하지 않는다.
기록은 `.runs/r18/test-attempt.txt`이고 JUnit 파일은 생성되지 않았다. NightCoder 게이트 판정이 필요하다.

## 설계 대비 차이

중앙 `domain_filter.py`는 files 범위 밖이므로 수정하지 않았다. 법률 모듈을 명시적으로 import한 뒤
get_filter("legal")를 호출해야 한다. 최초 호출 자동 로딩용 중앙 BUILTINS 정적 항목 추가는 **후속 연결 필요**다.
현재 모듈의 import 시점 등록은 시험에서 확인하도록 정의했다.

날짜는 유효한 ISO/Korean 전체 날짜만 인식한다. 공통 날짜의 첫 언급 순서를 근거 튜플·본문 순서와 비교한다.
사건명과 날짜의 대응, 없는 날짜·누락 날짜, 연도만 있는 표현, 회고 표현을 의미적으로 검증하지 않는다.
폐지 상태는 문장/절 안에서 적용하며 법령명·항·호·시행일·부정문을 구별하지 않는다.
동일 조문 번호의 다른 법령, 한 절에 섞인 조문, 정당한 구법 설명 등에서 오탐 가능성이 있다.

RESEARCH_GRAPH_DESIGN의 시차 로그 리듀서·검증 조항 강제 주입·사건 유형별 검색 경로 격리는
이번 뼈대에 포함하지 않았다. branch는 기존 그래프 State의 값이며 별도 검색 경로 연결은 **후속 연결 필요**다.
기존 classify는 짧은 입력을 smalltalk로 끝내므로 빈 입력 screen 시험만 research 라우터를 주입한다.
기본 라우터를 변경하지 않았다. 모듈 간 새 import는 없고 guard 내부 계약만 사용하여 KNOWN_DEBT를 늘리지 않았다.
