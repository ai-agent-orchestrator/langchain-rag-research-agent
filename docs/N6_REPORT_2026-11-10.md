# N6 검색 장애 서킷브레이커

2026-11-10 KST · 작성: Claude (브랜치 `claude/n6-n7-n11`) · NightCoder 명세 `rra-n6-retrieval-breaker`

## 구현
`retrieve/breaker.py`, 표준 라이브러리만 사용, MATURITY=incubating.
- 상태 closed / open / half_open. 연속 `RetrievalUnavailable` n회(기본 5)에 open, open 동안 백엔드를 부르지 않고 즉시 `CircuitOpen`.
- `CircuitOpen`은 `RetrievalUnavailable`의 하위 클래스라 기존 503 매핑과 "무근거로 바꾸지 않음" 규칙이 그대로 적용된다.
- 쿨다운(기본 30초) 뒤 half_open에서 시험 호출 1회만 통과. 성공하면 closed, 실패하면 새 쿨다운으로 open.
- `RetrievalUnavailable`이 아닌 예외는 그대로 올리고 계수하지 않는다. half_open 시험 중이었다면 시험 자리만 풀어 준다.
- 시계 주입, 스레드 안전. 상태 변화 콜백은 이전·현재 상태와 횟수만 받는다(질의·메시지 없음).

## 시험
`tests/test_retrieval_breaker.py` 13개: 임계값 open과 즉시 실패(백엔드 미호출), 성공 시 계수 초기화, 다른 예외 비계수,
쿨다운 경계(9.999초 open, 10초 half_open), half_open 실패 후 쿨다운 재시작, half_open 동시 호출 1회만 통과,
시험 중 프로그래밍 오류 후 자리 해제, 8스레드 400회 정확 계수, 콜백 필드, 잘못된 설정 거절.
Linux 작업 환경에서 10회 반복 모두 13 passed.

## 연결(하지 않음, 제안)
- 위치 제안: `rag/guidance.py`의 `search_sync` 안에서 `self.library.search(...)`를 `breaker.call(...)`로 감싸기.
  검색 출처 불일치(provenance mismatch)도 `RetrievalUnavailable`이라 계수에 들어가는 점은 결정이 필요하다(장애가 아닌 데이터 문제일 수 있음).
- 가드레일 그래프(`rag/guardrail_graph.py`)는 `CircuitOpen`도 일시 장애로 보고 `max_loops`까지 다시 시도한다.
  open 동안의 재시도는 즉시 실패하므로 비용은 들지 않지만, 쿨다운보다 짧은 재시도는 의미가 없다는 점을 연결 시 고려한다.
