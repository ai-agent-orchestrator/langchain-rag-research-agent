## 2. 핵심 지적과 보완안 (심각도 순)

### 🔴 치명 — 고치지 않으면 동작하지 않음

**F2. 노브① "유사도 0.85 이상"을 그대로 쓰면 E5에서 근거가 전부 거절됨**
- 근거: legal-intake B02b 실측. E5에서 정답 문서의 1위 점수는 **0.79~0.80대**입니다. 비교 세트 근거 질문의 최저 top1은 0.7868이고, Q22 정답 1위는 0.8037이었습니다. 정답과 오답의 간격도 0.0136밖에 되지 않았습니다.
- 문제: 코사인 점수의 분포는 모델마다 다릅니다. 0.85는 E5에서는 "전부 거절", 다른 모델에서는 "전부 통과"일 수 있습니다. 기존 v0.2도 E6 학습 트랙에서 "고정 0.8이 안 되는 이유"를 짚었고, `RelevanceRule`에 고정 기본값을 두지 않았습니다.
- 보완:
  - 노브 위치(0~1)를 **모델 identity별로 골든셋 compare 세트에서 보정한 임계값 구간**에 매핑합니다.
    - Low 끝 = 근거 질문을 거의 다 살리는 τ
    - High 끝 = 무근거 오수용 0을 지키는 가장 보수적인 τ
  - 절대값 τ_abs와 간격 τ_gap 규칙(B02b 방식)을 함께 씁니다.
  - "0.85"는 예시 값으로만 문서에 남깁니다.

**F12. 두 노브가 독립적이지 않음: 노브①을 올리면 노브②가 지킬 엣지가 사라짐**
- 문제: 노브①의 임계값 게이트가 먼저 후보를 자르기 때문에, 노브②가 아무리 높아도 이미 잘린 골든 프레이즈는 되살릴 수 없습니다. "독립 조절"이라는 요구(R20)가 실제로는 깨집니다.
- 보완: **보호 후보 경로**를 따로 둡니다.
  - 골든 키워드 사전 일치 구간과 `Constraint_Guardrail` 구간은 노브① 게이트를 거치지 않고 후보에 합류합니다. 다만 노브②가 일정 값(제안 0.5) 이상일 때만입니다.
  - 노브①은 "일반 후보의 순도", 노브②는 "보호 후보의 생존과 배치"를 맡아서 역할이 겹치지 않습니다.
  - 다이어그램 02·04에 이 경로를 그립니다.

**F7. Token_Diet가 무한 반복하거나 조용히 자를 수 있음**
- 문제: 보호 항목만으로 예산을 넘으면 감량할 대상이 없어서 계속 돕니다. 반대로 끝을 잘라버리면 엣지가 조용히 사라집니다.
- 보완:
  - 반복 상한을 둡니다(제안: 온톨로지 분류 수 + 1회).
  - 보호 항목만 남았는데도 예산을 넘으면 **`BUDGET_PROTECTED_OVERFLOW`로 멈추고 보고**합니다. 사람이 예산을 늘리거나 보호 항목을 해제합니다.
  - 문자열 절단은 금지합니다.
  - 매 감량 회차에 무엇을 뺐는지 trace에 남깁니다.

**F1. 외부 전송 충돌: OpenAI 임베딩·Cohere Rerank·LangSmith·Claude 비교**
- 문제:
  - 원문은 이 네 가지를 기본처럼 씁니다. 그러나 기존 원칙은 외부 전송 0이 기본입니다.
  - 드래프트에는 사업 아이디어와 개인 소송 정보가 들어 있습니다.
  - 소송·증거 모드에서 실제 자료가 외부로 나가면 되돌릴 수 없습니다.
- 보완:
  - 모든 외부 부품을 **공급자 인터페이스** 뒤에 둡니다(`Embedder`, `Reranker`, `Tracer`, `Comparator`). 기본 구현은 로컬입니다: E5, BGE-Reranker, 로컬 JSONL trace.
  - 외부 공급자는 **실행 단위로 명시해서 켤 때만** 씁니다. 공유 마스킹을 통과한 텍스트만 보내고, 실행 기록에 전송 사실을 남깁니다.
  - **하드 규칙:** `litigation_evidence` 프리셋에서는 외부 공급자를 켜는 설정 자체를 거부합니다.
  - 정책 확정은 대표 결정 D1입니다.

### 🟠 중대 — 품질·보안 목표를 못 지킴

**F3. 리랭커는 클리셰 필터가 아님**
- 문제: Cohere Rerank와 BGE-Reranker는 "질문과의 관련도"를 매기는 모델입니다. 진부한 문장도 질문과 관련 있으면 상위에 올라갑니다. 원문은 "리랭커 단계에서 진부한 문장이 걸러진다"고 썼지만 그렇게 동작하지 않습니다.
- 보완: **엣지 점수를 리랭커와 분리한 별도 신호**로 만듭니다. 구성요소는 6개이고 모두 청크마다 기록합니다.

  | 구성요소 | 측정 |
  | --- | --- |
  | 희소성 | 배경 코퍼스 대비 IDF. 흔한 단어가 많으면 낮음 |
  | 골든 프레이즈 | 대표가 정의한 골든 키워드·용어 사전 일치 |
  | 구체성 | 숫자·날짜·금액·좌표·ID·직접 인용 포함 |
  | 인과·반전 표지 | "따라서·때문에·반면·하지만" 등 |
  | 온톨로지 우선순위 | 분류별 사전 가중치 |
  | 클리셰 감점 | 진부 문장 예시 묶음과의 임베딩 유사도 |

  최종 점수 = `(1−w)·리랭커 관련도 + w·엣지 점수`이고, `w`가 노브②입니다. 구성요소 가중치는 쌍 데이터셋(R19)의 compare 세트로만 조정하고 버전으로 고정합니다.

**F5. 온톨로지 파서가 원문을 바꿀 위험**
- 문제: PydanticOutputParser로 "JSON으로 파싱"하면 LLM이 문장을 다듬거나 합쳐서 원문 엣지가 바뀝니다. 40쪽을 한 번에 넣으면 비용이 크고 실패 범위도 커집니다.
- 보완:
  - 파서 출력은 `{segment_id, label, confidence, rationale_code}`만 담습니다. **본문은 원문 구간의 오프셋으로 참조**하고 LLM이 쓴 텍스트를 쓰지 않습니다.
  - 처리 순서는 이렇습니다.
    1. 정규식으로 결정적 표지를 먼저 분류합니다(예: "제약:", "TODO", 숫자 목표).
    2. 남은 구간을 세그먼트 묶음 단위로 로컬 Llama에 넣어 라벨을 붙입니다.
    3. 형식이 틀리거나 신뢰도가 낮은 구간은 `Unclassified`로 **보존**합니다. 삭제하지 않습니다.
  - 평가: 사람 라벨과의 일치율을 분류별로 개수로 보고합니다.

**F15. 드래프트 자체에 주입 문장이 있을 수 있음 (간접 프롬프트 주입)**
- 문제: AI와 나눈 대화 드래프트에는 "앞의 지시를 무시하고…" 같은 지시문이 자연스럽게 들어 있습니다. 그대로 Llama 인풋에 넣으면 백본 에이전트가 그 지시를 따를 수 있습니다.
- 보완:
  - 공유 `check_input_policy`를 **문서 프로필**로 구간마다 호출합니다.
  - 차단 구간은 인풋에서 빼고 "제외 구간 목록"으로 보고합니다.
  - 사용자 세션 위험 점수에는 넣지 않습니다(v0.2 규칙 유지, 오탐으로 잠기는 것 방지).
  - 최종 인풋은 **지시 블록과 자료 블록을 분리**합니다. 자료 블록은 "데이터로만 취급"하라고 표시합니다.

**F14. 마스킹 공유 방식이 정해지지 않음**
- 현황: 이 저장소의 `guard/masking.py`는 학습용 패턴 3개(주민번호·이메일·전화)뿐이고, 파일 안에 "S1 `mask_personal_data`가 아니다"라고 적혀 있습니다. legal-intake의 `mask_personal_data`는 아직 미구현입니다(인수인계 문서 4절).
- 보완:
  - **정본은 legal-intake** 하나입니다.
  - 이 저장소는 `Masker` · `InputPolicy` 프로토콜만 정의하고, 시험에는 가짜 구현을 씁니다.
  - legal-intake의 action이 완성되면 그 보안 모듈을 설치 가능한 하위 패키지로 분리합니다. 이 저장소는 그것을 의존성으로 씁니다(D3).
  - 그때까지 `guard/masking.py`는 **동결**합니다. 실제 자료 적재도 금지합니다.
  - `masking_version`을 색인 manifest에 기록합니다. 마스킹이 바뀌면 재색인합니다.

**F16. 공개 저장소에 개인 자료가 들어갈 위험**
- 문제: 실제 드래프트와 원문 요구사항 3페이지에 개인 소송 정보가 있습니다. 소송 모드는 본질적으로 실제 사건 자료를 다룹니다.
- 보완:
  - 공개 저장소에는 **합성 드래프트·합성 사건만** 둡니다.
  - 실제 자료는 `.gitignore`된 로컬 폴더에서만 처리합니다. 결과 증거 파일에는 원문·벡터를 넣지 않습니다.
  - 커밋 전 검사(시험)로 실제 자료 경로와 PII 패턴을 막습니다.
  - 확정은 D5입니다.

### 🟡 보통 — 모호해서 구현자가 임의로 정하게 됨

**F4. "유실 없는 압축", "단 1%도 깎지 않는", "완벽한 결과물"**
- 보장할 수 없는 표현입니다. 대신 측정 지표로 바꿉니다(3절 완료 기준).
  - 보호 항목 탈락 0(하드)
  - 골든 엣지 회수율 n/총수
  - 원문에 없는 숫자·ID 0

**F6. 무지성 청킹 금지 vs E5 512토큰 한계**
- 처리 방법:
  1. 구조 경계를 우선합니다: 제목, 대화 턴(대표/AI), 문단, 목록 항목.
  2. 구조 단위가 512토큰을 넘으면 **문장 경계에서만** 하위 분할하고 `parent_segment_id`를 유지합니다.
  3. 조립 단계에서는 부모 단위로 다시 묶을 수 있게 합니다.
- 토큰은 E5 토크나이저로 셉니다(색인용). 예산 검사(Token_Check)는 **백본 모델 토크나이저**로 따로 셉니다.

**F8. AgentState 보완**
- 원문 5필드는 이름 그대로 유지합니다: `raw_draft` · `ontology_mapped` · `filtered_context` · `token_count` · `final_prompt_input`.
- 필수로 추가하는 필드:
  - 식별·설정: `request_id`, `task`, `knobs`, `preset`
  - 처리 결과: `segments`, `causal_links`, `candidates`, `edge_scores`, `protected_ids`, `excluded_segments`
  - 진행 상태: `diet_rounds`, `status`
  - 버전: `versions`(chunker, masking, policy, index, prompt, rule, golden)
- 요청마다 새 상태를 씁니다. 공유 가변 상태는 금지합니다.

**F9. 인과관계 그래프의 정의**
- 링크 타입 4개:

  | 타입 | 뜻 |
  | --- | --- |
  | `causes` | 원인 → 결과 |
  | `supports` | 근거 → 주장 |
  | `contradicts` | 서로 반대 |
  | `supersedes` | 새 결정이 옛 결정을 대체 |

- 생성 규칙: 명시적 표지(정규식)와 인접 구간은 자동으로 만듭니다. LLM이 제안한 링크는 REVIEW 표시로만 둡니다.
- 감량 규칙: 링크로 묶인 쌍에서 한쪽만 남으면 "연결 끊김" 표시를 남깁니다. `supersedes`로 대체된 옛 결정은 현재 결정보다 뒤에 배치합니다. v0.2의 "폐기안이 현재 결정보다 앞서지 않음" 규칙과 같습니다.

**F10. 평가 기준: Claude 결과는 정답이 아님**
- 정답 기준은 **사람이 드래프트마다 표시한 "반드시 남길 구간" 목록**(골든 엣지)입니다.
- Claude 직접 요약은 비교 대상(기준선)의 하나입니다. 실행하면 드래프트가 외부로 나가므로 선택 실행입니다(D1).
- RunEval의 "엣지 단어 포함" 검사는 표면 단어 대신 **원문 구간 ID가 최종 인풋에 포함됐는지**로 판정합니다. 마스킹 치환과 동의어 때문에 단어 일치는 틀리기 쉽습니다.
- 비교할 기준선: ① 앞부분 자르기, ② 글자 수 청킹 RAG, ③ Llama에 원문 직접, ④ Claude 직접 요약(선택), ⑤ 이 파이프라인.

**F11. "노브 2개" 원칙과 숨은 파라미터**
- 사용자에게 보이는 값은 노브 2개와 프리셋뿐입니다.
- 나머지는 **버전으로 고정한 설정**이고 노브로 노출하지 않습니다: 토큰 예산(백본 모델 창), 보호 규칙, 점수 구성 가중치, k 범위, 감량 순서.
- 설정을 바꾸면 버전이 바뀌고, 평가 결과는 같은 버전끼리만 비교합니다.

**F13. 작업 설명(질문)이 없을 때 노브①의 의미**
- 원문의 "드래프트 통째 → 마스터 프롬프트" 모드에는 검색 질의가 없습니다.
- 보완: `task`가 없으면 노브①은 **각 구간과 그 구간이 속한 온톨로지 분류 중심 벡터의 유사도**로 동작합니다. 분류 안의 대표성을 거르는 용도입니다. trace에 모드를 기록합니다.

**F17. 백본 모델과 토큰 예산 미정**
- Llama 모델 ID·정밀도·서빙 방식은 legal-intake와 같이 대표 PC 사양으로 정합니다(Windows, RAM 16GB, RTX 5060 8GB).
- 토큰 예산 = 모델 창 − 지시 블록 − 출력 여유분으로 계산하는 설정값입니다.

**F18. LangSmith 원격 전송**
- 서빙: `serving_trace_guard()`로 업로드 0을 유지합니다. 환경변수가 켜져 있어도 같습니다(기존 코드 유지). 같은 스키마로 로컬 JSONL에 기록합니다.
- 실험: 합성 또는 마스킹 자료만, 허용 목록 필드만 원격으로 보냅니다.
- 원문의 "어떤 엣지 문장이 살아남았는지 시각화"는 문장 본문 대신 **구간 ID·분류·점수 구성요소**로 표시합니다. 본문 확인은 로컬 뷰어로 합니다.

**F20. 재사용 인터페이스**

| 함수 | 용도 |
| --- | --- |
| `build_brief(draft, task=None, knobs=None, preset=None) -> Brief` | 긴 드래프트 → 백본 인풋 |
| `search(query, collection, knobs=None) -> RetrievalResult` | 일반 검색(법률 검색·안내 근거) |
| `build_graph(...)` | LangGraph 서브그래프. 다른 에이전트 그래프에 끼워 쓰기 |

- 어댑터: LangChain `BaseRetriever`, CLI, 선택형 FastAPI 내부 라우터.
- `Brief`는 `final_prompt_input`, 포함 구간 ID, 제외 구간·사유, 버전, 상태를 담습니다.
