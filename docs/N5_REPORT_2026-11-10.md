# N5: BoundedWorker 부하·취소 시험

2026-11-10 KST. NightCoder 레인, 현재 저장소·브랜치에서 작업.

## 구현

`tests/test_bounded_worker_stress.py`에 실제 `BoundedWorker`와 실제
`ThreadPoolExecutor`를 사용하는 시험 4개를 추가했다. 생산 코드나 기존 시험은
수정하지 않았다. 스레드 작업은 Event로 종료를 제어하고 이벤트 루프의 상태
전이를 기다린다. timeout 시나리오의 응답 제한은 0.02초다. 다른 시간값
(상태 관찰 2초, 스레드 해제 3초)은 교착 시 시험을 끝내는 watchdog이며,
특정 시간 안에 얼마나 처리했는지로 성패를 결정하지 않는다.

| 시나리오 | 시험의 검증 내용 | 실행 결과 |
| --- | --- | --- |
| 동시 요청 폭주 | 동시성 3, 대기열 5, 요청 24. 실행 작업을 막은 상태에서 초과 16건의 `InferenceCapacityExceeded`, 허용 8건의 고유 결과, 종료 후 active/waiting 0 및 세마포어 허용량 3 복원, 후속 요청 성공 | 미실행 |
| 느린 작업 + 응답 timeout | 실제 작업 시작을 확인하고 응답 timeout을 관찰. 작업 해제 전 active 1·허용량 0 유지, 후속 1건 대기·추가 1건 거절. 해제 후 대기 요청 성공과 슬롯 복원 | 미실행 |
| 대량 취소 + 늦은 예외 | 실행 4건과 대기 12건을 만든 뒤 실행 4건 및 대기 6건 취소. 실제 작업 해제 전 슬롯 유지, 나머지 대기 6건 성공, 슬롯 전량 복원. 취소된 호출의 실제 작업은 늦게 RuntimeError 발생. shutdown·이벤트 루프 처리·GC 뒤 루프 예외 진단 및 Python 경고 부재 검사 | 미실행 |
| 진행 중 aclose | 실행 1건·대기 1건 중 닫기 시작. 실행 작업 해제 전 close 미완료, 새 요청 거절. 실행 작업은 정상 결과, 대기 요청은 closed 예외로 끝나고 실행되지 않음. close 완료 및 슬롯 복원 | 미실행 |

슬롯 누수를 active 값만으로 놓치지 않도록 active/waiting과 실제 세마포어
잔여 허용량을 함께 검사한다. private 상태에 대한 의존은 시험에만 있다.
실패 경로에서도 Event를 해제하고 호출 태스크를 회수한 다음 worker를 닫는다.

## 발견 사항 및 미검증

소스 검토상 aclose는 `_closed`를 먼저 설정하고 실제 executor 종료를 기다린다.
이미 실행 중인 호출은 작업 결과를 받으며, 대기 중 호출은 슬롯을 얻은 뒤
closed 상태를 검사하여 실행 없이 실패한다. 위 시험은 이 동작을 명시한다.
실제 실행에서 누수나 이상 동작이 있는지는 **미검증**이다. 관찰한 실패에
기대값을 맞추거나 생산 코드를 수정하지 않았다. 수 초 내 완료 여부도 미검증이다.
네트워크·모델·LLM·임베더·저장소 API를 사용하지 않는 동시성 시험이다.

기존 추적 파일 357개의 작업 전후 SHA-256은 모두 동일했다. 비교 증거는
`.runs/n5/tracked-before.json`과 `.runs/n5/tracked-after.json`에 기록했다
(.env 계열은 읽지 않고 제외).
기존 파일의 HEAD 대비 diff도 없어 data/profiles, frozen masking, 기존 시험,
KNOWN_DEBT, 금지 생산 파일과 README를 변경하지 않았다.
보호 파일 18개의 별도 기준 manifest는 이 저장소에서 찾지 못했으므로,
외부 기준과의 18개 개별 대조는 **미검증**이다.
변경 범위는 지정된 신규 시험과 이 보고서 두 파일뿐이다.
push·원격/브랜치 설정 변경·새 패키지 설치는 하지 않았다.
