# R47 — 체크포인터 기반 리서치 세션

## 구현

- `ResearchSession(thread_id, checkpointer, max_items=50)`를 선택적으로 생성하고
  `run(question, checklist, search=..., cfg=...)`로 같은 주제의 후속 질문을 실행한다.
  반환형은 기존 `ResearchResult`다. 질문·검색 본문은 호출자가 이미 마스킹해야 한다.
- 실제 LangGraph 체크포인터가 thread별 sources·claims·metrics·relations를 보관한다.
  새 세션 객체도 같은 saver와 thread로 이어 간다. 모델·저장소를 로드하지 않으며
  `SearchFn`에는 기존 Chroma 어댑터를 주입할 수 있다. memvid 의존성은 추가하지 않았다.
- 기존 span 검증을 통과한 claims와 그 sources만 재사용한다. 계획의 필수 지표에서
  coverage가 부족한 지표만 검색 질의에 넣고, 기존 관점 분기·gap 재시도·검수 예산을 사용한다.
  지표 계획이 비어 있으면 검색을 생략할 근거가 없어 일반 검색을 실행한다.
- 각 실행은 새 비용·재작성 예산으로 기존 실제 리서치 그래프를 실행한다.
  planner/extractor/writer/verifier/refiner 및 모델 인터페이스는 그래프에 주입한다.
  기본 `ResearchRunner`, `ResearchConfig`, 서비스 경로는 변경하지 않았다.
- 체크포인트 이벤트에 `thread_id`, `reused_sources`, `saved_shadow_tokens`,
  `estimated`, `shadow_tokens`, `path`, 기존 `end_type`을 기록한다.
  절약량은 재추출하지 않은 출처 본문의 `est_tokens` 추정치이며 실제 청구 토큰이나
  전체 실행 비용 차이가 아니다. 최신 이벤트는 `session.last_event`로도 확인한다.
- 최신 체크포인트의 메시지·이벤트·sources·claims·metrics·relations는 각각 기본 50개로
  제한하고 오래된 항목부터 제거한다. 제거된 출처·claim을 참조하는 근거도 제거한다.
  반환 보고서는 해당 실행의 전체 결과이며 제한은 다음 실행에 넘길 기억에 적용된다.

## 시험

신규 시험은 실제 그래프·MemorySaver·로컬 규칙 검색을 사용하는 **경로 시험**이다.
재구성 후 재사용/검색 감소, 누락 지표 질의, thread 격리, 기본 50개 claim 제한,
오래된 메시지·근거 제거와 참조 정합성, 순차/병렬 플러그인 전달, 잘못된 인자,
체크포인터 누락, injection 배제, 검색 실패 시 이전 기억 보존을 정의했다.
실제 모델 품질·검색 정확도 평가 수치는 산출하지 않았다.

실행 시도:

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_research_session.py -q
.\.venv\Scripts\python.exe -m pytest -q
```

두 명령 모두 `No module named pytest`로 시험 수집 전에 종료했다.
**tests not run here: repository .venv Python runs, but pytest is not installed.**
이 환경에서 시험 미실행: PATH의 python/py는 없고, 저장소의 Python 3.15.2에는 pytest가 없다.
설치 금지 규칙에 따라 새 패키지는 설치하지 않았다.
최종 시험 수: passed/failed/error/skipped 모두 집계 불가(수집·실행 0건).
NightCoder에서 위 전체 시험 명령으로 판정해야 한다.
신규 두 Python 파일의 AST 구문 검사와 `git diff --check`는 통과했다.

보호 확인: 기존 tests 전체, data/profiles, 명시된 금지 소스 3개, README 총 141개를 확인했다.
Git clean 필터를 적용한 내용은 HEAD와 동일하다. Windows CRLF 때문에 원시 파일 SHA-256은
일부 Git blob의 SHA-256과 다르므로 이를 동일하다고 보고하지 않는다.
작업 파일의 SHA-256과 비교 내역은 `.runs/r47/protected-sha256.json`에 기록했다.
별도 보호 18개 기준 manifest는 이 저장소에서 확인하지 못해 그 기준과의 일치는 **미검증**이다.
기존 시험 기대값·skip·KNOWN_DEBT·금지 파일은 수정하지 않았다.

## 설계 대비 차이

- 변경 허용 범위를 지키기 위해 기존 그래프/관측 모듈을 수정하지 않고 세션용 외부
  StateGraph와 실행별 MemorySaver로 조합했다. 기존 runner의 내부 결과/직렬화 어댑터를
  재사용하므로 해당 내부 계약 변경 시 함께 점검해야 한다.
- 사람의 계획 승인 interrupt와 HTTP/UI·보드 JSONL 연결은 **후속 연결 필요**다.
  세션에서는 `review_plan=True`를 명확한 오류로 거절하며 기존 ResearchRunner API를 안내한다.
- 동일 thread는 같은 주제·코퍼스·접근 권한을 뜻한다. 의미 기반 주제 전환 판정은 하지 않는다.
  코퍼스·권한·주제 변경 시 호출자가 새 thread를 사용해야 한다.
- 트리밍은 최신 상태의 항목 수 제한이다. saver의 과거 체크포인트 보존 정책이나
  단일 긴 메시지의 문자 수, 동시 실행 잠금은 구현하지 않았다.

## 미검증

실행 시험 전부, 실제 Chroma 검색, 영속 saver 재시작, 실제 모델·토큰 절약·품질,
동일 thread의 동시 호출은 미검증이다. 모델·네트워크 호출·다운로드는 실행하지 않았다.
실제 모델 실행용 통합 CLI는 이 변경 범위에 없어 **후속 연결 필요**다.
대표의 오프라인 주입 모델/Chroma 실행 진입점이 마련되면 별도 검증해야 한다.
원격·브랜치 설정 변경, push는 하지 않는다.
