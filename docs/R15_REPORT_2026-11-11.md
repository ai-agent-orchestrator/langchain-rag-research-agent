# R15 잡음 문서 내성 — refine 옵션

## 구현

`ResearchConfig.drop_generic: bool = False`를 마지막 필드로 추가했다. 기본 설정에서는 기존 추출 입력과 로그를 유지한다. 켜면 refine에서 주입 문서 검사를 먼저 하고, 빈 줄로 구분한 문단별로 길이 6자 이상 문장을 검사한다. 기존 `CLICHE_CUES`가 들어간 문장이 절반 이상이고 숫자·인과·조건 표현이 없는 문단을 추출 입력에서 제외한다. 인과·조건 판정은 기존 `kind_of`를 재사용하며, 숫자는 단위 유무와 무관하게 보존한다. 별도 모델·패키지·저장소 의존성은 추가하지 않았다.

로그는 `REFINE:DROP_GENERIC:<문단 수>` 코드만 추가한다. 주입으로 버린 문서는 이 수에 포함하지 않는다. 문서 전체가 일반론이면 pending에서 제거한다. 일부 문단만 버릴 때는 해당 위치를 같은 길이의 공백으로 바꾸고 줄바꿈을 보존한다. 따라서 남은 Claim의 span은 원래 SourceRef에 대해 검증할 수 있다. 원래 sources는 기존 누적·감사 계약을 유지한다. 일반론은 추출용 pending 및 claims/metrics/relations에 들어가지 않는다. retrieve_gap도 같은 refine을 통과한다.

## 시험

신규 `tests/test_research_noise.py`는 실제 ResearchRunner/LangGraph, keyword_search, rule extractor, core dataclass를 사용한다. 대체 그래프나 가짜 저장소를 만들지 않았다. 총 13개 시험 항목(매개변수 확장 포함)을 작성했다.

- 잡음 문서 30개와 근거 문서를 모두 검색하도록 k를 늘린 경로: 잡음 claim 감소, 필수 지표·인과·조건 보존, 보고서와 검수 결과 확인.
- 기본값과 명시적 False 결과 전체 동일성, 기존 extract_rule 결과 및 로그와 일치.
- LF/CRLF/공백 빈 줄 문단 경계, 부분 제거 후 원문과 span 보존.
- 상투어가 많아도 수치·인과·조건이 있으면 보존, 상투어 없는 일반 claim 보존, 문장 비율에 따른 제거.
- 주입 검사 우선순위와 코드 전용 로그, gap 재검색의 refine 재사용.

전체 명령 `python -m pytest -q`를 시도했으나 Python 명령을 찾지 못해 시작하지 못했다. `python`, `py`, `pytest` 명령 및 저장소 `.venv-python` 안의 python.exe도 발견하지 못했다.

## PC 비교 실행 명령

아래는 실행하지 않은 대표용 PowerShell 명령이다. 기존 research_eval을 import하며 파일은 수정하지 않는다. compare 문항만 사용하고 결과는 `.runs/r15`에 쓴다. 규칙 기반 경로 시험이며 실제 모델 품질 평가가 아니다. aggregate의 지표별 결과에는 표본 수와 Wilson 95% 구간이 포함된다. 기존 기본 k=2와 전체 입력 정제 확인용 k=40을 각각 비교하며 설정 선택은 compare 결과만 사용한다.

```powershell
@'
import json, sys
from pathlib import Path
from dataclasses import replace
sys.path.insert(0, 'scripts')
import research_eval as ev
cases = [c for c in json.loads(ev.CASES.read_text(encoding='utf-8'))['cases'] if c['split'] == 'compare']
output = {}
for k in (2, 40):
    for enabled in (False, True):
        rows = []
        for case in cases:
            corpus = ev.padded(case, 30)
            cfg = replace(ev.CONFIGS['graph_full'], k=k, drop_generic=enabled)
            result = ev.ResearchRunner(ev.keyword_search(corpus), cfg).run(case['question'], tuple(case.get('checklist', ())))
            row = ev.score(case, result, ' '.join(corpus.values()))
            row['claims'] = len(result.claims)
            row['background_claims'] = sum(c.source_id.startswith('pad') for c in result.claims)
            rows.append(row)
        output[f'k={k},drop_generic={enabled}'] = {'summary': ev.aggregate(rows), 'cases': rows}
out = Path('.runs/r15')
out.mkdir(parents=True, exist_ok=True)
(out / 'compare.json').write_text(json.dumps(output, ensure_ascii=False, indent=2), encoding='utf-8')
'@ | python -
python -m pytest -q tests/test_research_noise.py tests/test_structure.py
python -m pytest -q
```

confirm은 이 비교로 설정 1개를 선택한 뒤 해당 설정에 한 번만 적용해야 한다. 이번 작업에서는 compare/confirm 모두 실행하지 않았다. research_eval CLI에는 drop_generic 옵션이 없으므로 CLI 연결은 후속 연결 필요다.

## 설계 대비 차이

설계 10절의 일반론 축소를 refine의 선택 기능으로 구현했다. 기존 sources는 원문 span 검증용 텍스트를 이미 저장하므로 이를 제거하거나 reducer를 변경하지 않고 추출 입력만 정제한다. 설계의 원문 비보관 목표 전체 구현은 이번 범위 밖이며 후속 연결 필요다. 기존 추출기 인터페이스를 유지하기 위해 공백으로 위치를 보존한다. 기본 모드는 내용 변경 없이 종전 경로를 유지한다.

비율 기준은 문장 중 상투어 포함 문장 수를 사용한다. 기존 버전 관리된 cue 목록은 변경하지 않았다. 모든 숫자를 보호하므로 research_eval의 BACKGROUND처럼 문단에 문서 순번이 있는 경우에도 보존한다. 이는 수치 손실을 피하는 보수적 선택이며 해당 잡음 패턴 감소는 미검증이다. 재현 코퍼스는 숫자 없는 잡음 문서를 사용한다. 검색 k를 밀어내는 잡음의 순위 문제는 refine만으로 복구하지 못한다.
