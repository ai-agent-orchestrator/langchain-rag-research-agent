# R55: R16 리서치 CLI 재작업

## 이전 실패 원인

**마지막 1개 실패의 직접 원인은 미확정이다.** `git diff HEAD...nc2/failed/507-rra-r16-research-cli-160917`로 세 파일을 확인했다. 실패 브랜치 보고서의 마지막 게이트 수치는 764 passed / 1 failed / 0 error / 1 skipped / 10 deselected지만 시험 이름과 traceback이 없다. 이는 이번 실행 결과가 아니다. 앞선 체크리스트 중복 제거 수정은 브랜치에 이미 포함되어 있다. 마지막 실패를 그 문제로 단정하지 않았다. 이번 환경에서도 의존성 때문에 재현 시험을 시작하지 못했으므로 실패 해결·전체 시험 통과는 미검증이다.

확인된 기능 누락은 문항 파일 입력이다. 이전 CLI에는 `--question`만 있고 문항 파일 선택이 없었다. 이를 추가했지만 이것이 이전 실패의 원인이라는 증거는 없다.

## 구현

- 지정된 CLI와 시험을 실패 브랜치에서 검토·복원하고 현재 그래프 API에 연결했다. 질문·체크리스트·문서 폴더·설정 이름·JSON/Markdown·`.runs/` 안의 파일 출력을 제공한다. 체크리스트는 trim·마스킹 후 첫 등장 순서대로 중복 제거한다.
- `--cases FILE --case ID`로 기존 연구 평가 문항 형식의 JSON에서 정확히 한 문항을 선택한다. 최상위 목록과 `{"cases": [...]}`를 지원한다. 문항의 `question`, `checklist`, `docs`를 검증하고 실제 `keyword_search`와 `ResearchRunner`에 연결한다. CLI 체크리스트를 추가 병합한다. 누락·중복 ID, 잘못된 타입·JSON, 마스킹으로 충돌한 문서 ID는 고정 오류 코드와 종료 코드 2로 거부한다. 문항 파일과 질문·문서 폴더·Chroma 입력은 혼용하지 않는다.
- JSON은 기존 출력 필드에 `end_type`과 `estimated: true`를 추가한다. 종료 유형은 `ResearchResult.end_type`을 그대로 사용하며 토큰은 shadow 추정값이다. Markdown에도 종료 유형을 표시한다. 실제 호출 수·시간·비용을 추정하여 만들어 넣지 않는다.
- `--planner llm`, `--extractor llm`, `--writer llm`은 `main`의 해당 모델 인자로 주입한 모델만 사용한다. 기존 구조화 출력 어댑터·마스킹·규칙 폴백·검수를 재사용한다. 주입 없이 옵션을 켜면 거부한다. 기본은 전부 rule이며 `CONFIGS['graph_full'] == ResearchConfig()`를 유지한다.
- `--chroma`는 기존 Library를 열어 실제 Chroma 어댑터로 검색한다. 새 인덱스를 만들지 않으며 finally에서 닫는다. 주입 임베더 또는 명시적 캐시 E5 revision을 사용한다. 키워드 경로는 규칙 경로 시험용이며 실제 벡터 검색 품질 결과로 해석하지 않는다. memvid를 import하거나 변경하지 않았다.

사용 예시(여기서 실행하지 않음):

```powershell
$env:PYTHONPATH = 'src'
python -m rag_research_agent.rag.research_cli --docs .runs/r55/documents --question "매출 분석" --checklist 매출 --config graph_full --json --out r55/report.json
python -m rag_research_agent.rag.research_cli --cases evals/research/cases.ko.json --case CASE_ID --config graph_basic --out r55/report.md
```

`CASE_ID`는 파일에 있는 단일 문항 ID로 바꾼다. 상대 출력 경로는 `.runs/` 기준이다. 이 CLI는 설정 선택·골든셋 점수 집계·confirm 평가를 수행하지 않는다.

## 시험

실제 그래프·masker·Library·ChromaIndex·검색 어댑터를 통과하는 시험을 정의했다. 기존 R16의 18개 매개변수화 시험을 보존하고, 단일 문항 선택·입력 오류·종료 유형·추정 표시·모델 주입 요구·실제 모델 어댑터의 스키마 실패와 규칙 폴백·유효 작성 출력·기본 설정 보존 시험 19개를 추가했다. 총 19개 함수 / 매개변수화 37개 시험이다. fake는 기존 FakeEmbedder와 모델 경계에만 사용하며 그래프·저장소·스키마를 대역으로 바꾸지 않았다. 이는 **경로 시험**이며 실제 모델 결과가 아니다. 신규 시험 개인정보 표식은 예약된 `[MASKED_EMAIL]`만 사용한다.

전체 시험 시도 명령(NightCoder의 memvid 표식 제외 규칙):

```powershell
& .venv/Scripts/python.exe -m pytest -q -p no:cacheprovider -m 'not memvid' --basetemp=.runs/r55/full-tmp --junitxml=.runs/r55/full-pytest.xml
```

**tests not run here: pytest is not installed in the available Python interpreter (No module named pytest).**

이 환경에서 시험 미실행: `.venv`의 Python 3.15에 pytest가 없다. 기존 로컬 캐시 실행기 `.runs/r4/cached_pytest.py`로 R16 재현도 시도했지만 캐시의 `pydantic_core` 네이티브 모듈이 사용 중인 Python과 호환되지 않아 플러그인 로딩에서 중단했다(`ImportError: cannot import name 'ArgsKwargs'`). 패키지 설치나 모듈 대역 삽입은 하지 않았다. 증거: `.runs/r55/full-test-attempt.txt`, `.runs/r55/reproduce.txt`.

이번 실행 시험 수는 **0개**다. passed/failed/error/skipped는 시험 시작 전 실패로 **집계 불가**이며 0 passed를 통과로 보고하지 않는다. 두 Python 파일 AST/compile 정적 검사는 통과했다(`.runs/r55/static-check.txt`). 정의한 37개 시험과 전체 시험의 실행 판정은 NightCoder 게이트에서 필요하다.

보호 기준 `.runs/r5/protected-before.json`의 Expected 값과 보호 파일 **18/18개 SHA-256이 동일**하다. 증거: `.runs/r55/protected-after.json`. 금지 파일·기존 다른 모듈 시험·KNOWN_DEBT는 변경하지 않았다. 변경 범위는 지정된 CLI·신규 시험·본 보고서 세 파일이다. 네트워크·모델 다운로드·실제 모델/LLM 실행·새 패키지 설치·push·원격/브랜치 설정 변경은 하지 않았다.

## 설계 대비 차이

`RESEARCH_GRAPH_DESIGN.ko.md`, `METRICS_BOARD.ko.md`, `DOMAIN_FILTERS.ko.md`, `LANGGRAPH_GUARDRAIL.ko.md`를 확인했다. CLI는 rag 조립 계층에서 기존 그래프·검색·모델 어댑터를 연결한다. 모듈 경계와 MATURITY를 유지하며 새 도메인 필터·그래프·저장소를 구현하지 않았다.

R16 호환 기본값으로 키워드 검색을 유지하며 Chroma는 명시적 옵션이다. 신규 저장소 개발은 하지 않았다. Chroma 버전 발행·롤백·DB 전체 해시 manifest는 **Chroma 경로에 없음**이며 임의 대체 구현하지 않았다.

자기 교정·근거성 검수·종료 유형은 기존 그래프에 위임했다. 관련성 채점기 옵션, 체크포인터/thread·interrupt 승인 CLI, 골든셋 평가·LLM-as-judge, 전체 보드 이벤트 스키마는 **후속 연결 필요**다. 이번 구체 작업인 R16 CLI 재구현 범위에서 검증되지 않은 세션 저장·승인·평가를 새로 구현하지 않았다. 모델 옵션은 주입식 Python 진입점에서만 활성화할 수 있으며 별도 모델 로더는 없다.
