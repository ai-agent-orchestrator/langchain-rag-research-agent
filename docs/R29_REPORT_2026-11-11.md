# R29: 보고서 내보내기

작성: 2026-11-12 KST. NightCoder 레인.

## 구현

`rag/research_export.py`에 명시적으로 호출하는 `export_markdown(result)`와 `export_html(result)`를 추가했다. 기존 설정이나 실행 경로는 변경하지 않는다. 두 함수는 이미 마스킹된 ResearchResult를 받아 문자열만 반환하며 파일 저장은 호출자가 담당한다. 저장 시 결과는 `.runs/` 안에 둔다.

Draft 문장별 claim_ids를 Claim 및 SourceRef에 연결한다. 각주는 처음 인용되는 순서로 번호를 붙이고 같은 문서·구간은 재사용한다. 문서 ID, 0부터 시작하는 반열린 문자 구간 `[start:end]`, 해당 원문 구간만 표시한다. 누락 claim/source 또는 span 불일치는 ValueError로 거절한다. 원문 전체나 지어낸 인용을 대신 출력하지 않는다.

검수 코드가 있으면 미통과 항목별로 표시한다. verify 실행 경로가 있고 미통과 코드·중단·검토 대기가 없을 때만 통과로 표시한다. 검수 전 종료나 baseline은 미검증이다. 중단 코드와 검토 대기를 별도 표시한다. 부록은 노드 경로, 전체 추정 토큰, 노드·종류별 추정 토큰을 포함하며 실제 사용량·과금이 아님을 명시한다.

HTML은 외부 리소스·스크립트 없이 한 파일로 저장 가능한 문서다. 문장·출처 ID·인용·검수 코드·경로·비용 항목의 입력 텍스트를 이스케이프한다. 각주 링크와 ID는 내부 정수 번호로만 만든다. Markdown도 HTML 및 Markdown 문법을 이스케이프해 입력을 텍스트로 취급한다. 렌더러는 개인정보 마스킹을 대신하지 않는다.

## 시험

신규 시험 파일은 실제 ResearchResult, Draft, Claim, SourceRef와 규칙 기반 ResearchRunner를 사용한다. 대체 결과 클래스나 모델·네트워크 호출은 없다. 각주 재사용·순서·HTML 링크 연결, 정확한 인용 구간, 입력 이스케이프, 통과·미통과·미검증·검토 대기, 부록 추정치, 잘못된 인용 거절, 실제 Runner 결과 연결과 입력 불변성을 검증하도록 13개 사례를 정의했다.

- `python -m pytest -q`: PATH에 Python 명령이 없어 시작 불가.
- `.\.venv\Scripts\python.exe -m pytest -q`: `No module named pytest`로 수집 전 시작 불가. 로그: `.runs/r29/full-suite.log`.
- **tests not run here: repository venv Python is available, but pytest is not installed.** 이 환경에서 시험 미실행: 가상환경에 pytest 없음. 패키지를 설치하지 않았다.
- 최종 시험 실행 수 0건. passed/failed/error/skipped는 모두 미집계이며 통과로 판정하지 않는다. 전체 시험 판정은 NightCoder 게이트에서 필요하다.
- 새 Python 파일 두 개의 AST 구문 검사 및 `git diff --check` 통과. 런타임 검증은 아니다.
- 보호 파일은 `.runs/n10/protected-after.json`의 Expected SHA-256과 작업 전후 모두 18/18 동일. 근거: `.runs/r29/protected-before.json`, `.runs/r29/protected-after.json`.
