# R13 체크포인트와 계획 검토

## 구현

`ResearchRunner(checkpointer=...)`와 `build_research_graph(..., checkpointer=...)`가 LangGraph `BaseCheckpointSaver`를 받아 compile에 전달한다. 기본값은 `None`이다. `ResearchConfig.review_plan=False`가 기본이며 기존 기본 노드·검색·검수 경로를 유지한다.

검토를 켜면 `plan → review_plan → retrieve` 순서로 실행한다. 별도 검토 노드의 `interrupt`가 필수 지표 목록을 반환하므로 재개 시 계획 노드는 재실행되지 않는다. 순차·병렬 검색 모두 검토 뒤에 시작한다. `ResearchResult.interrupts`에 LangGraph 중단 정보를 담는다. `path`는 해당 호출에서 완료된 노드만, 나머지 결과는 체크포인트의 누적 State를 반영한다.

```python
from langgraph.checkpoint.memory import MemorySaver
from rag_research_agent.rag.research_graph import ResearchConfig, ResearchRunner, keyword_search

runner = ResearchRunner(
    keyword_search({"doc-a1": "매출은 18% 증가했다. 거래량은 12% 감소했다."}),
    ResearchConfig(review_plan=True, stance_split=False),
    checkpointer=MemorySaver(),
)
paused = runner.run("매출 거래량 분석", ("매출",), thread_id="review-a1")
result = runner.resume("review-a1", required_metrics=["거래량"])
```

검토 입력은 `required_metrics` 문자열 목록/튜플이다. 공백을 제거하고 중복을 순서대로 제거하며, 빈 목록은 허용한다. 잘못된 입력은 재개 전에 거부하여 검토를 소비하지 않는다. 변경 지표의 origin은 `review`, 기존 perspectives는 유지한다. 질문·체크리스트와 동일하게 호출자가 마스킹한 지표를 전달해야 한다.

체크포인터 사용 시 비어 있지 않은 thread ID가 필수다. 이미 사용한 ID로 새 run을 시작하면 누적 리듀서 오염을 막기 위해 거부한다. resume은 중단된 검토가 있는 같은 ID에서만 가능하다. 같은 saver를 주입한 새 Runner에서도 이어갈 수 있다. 동시 쓰기와 thread ID 소유권은 호출자 책임이다.

SQLite는 선택 사항이다. 이미 `langgraph-checkpoint-sqlite`가 설치된 환경이라면 `with SqliteSaver.from_conn_string('.runs/r13/review.sqlite') as saver:` 안에서 saver를 주입하고 run/resume을 실행한다(`from langgraph.checkpoint.sqlite import SqliteSaver`). 패키지 설치·의존성 추가·별도 저장소 구현은 하지 않았다. 이번 작업은 저장소와 무관한 실행 상태 저장 기능이며 memvid를 import하지 않는다.

## 시험

새 `tests/test_research_checkpoint.py`에 매개변수 확장 기준 16건을 작성했다. 실제 `MemorySaver`, `ResearchRunner`, 기존 `keyword_search`를 사용한다. 호출 수 래퍼는 실제 함수에 위임하며 대체 그래프·저장소·모델을 만들지 않는다. 모두 오프라인 경로 시험이며 모델 품질 평가가 아니다.

- 순차·병렬 각각 중단 시 검색 0회, 재개 완료 후 검색 1회 및 계획 1회: 앞 노드 재실행과 중복 검색 방지.

- 체크포인터 없는 기본 결과와 검토 없는 체크포인터 결과의 동등성.
- 필수 saver/thread 검증, 잘못된 지표 수정 후 정상 재개, thread 분리, 중복 run·없는/완료된 검토 재개 거부.

## 설계 대비 차이

정본의 기본 그래프는 유지하고 R13에서 요청한 검토 노드만 옵션으로 추가했다. State의 plan 덮어쓰기 및 출처·주장·수치 누적 원칙을 따른다. 체크포인트 조회와 실행·재개는 기존 `serving_trace_guard` 안에서 수행한다. 도메인 필터와 반복·비용 한도는 변경하지 않았다. HTTP/UI 검토 연결은 지정 파일 범위 밖이므로 후속 연결 필요다.

## 미검증

MemorySaver 중단·재개의 실제 동작과 전체 회귀 시험, SQLite 직렬화·프로세스 재시작 복구, 동시 thread 쓰기, 실제 Chroma·실제 모델 결합은 미검증이다. MemorySaver는 메모리 내 상태이며 프로세스 종료 후 복구용이 아니다. 네트워크·모델 다운로드·실제 모델·LLM 호출·LangSmith 업로드는 실행하지 않았다.

실제 모델 검증이 필요하면 대표 PC에서 이미 보유한 로컬 모델과 masker를 제공하는 `.runs/local_planner_factory.py`를 준비하고 아래 명령을 실행한다. factory는 기존 주입 진입점이며 이번 작업에서 만들거나 실행하지 않았다. 외부 API·다운로드를 사용하는 factory를 사용하지 않는다.

```powershell
python -c "import runpy; from langgraph.checkpoint.memory import MemorySaver; from rag_research_agent.rag.research_graph import ResearchRunner, ResearchConfig, keyword_search; c=runpy.run_path('.runs/local_planner_factory.py'); r=ResearchRunner(keyword_search({'doc-a1':'매출은 18% 증가했다.'}), ResearchConfig(planner='llm', review_plan=True, stance_split=False), planner_model=c['model'], masker=c['masker'], checkpointer=MemorySaver()); print(r.run('매출 분석', ('매출',), thread_id='local-a1')); print(r.resume('local-a1', required_metrics=['매출']))"
```

변경은 지정 소스 1개·신규 시험 1개·본 보고서 1개다. push·원격/브랜치 설정 변경은 하지 않았다.
