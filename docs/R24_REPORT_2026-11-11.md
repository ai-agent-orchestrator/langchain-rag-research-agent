# R24 — 리서치 합성 문항 확장

## 구현

- `evals/research/cases_v2.ko.json`: 기존 `research-eval/1`과 같은
  version/note/cases 및 id/split/question/checklist/docs/gold 구조의 별도 데이터셋이다.
  버전은 `research-eval/2`로 구분한다. 기존 `cases.ko.json`은 수정하지 않는다.
- 경제·기술·사회·환경·교육 각 6문항, 총 30문항이다. 주제별 compare 4개와 confirm 2개로
  전체 compare 20개 / confirm 10개를 분리했다. 두 split의 질문과 문항 ID는 겹치지 않는다.
- 각 문항은 수치 지표 2개, 골든 인과 1~2개, 조건·예외 1개, 반대 근거 0~1개,
  배경 잡음 문서 3~6개를 갖는다. 소수, 퍼센트포인트, 감소·증가와 비용 증가 등도 포함한다.
  모든 질문과 문서에 합성 표시를 하고 실제 통계가 아님을 최상위 note에 명시했다.
- `tests/test_research_cases_v2.py`: JSON 중복 키·필수 키·자료형, ID 유일성,
  split·주제 분포, 지표명과 정확한 수치 토큰의 동일 문서 공존, 인과 구절 그룹의 동일 문서 공존,
  조건·반대 구절의 근거 존재, 잡음 수·정답 분리, 합성 표시·개인정보 형태 부재를 확인한다.
  연락처·금융정보 시험 값은 필요하지 않아 넣지 않았다.
- 새 구현은 데이터와 실제 JSON을 읽는 시험뿐이며 대체 모델·검색기·필터를 만들지 않았다.
  기존 시험·기대값·skip·KNOWN_DEBT와 제품 기본 설정을 변경하지 않았다.

## 시험

사용 가능한 Python은 PATH 밖의 다음 실행 파일이다. 패키지는 설치하지 않았다.

```powershell
& 'C:/Users/Codelab/AppData/Roaming/uv/python/cpython-3.15.2-windows-x86_64-none/python.exe' tests/test_research_cases_v2.py -v
```

최종 새 문항 계약 시험: **passed 9 / failed 0 / error 0 / skipped 0**.
30문항 전체를 순회하며 검사한다. 로그: `.runs/r24/contract-unittest.log`.
초기 실행에서 셸의 표준입력 인코딩 때문에 질문의 합성 표시가 깨진 오류를 검출했고,
UTF-8로 질문을 복원한 뒤 최종 실행을 통과했다. 기존 시험은 수정하지 않았다.

NightCoder 게이트와 동일하게 memvid 표식 시험을 제외한 전체 시험 시도 명령:

```powershell
& 'C:/Users/Codelab/AppData/Roaming/uv/python/cpython-3.15.2-windows-x86_64-none/python.exe' -m pytest -q -m 'not memvid' -p no:cacheprovider --basetemp=.runs/r24/full-tmp --junitxml=.runs/r24/full-pytest.xml
```

**tests not run here: available Python has no pytest module (No module named pytest).**

이 환경에서 시험 미실행: Python은 있으나 pytest가 없어 전체 시험 명령을 시작하지 못했다.
전체 pytest 실행 0건, passed/failed/error/skipped 집계 불가이며 위 계약 시험 결과와 구분한다.
전체 시험 판정은 NightCoder 게이트에 남긴다. 로그: `.runs/r24/full-pytest.log`.
memvid 시험을 실행·변경·재시험하거나 skip을 추가하지 않았다.

## 설계 대비 차이

정본 `RESEARCH_GRAPH_DESIGN.ko.md`, `DOMAIN_FILTERS.ko.md`, `LANGGRAPH_GUARDRAIL.ko.md`를
확인했다. 이번 범위는 평가 입력 확장이므로 그래프·도메인 계약·가드레일 구조 변경이 없다.
src 모듈과 import 경계, MATURITY, 기본 저장소 Chroma 및 memvid 보존 방침은 그대로다.

기존 실행기·그리드·보드는 여전히 기존 데이터셋을 기본으로 쓴다. 새 파일 경로 선택 옵션과
보드의 v2 메타데이터 연결은 허용된 세 파일 밖이므로 **후속 연결 필요**다.
데이터셋의 confirm은 형식 검증에만 사용했고, 설정 선택이나 품질 평가에 사용하지 않았다.
설정 선택은 compare로만 하고 선택한 단일 설정에 confirm을 한 번만 적용하는 원칙을 유지한다.

## 미검증 및 보존 확인

실제 그래프 실행·검색 품질·실제 모델 품질·Chroma 통합은 **미검증**이다.
모델·임베더가 필요 없는 형식 시험이므로 실제 모델 실행 명령은 추가하지 않았다.
실제 모델 연결 실행 명령은 모델 주입과 v2 선택 옵션 연결 후 별도 정의가 필요하다.
fake 임베딩 평가, LLM 호출, 모델 다운로드, 네트워크, 유료 API, 원격 업로드를 수행하지 않았다.

보호 파일은 `.runs/n10/protected-after.json`의 Expected를 기준으로 작업 전후
**18/18 SHA-256 동일**이다. 기록: `.runs/r24/protected-before.json`,
`.runs/r24/protected-after.json`.
기존 `evals/research/cases.ko.json` SHA-256도 작업 전후 동일하다:
`B8E25E6DE22A7CFCFEF7AC879D6A6D7390E7EFB04C98AEA8C41DA73162F25CD5`.
변경 범위는 지정된 세 파일뿐이며 README.md·data/·profiles/·동결 파일을 수정하지 않았다.
push·원격 설정·브랜치 설정 변경은 수행하지 않았다.

`git commit -m "test: expand synthetic research corpus to thirty cases"`를 시도했으나
